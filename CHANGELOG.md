# Changelog

All notable changes to the kit are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The kit's version is the one at the bottom of `AGENTS.md`. The CLI on npm carries the same version.

## [Unreleased]

### Added

- **After the MVP: the hourglass.** Past "MVP complete" the pyramid turns upside down and widens. Each layer adds new features (each in thin) plus a pass on what's already there, the core every layer. A pass is an improvement. One layer is planned at a time, with the same gate between layers.
- **One pass at a time, with a gate between passes (#60).** `pyramid` outlines every pass (milestone, slices, one line on "better") and details only the current one. The MVP is 3 passes, Works, Real and Ready; more needs a `decisions.md` reason and the person's yes, capped at 4. Only the core, the supports it can't work without ("does the core work without it?") and the floor go in; an insisted non-core must is asked about once, then capped at pass 1 or 2; other features get their own 1- to 2-pass pyramid. `issues` writes the current pass only and refuses later ones until their gate. A new `pyramid/references/pass-gate.md`: the person tries it, a fresh read-only audit against the plan and the approved wireframes, cleanup capped at about 20%, and a re-plan on the strongest tier (asked first), then the consistency check. `coordinate` stops at the end of a pass with a ⏳ decision, under `/afk` too, and `/back` offers the gate first. The end of pass 3 is "MVP complete" on the test site, not launch: `AGENTS.md`, the stack pack and `/back` say launch is the person's call. The pyramid and MVP templates gain the outline, the per-pass status and the gate record.
- **A research standard for every app, and for the kit's own `research/` (#32).** `docs/research/README.md` is an index: one row per dossier with the question, the decision it fed, the date, the status (`draft`, `current`, `stale`, `superseded by …`), the re-check date and the author's model and effort. `/idea` and `/join` create it from `templates/research-index.md`; dossiers start from `templates/research.md`. Each dossier has a `<topic>/` folder with `provenance.json` (`research-provenance/1`: the exact model ID, effort, harness, dates and brief for every role, `unknown` when not recorded, never guessed), a desk-research store (hypotheses, coverage matrix, append-only `sources.csv` and `claims.csv` with a label on every claim) and a fact-check disposition file; benchmarks add manifest-first, append-only run folders. A fresh-context fact-check comes before `current`. The `research` skill gets reference files for desk research, provenance (with the `Research-Model:` and `Research-Effort:` trailers) and measurements, plus a JSON schema. `scripts/check-research.mjs` (no dependencies) checks all of it, and the append-only rule with `--base`; it runs in the kit's CI on `research/`, ships in the research skill, runs in the app CI templates, and `/back` and `doctor` list stale dossiers. The kit's six dossiers are backfilled: only the competitor scan recorded its model (`claude-opus-5-5`); every other model, and every effort, is `unknown`.

- **Behaviour tests for the skills (#54).** `evals/` runs seven scenarios (the grill, git safety, secrets, test-first inside the fence, a weakened test in review, the wireframe gate, asking before the strongest tier) in Claude Code twice, with the kit installed through the CLI and without. Checks read the transcript and the files; none asks a model. A scenario fails when a check fails with the kit or the kit made no difference. Results append to `evals/results/<date>-<model>-<kit>.json` with tokens, cost and time per run. Limits: turns, a timeout and a dollar cap per run, and at most 20 runs. `.github/workflows/evals.yml` runs them on Haiku 5.5 for pull requests that change skills, `AGENTS.md`, `plugin/` or `scripts/`, and by hand with a model pick; the key lives in the `evals` environment, and forks never run. `npm run evals` runs locally with your own login. The harness's tests use a fake `claude` and run in normal CI.
- **GitHub Free with a private repo works without environments (#14).** GitHub gives that combination no environments, environment secrets, deployment branch rules or required reviewers. `setup-github` now sets the repository variable `SECRETS_MODE=repository` there, and the same TanStack Start workflows then name no environment and read repository secrets and variables called `TEST_<name>` (test and previews) and `PRODUCTION_<name>`. `pnpm connect` and `push-secrets.mjs` read that variable and write those names. `deploy-production` needs `deploy production` typed in a confirm box on every plan. The grill, `setup-github`, the stack skill and the pack README say what is lost: no required reviewer on production, no main-only rule, and every workflow on every branch can read the production secrets.
- **Wireframes get their own step and an approval gate (#52).** A new `wireframes` skill draws every screen in the main flow plus the core screen's empty, error and loading states: sketches in `docs/design.md` and one self-contained clickable prototype, `docs/wireframes/index.html`, in light and dark from the look-and-feel tokens. It asks *"What would you change?"*, revises until the person says yes, and records `Wireframes approved: <date>, <hash>` in `decisions.md`. `/idea` starts it in the background on the strongest tier once the product grill is confirmed, names the app meanwhile, and runs no tech grill or pyramid before the approval (steps 4–6; later steps move up by two). `pyramid` builds the schema and API from the approved screens and doesn't redraw them; a changed screen goes back through approval, as do new screens in `/join` and big features. The consistency check flags an MVP screen without an approved wireframe. The grill log's coverage map gains look and feel and both wireframe lines, and `/back` resumes a kickoff paused after naming.
- **`/afk` reaches cloud sessions through the Google Sheet board (#50).** A "Presence" tab in the `[board] sheet` holds the status, since, until, what may merge, what pings and the machine label. Nothing else. `afk` and `back` write it, and `coordinate` and `back` read it, through the Sheets connector. `worklog.mjs presence afk` takes `--until`, `--merge` and `--pings`; `presence sheet` prints the tab's row; `presence --shared` picks the local file or the sheet, whichever is newer, and says which. An away past its hard stop, or over 24 hours old, counts as unknown, and `/back` says so. Presence never goes in a repo. No sheet, no shared copy: the skills say so. `[presence] machine` in the profile sets the label.
- **Acceptance checks as WHEN/THEN with IDs (#45),** from GitHub Spec Kit (with OpenSpec and Kiro). Each check is `AC-<issue>-<n>: WHEN … THEN …`, and the test that proves it starts its title with the ID. `build` names tests that way, `pr-review` makes a missing ID a must fix, and `qa` reports one line per ID. `[NEEDS CLARIFICATION: …]` marks an open question and keeps an issue off `status:ready`.
- **A read-only consistency check after the issues are written (#46),** from Spec Kit's `analyze`. `issues/references/consistency.md`: a fresh agent checks a pass's issues against the MVP, features, pyramid, design and decisions (missing features, broken dependencies, screens with no slice, floor items, clashing checks, open markers), reports, and fixes nothing. `idea` step 8 and `pyramid` re-plans run it.
- **A complexity score on each issue (#47),** from Task Master's `analyze-complexity`. `Complexity: 1–10 · <reason>` against a four-row scale in `issues`; above 7 is split before it's ready. `routing` sets build effort from it (1–4 low, 5–7 medium, never the strongest tier without asking), and `coordinate` skips an unsplit one and allows three review rounds at 6–7.
- **A load-when index for guides and references (#48),** from Agent OS's standards index and Kiro's steering files. `guide/README.md` lists each guide with a "load when" rule, and `build`, `issues` and `stack-tanstack-start` have a **References** table. `AGENTS.md` and `writing-for-agents` point to them.
- **The grill asks about look and feel (#41).** A new product topic, with open questions first because it is taste: the feel in three words, apps they like, existing brand files, light or dark, density, the voice of the copy, and what to avoid. The answers go to "Look and feel" in `docs/design.md`, and the CTO step turns them into theme tokens. A `[design]` section in the profile pre-fills it.
- **`onrails` is on npm** (0.4.0, published 2026-11-23). `npx onrails init` is the README's install path next to the plugin.
- **Release workflow for the CLI (#37).** A `v*` tag runs `.github/workflows/release.yml`: it checks the tag matches the CLI and plugin version, runs the same checks as CI, checks the package holds only the intended files, waits for approval in the `release` environment, then publishes `onrails` to npm with trusted publishing (no token) and provenance. `npm run release:bump <version>` moves the CLI, both plugin manifests, the `AGENTS.md` footer and the changelog together, and CI fails if they drift. `RELEASING.md` has the owner's one-time setup. Nothing is published yet.
- **`pnpm connect`: set your own keys from your terminal (#36).** Based on Matt Pocock's wizard (MIT). The TanStack Start pack's dependency-free script lists the providers the app needs (from `.env.example` and the workflows) and what's already set, by name only, then walks each missing one: short steps from the provider file, the page opened after a yes, each value typed with hidden input (paste works) and checked for shape, then saved to `.env.local` (mode 600), `wrangler secret put` or `gh secret|variable set`, always on stdin, a yes per destination, and a separate yes for production. `pnpm connect clerk` does one provider, `--force` sets values again, `--dry-run` changes nothing. Each provider file gets a `json connect` block (names, scope, destinations, page, shape); `secrets`, `idea` and `join` now send the self-serve path there. The monorepo pack runs the web app's script. After a security review it also drops typing from before each question, hides anything but y/n at a y/N question, reads a PEM key to its END line, refuses live keys outside production and test keys in it, writes only inside the repo to git-ignored files, pins `gh` to `origin` with `-R`, strips escape sequences from provider text, warns when it couldn't check a destination, and on Windows uses `cmd.exe` only for `.cmd` shims, fully escaped. A second review: every value is read hidden, a public one is shown afterwards and refused when it looks like a secret key, Cloudflare's Turnstile test keys are refused in production, and a failing tool's output is never printed.
- **Competitor scan in the background (#34).** Once the grill has covered "who and why" and "the main flow", a scan of 3 to 8 competitors runs in the background on the everyday model. The MVP topic opens with what exists, what users complain about and the gaps, and the naming step drops names close to a competitor's. `/join` offers it once.
- **Four ideas from Matt Pocock's skills (#27),** rewritten in the kit's voice. A new `diagnose` skill: a check that goes red on the bug before any theory, then shrink, guess, probe, fix with a regression test and clean up; a bug in production is a blocker. `build` step 5 spells out red, green, refactor, one check at a time, and `guide/testing.md` matches. `/back` after a long run and `/afk` at its hard stop run a short retro: at most 5 findings, each an app issue or a drafted kit issue the person files. A new `writing-for-agents` skill for editing skills and `AGENTS.md`, linked from CONTRIBUTING. A root `NOTICE` carries his MIT licence, and the CLI and plugin bundles ship it.
- **Credits** in the README: Matt Pocock for the "grill me" interview and test-driven development with AI, plus the books, people and projects the kit borrows from.
- **TanStack recipes, loaded only when needed (#9).** `stack-tanstack-start/references/tanstack/` has one recipe per library: Start, Router, Query, Form, Table v9, Charts, Markdown, Highlight, Virtual and Hotkeys. Each quotes TanStack's official agent prompt with its source and date, records the version checked on npm (2026-11-23), checks every API the prompt names against the library's source, and adds the kit's rules and a "Done when" list. The `stack` skill and the `docs/stack.md` template make them the default per area for any web app, installed only by the issue that needs one; an issue's new `Recipes:` line names the recipe and `build` loads it. `dependencies` says how to pin exactly and marks Hotkeys (0.x) as young.
- **The TanStack Start pack keeps list state in the URL and shows every data state (#7).** The notes list keeps its search, order and page count in validated search params (small hand-written parsers, so no schema library ships with every page). A note has its own page, `/notes/$noteId`, with a params schema, a designed not-found state, and a "More notes" part streamed behind `<Suspense>`. Rename and delete are optimistic, roll back when refused, and say so in a designed toast with a reference id. Slow navigations show the page skeleton (`defaultPendingComponent`, 300 ms delay, 500 ms minimum). The note forms use TanStack Form and load lazily behind a form-shaped skeleton, so the pages stay within their budgets; the generator's form uses TanStack Form too.

### Fixed

- **The monorepo-expo pack says `eas env:set`, not the deprecated `eas env:create`,** in its README and `.env.example`, matching eas-cli 27.11.0, where `env:set` creates or updates a variable. The Expo provider file's trap note now says why (#15).
- **Keys from `clerk env pull` work with no rename (#13).** The TanStack Start pack reads the publishable key as `VITE_CLERK_PUBLISHABLE_KEY`, the name Clerk's TanStack Start quickstart uses and its CLI writes; the env schema, `.env.example`, `wrangler.jsonc`, the Clerk connect block and walkthrough, the stack skills and the monorepo pack say so, and the rename steps are gone. The old `CLERK_PUBLISHABLE_KEY` still works, with one `env_name_deprecated` warning in the Worker log; the new name wins when both are set.
- **Clerk tokens are checked against the app's own origins** (`authorizedParties`) in the TanStack Start pack, for the session cookie and `/api/v1` bearer tokens. The list comes from `SITE_URL`, localhost and the test Worker's previews, so there is no new setup step; `CLERK_AUTHORIZED_PARTIES` adds more. A token for another site, or with no `azp`, gets the same 401 as no token, and production with Clerk keys but no origin refuses to start. Native apps, whose tokens have no `azp`, opt in with `CLERK_ALLOW_NATIVE_TOKENS` (bearer on `/api/v1` only); the monorepo-expo pack turns it on. The refusal reason no longer reaches the page or the response headers. The `Authorization` header is parsed exactly as Clerk does (`bearer x` no longer counts), and on `/api/v1` the cookie never reaches Clerk (#12).
- **A look-alike path no longer slips past the path guards** in the TanStack Start pack. The router matched case-insensitively and decoded escaped letters, so `/API/v1/notes` or `/%61pi/v1/notes` reached the API without the body cap, the rate limit or the cookie removal, and `/NOTES` skipped the Worker's Access check. The router is now case-sensitive, and the request guards answer with a plain 404, server functions included, any path Start would resolve to another one: an empty segment (`/api//v1`), an escaped control character or trailing space (`/notes%20`), or anything Start's own `getNormalizedURL` decodes (`/%61pi`, `/%5FserverFn`). Every guard then compares the path Start routes (`canonicalPath`, #18).
- **Three notes from the path-guard security review (#65)** in the TanStack Start pack. A lowercase escape of a non-ASCII character (`/notes/caf%c3%a9`, sent by some API clients) routes like the uppercase one instead of a 404, and every guard compares the path Start routes; escaped unreserved and control characters and a trailing `%20` are still refused. `//x` (Start's 308) and an empty server function ID (`/_serverFn/`, Start's bare 500) are answered before Start's handler by `beforeStart` in a new Worker entry, `src/server.ts` (`main` in `wrangler.jsonc`), with the guards' plain 404 and the security headers; the `sentry` and `jobs` add-ons' entries keep that call. An unknown server function ID gets the `internal` envelope with the security headers, not Start's `Server function info not found` 500.
- **A native token also needs the app's own claim** in the TanStack Start pack. With `CLERK_ALLOW_NATIVE_TOKENS=true`, a bearer token with no `azp` got through from any app on the same Clerk instance. It now needs an `app` claim equal to the new `CLERK_NATIVE_APP_CLAIM`, which the person adds to the instance's session token claims (a "Setup step for you" in the `secrets` skill's Clerk file); no claim, a wrong or non-string one, or the flag without the variable is the uniform 401. Clerk's custom claims are per instance, so this can't tell two apps on one instance apart: one Clerk application per product stays the rule. The monorepo-expo pack sets the variable (#19).
- **Tests for the Clerk guards that nothing failed without** in the TanStack Start pack. An e2e check that a valid cookie plus a bare or inexact bearer token is a 401 and that Clerk never saw the cookie (`x-clerk-auth-status`), so unwiring `requestForClerk` fails it; a unit test that the `@clerk/backend` dev dependency is the version `@clerk/tanstack-react-start` resolves, so the header parity test can't go stale. On `/api/v1`, Clerk's own query parameters no longer reach Clerk: a junk `__clerk_handshake` made a development instance throw (a 500), and `__clerk_redirect_url` (an open redirect), `__clerk_db_jwt` and `__clerk_synced` started a redirect. `requestForClerk` drops every `__clerk*` parameter there, and any redirect Clerk still answers with on the API is the uniform 401 (#20).
- **A crafted link can no longer send a tester's Clerk dev session to another site (#66)** in the TanStack Start pack. On a development instance, `@clerk/backend` answered `/notes?__clerk_redirect_url=https://evil.example` with a 307 to that site carrying the dev browser token (`__clerk_db_jwt`). The request guards now answer a `__clerk_redirect_url` or `__clerk_satellite_url` that isn't on one of the authorized parties with a 400 on every path (the API already dropped them, so it stays the 401), Clerk no longer sees the client's `X-Forwarded-*` or `Forwarded` headers, which put a spoofed host in its handshake URLs, and any redirect Clerk itself throws outside the parties and its Frontend API, or to the Frontend API with a `redirect_url` off the parties, gets the same 400. The development sign-in, handshake and satellite sync flow is unchanged and tested; production instances never take that path.
- `.clerk/` (Clerk claim files and temporary keys) is git-ignored in both packs, and CI fails if anything under it is committed.
- **The first pull request can merge now.** `setup-cloudflare` deploys the test Worker once, as the Coming soon page, so previews have a Worker to upload to. `--no-first-deploy` skips it. If the test Worker is missing, the `preview` job fails and names the fix (#3).

### Being built

- A needs-you convention: one clear way for agents to flag what's waiting on you.
- A status board: where every issue and pull request stands, in one place.
- A "Coming soon" page that keeps an app private until you choose to make it public.
- Permissions by relationship (ReBAC): a built-in engine behind a swappable port, and `authorize()` returns a proof the repository needs. The notes example uses it, so agents copy the real pattern.
- Go-style results: services return a value or a typed error instead of throwing.
- An app map: every file belongs to a named area, `pnpm map:check` fails on a gap, and the loop never runs two issues on the same one-at-a-time area.
- One-command dev: `pnpm dev` checks what's missing and names the fix, then migrates, seeds and waits for the health check.
- Tests for the kit itself: scripted sessions replayed each release to prove the agents still follow the rules.
- An incident skill: find the cause, roll back, open the fix issue, write what happened.

- **Renaming the kit to OnRails.** The npm package becomes `onrails`, and the plugin's short name is `or`, so commands read `/or:idea`, `/or:join`, `/or:back` and `/or:afk`. The repo, CLI, plugin and README move together in one pull request.

## [0.4.0] - 2026-11-23

### Added

- **Monorepo + Expo pack.** One repo for a web app and an iOS and Android app, with one API contract both follow.
- **Stub packs** for Electron desktop apps, Python with FastAPI, and Unity. Each is researched and fact-checked, with a `PACK.md` the agent builds from.
- **Add-ons for the TanStack Start pack:** analytics, Sentry, background jobs, email through Resend, Stripe, uploads to R2, and a move to Supabase Postgres. With no keys set, the app still builds and the feature stays off.
- **Deploys.** A test and a production environment, each with its own database. Main deploys to test, every pull request gets a preview, and production deploys only when you start it. A failed deploy rolls back.
- **A versioned `/api/v1` HTTP API** in the TanStack Start pack, for mobile and desktop apps. It takes Clerk bearer tokens.
- **`setup-cloudflare`**, a script that creates the Cloudflare databases, buckets and queues and pushes the secrets. It shows a dry run first.
- **Presence across threads.** `/afk` in one thread tells the other threads on the machine that you're away. The first `/back` after it tells them you're back.
- **An opt-in work log.** Your first prompt starts the clock and `/afk` stops it. It lives in your home folder or a Google Drive folder, never in the repo.
- **CLI:** `doctor --fix` offers a fix for each problem and runs it only after a yes. `profile init`, `show` and `copy` manage your personal defaults. `init` installs the Claude Code hooks.
- Public project files: this changelog, a security policy, a contributing guide, a code of conduct, and issue and pull request templates for the kit itself.

### Changed

- The TanStack Start pack is hardened: security headers and a strict CSP on every response, rate and body limits, accessibility checks on every route, page-weight budgets in CI, and SEO files from the start.
- Making an app public is on the always-stop list, next to deploying to production.
- The README is rewritten, with a path chart and a flow chart.
- The coordinator names every skill from the issue in the builder's brief.

### Fixed

- `setup-github.mjs` now asks for your GitHub plan (`--plan free|team|enterprise`, or `github_plan` in your profile) and labels each step with the plan it needs. On a private repo, a required reviewer on `production` needs GitHub Enterprise, not Team. The script no longer claims Team turns it on.

## [0.3.0] - 2026-11-22

### Added

- **The check contract.** Every project has the same six commands, whatever the stack: `check`, `lint`, `typecheck`, `test`, `test:e2e` and `build`. Skills, CI and the loop call only those.
- **Guardrails.** CI runs the checks, a secret scan, and a guard that blocks changes to the agents' own rules until you add the `human-approved` label. Force pushes and pushes to main are blocked in the tool.
- **The TanStack Start stack pack.** A working web app with configs, the folder skeleton, an example module through every layer, CI and the checks. It runs with no accounts and no keys.
- **The `ai-dev-workflow` CLI:** `init`, `update`, `doctor` and `add`. It never overwrites a file of yours.
- **Codex support:** command rules and project settings, next to Claude Code's.
- **Know-how skills:** `web-performance`, `web-security`, `seo`, `a11y` and `dependencies`.
- **The `secrets` skill.** It lists every key the app needs and where to get it, and pushes values without printing them.
- **A one-time GitHub setup script**, sized to your plan.
- **A personal profile** for what never changes for you, and app presets for the product grill.
- Hooks for Claude Code: a session-start hook that gives every session the branch, the last commit and `docs/state.md`, and a desktop notification when an agent needs you.

### Changed

- Feature folders: a feature's UI, server code and schemas live together, and lint stops one feature importing another.
- Cloudflare first for hosting and data, where it's free.
- `qa` uses Playwright first, then your own browser.
- Agents tell you right away when they're rate-limited or blocked, and keep doing other work.

## [0.2.0] - 2026-11-22

### Added

- **Four commands:** `/idea`, `/join`, `/back` and `/afk`. The other skills are called for you.
- **Checks before merge.** Acceptance checks are tagged `auto` (CI runs them) or `agent` (a fresh agent checks the preview).
- **Lanes:** tiny, normal and risky. Only risky changes get a security review.
- **The always-stop list:** real data, production, secrets and money always wait for you.
- Slice 0 sets up CI, a boundary check and a test deploy.

### Changed

- Skills are renamed to short names that don't clash with built-in commands, and each one names the next.
- Reviewers read the diff from main, never the author's description. Two rejections send an issue to you.
- The product grill goes by topic, and the MVP's core is never a default.
- The strongest model plans. The everyday model writes the issues.

## [0.1.0] - 2026-11-22

### Added

- The first kit: `AGENTS.md`, skills for the product grill, the tech grill, research, the tracer-bullet pyramid, issues, model routing, the build loop, reviews and browser tests, plus templates and a guide.
- Skills live in `.agents/skills` for Codex and are copied to `.claude/skills` for Claude Code. CI checks the copies match.
