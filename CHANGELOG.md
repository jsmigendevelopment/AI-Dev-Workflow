# Changelog

All notable changes to the kit are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The kit's version is the one at the bottom of `AGENTS.md`. The CLI on npm carries the same version.

## [Unreleased]

### Added

- **Preflight: every sandbox blocker in the first minute (#100).** New `npx onrails preflight`, also in the kit as `node .agents/skills/ask/scripts/preflight.mjs`, so it runs when the registry is the blocked thing. It probes the agent's own session in about 10 seconds: repo write, `.git` write (a temp branch), the package registry the project's `.npmrc` names, GitHub (`gh api rate_limit` and `git ls-remote`), loopback, headless Chromium when the project's tests use Playwright, Node and the package manager against `engines` and `packageManager`, and the model and effort the session can see. It prints one table, then a four-rung ladder for each failure, written for the tool in use (Claude Code, a Claude Code cloud session, Codex): work around it in the sandbox (a project-local cache or `--prefer-offline`, another port, `--webpack`, the server and tests in one process, Playwright's bundled browser), one command outside the sandbox through the tool's own permission request, the environment tools, and only then the person. It drafts ONE "Setup step for you" with a numbered fix for every row still blocked and a `Tried:` line. `/idea`, `/join`, `/back` and `build` run it first, and `AGENTS.md` gains rule 14, "Preflight before you build", so it holds even when no skill fires (on Haiku 5.5 the eval failed 3 of 3 runs without that line and passed 3 of 3 with it [measured, 2026-11-25]). `ask` gains `references/preflight.md`: fix in one batch, never one message per problem, and never scaffold while installs are blocked. `--record` writes an `Environment:` line to `docs/state.md`, and `--if-changed` skips every probe when that line says ok and the sandbox hasn't changed. A missing GitHub is "limited", not blocked: the loop has local mode. Preflight only runs known package managers (npm, pnpm, yarn, bun) and checks version strings. A prerelease such as `yarn@4.0.0-rc.42` keeps its name and skips only the version compare; anything else in `packageManager` is "limited", nothing runs, and the lockfile names the manager. It uses no shell: on Windows each command is found on PATH, and only a `.cmd` or `.bat` shim goes through `cmd.exe`, with plain words. It prints a value from the repo or the environment only when it matches a safe pattern. 24 tests.
- **The strongest-tier question is asked once per session (#100).** A yes covers every CTO job in the session and is written to a new `Strongest tier:` line in `docs/state.md`. A session that can't switch models says so once, carries on with the model it has and records it. `/idea` step 9 no longer tells the person to start a new session. `/idea` and `npx onrails profile init` ask once, at setup: "May the planner use your strongest model without asking each time?", saved as `ask_before_strongest`. `AGENTS.md` rule 13 says "once per session".
- **Two evals for #100.** `preflight-blocked`: a dead registry and a Node the sandbox doesn't have give one batched message with what was tried, one ping, and no scaffolded file. `asked-once`, a guard: the tier isn't asked twice, the person isn't told to restart, and what the repo already answers isn't asked. The runner's default cap goes from 36 to 40 runs, for twenty scenarios. That is the hard cap, so the next scenario has to raise it.
- **`docs/decisions.md` for the kit itself.** The kit's own decisions get a row each, with who made them.

### Changed

- **Releases are cut only when the owner asks.** `RELEASING.md` says so: no version bump, tag or publish after merges on any automation level.

## [0.6.0] - 2026-11-24

### Added

### Changed

- **Signature follow-ups (#93).** `signature --write` now writes the end marker as `<!-- onrails:signature end sha256=<hex> -->`, the sha256 of the block. A later run replaces the block only when that hash matches, or, for an older block with no hash, when the block equals a render of the current profile (any theme, style or mode). Anything else is refused, so a quoted marker or a hand edit is never deleted. With no markers, it trims only spaces, tabs and line breaks from the end. Text is normalized to NFC, and any combining mark left over is refused, apart from the parts of an emoji. Invisible fillers (U+034F, U+115F, U+1160, U+180B to U+180F, U+2800, U+3164, U+FFA0) are refused. Unassigned code points are refused. Skin-tone, joined, keycap and flag emoji are allowed, and a lone piece is refused. `--markdown` breaks the line after the name with a backslash, not two trailing spaces, so an editor that trims them doesn't break the hash. The TOML reader refuses a key set twice in a link's `{ }` table.
- **What npm's renderer was checked against (#93).** markdown-it 14.1.0 with `linkify` on links bare domains in text (`evil.com`, and `evil️.com`, `🔥.ws` and `1️⃣.com` too), but not text inside a link. So signature text refuses a full stop with a character on both sides (`Node.js` and `2.0` too), and a link label may hold one. npm's own renderer wasn't fetched.

## [0.5.0] - 2026-11-24

### Added

- **A line on what to try, per merge.** Every step has a try line: what the person does on the test site and what they see. - **Flow numbers.** `coordinate/scripts/flow.mjs` (no dependencies, no API calls) reads `gh pr list --state merged --json ...` and prints merges a day, hours from pull request to merge (median and 85th percentile), hours from issue to merge, the median and the longest gap between merges, the median size and the slowest pull requests. - **The `ai-dev-workflow` CLI:** `init`, `update`, `doctor` and `add`. It never overwrites a file of yours.
- **Codex support:** command rules and project settings, next to Claude Code's.
- **Know-how skills:** `web-performance`, `web-security`, `seo`, `a11y` and `dependencies`.
- **The `secrets` skill.** It lists every key the app needs and where to get it, and pushes values without printing them.
- **A one-time GitHub setup script**, sized to your plan.
- **A personal profile** for what never changes for you, and app presets for the product grill.
- Hooks for Claude Code: a session-start hook that gives every session the branch, the last commit and `docs/state.md`, and a desktop notification when an agent needs you.

### Changed

- Feature folders: a feature's UI, server code and schemas live together, and lint stops one feature importing another.
- Cloudflare first for hosting and data, where it's free.
- `qa` uses Playwright first, then your own browser.
- Agents tell you right away when they're rate-limited or blocked, and keep doing other work.
