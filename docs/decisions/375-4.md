# Decision 375-4

- **Date:** 2026-11-27
- **Decision:** A split parent's Size line becomes `Size: split into #<child>, #<child>` (it may keep its old estimate before a `·`). The check passes it only when at least one child it names is another issue in its input, never itself, and only when it isn't ready: no `status:ready` label in any case (item 12 now fetches `labels`; labels that aren't a list exit 2). A parent read from a file passes only when it says `Status: blocked` (a list mark and bold allowed), since `coordinate`'s local mode adds `Status: ready` to a file with no status line. In `docs/issues/` the parent says `Status: blocked` until its last child is `done`. A value that states both a split and an exception fails: keep one. With no open child left, the check says to close the parent. The size script exits 2 on an empty list, accepts a `null` body as no Size line, and in local mode skips `Status: done` files; the consistency check says to list only this pass's open files when other passes have some. (#375, review rounds 1 to 3 on #391)
- **Options considered:** narrow the parent to its first child; move the parent out of the pass's milestone; a Size form for the parent that the check passes. For old files: skip done files in the script; only tell the checker to pass the pass's files; both
- **Why:** A form the check passes keeps the parent and its links where the pass's reader looks, and needs no milestone moves. Checking its children and its status stops a parent that splits into nothing, or that the loop would build. `Status: blocked` is a status `coordinate`'s local mode already knows and never builds. Skipping done files is a few lines in the script; another pass's open files can't be told apart from the file alone, so the checker lists the files.
