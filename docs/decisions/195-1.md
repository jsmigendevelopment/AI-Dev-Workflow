# Decision 195-1

- **Date:** 2026-11-27
- **Decision:** How #195 finishes the preflight follow-ups. (1) Before the read, the folder that holds the common `.git` folder counts as a checkout only when its own `.git` leads back to that folder; the folder holding a bare repo or a `--separate-git-dir` folder (`~/proj.git`) no longer hides every PATH folder under it. A checkout no record names is still found by the `.git` search above each folder. (2) When a PATH entry is left off because a `.git` at or above it can't be read, the git, npm and gh rows say the tool is checked after the repo is read (limited) instead of "isn't installed" (blocked). (3) `scripts/preflight.mjs` is split: the safe-value filter, ladders, table and Environment record go to `scripts/preflight-output.mjs`, the version range and package manager row to `scripts/preflight-versions.mjs`, both synced next to `preflight.mjs`; `preflight.mjs` re-exports `render`, `readRecord`, `withRecord` and `satisfies` so its callers don't change.
- **Options considered:** Keep counting the parent folder and document the cost (a whole home folder's tools lost before the read); count it only when its `.git` resolves to the shared folder (chosen); for the row, a new status; one master for output only (still over 300 lines)
- **Why:** The check costs one `.git` read and only drops what really is a checkout. The limited row matches the other fail-closed rows. Two new masters bring every preflight master under 300 lines.
