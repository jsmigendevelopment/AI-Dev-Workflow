# Decision 333-3

- **Date:** 2026-11-27
- **Decision:** `has-records` counts any valid `job` record with the pull request's number and the head sha, whichever job wrote it. In practice that is the reviewer's `job=review-code` line: the builder's finish record names the commit before it and sits on the branch, not in the coordinator's checkout. A file that fails `validate` counts as missing, never as an error. (#333)
- **Options considered:** only `job=review-code`, which would also refuse a head that `qa` or the security review ran on but whose review line was lost, and gives the same answer in every other case; any `job` record; any `job` record but the builder's, which adds a rule for a record that can't match anyway
- **Why:** The simplest rule that meets AC-1: every record is checked by `validate`, and the head sha ties it to the exact commit that merges.
- **Originator:** AI pick, not reviewed
