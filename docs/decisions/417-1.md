# Decision 417-1

- **Date:** 2026-11-27
- **Decision:** When the reviewer runs the checks itself (decision 28), `pr-review` ends its `Checks:` comment with the printed output of `insights.mjs line check pr=<pr> sha=<sha> 'commands=<commands>' state=<success|failure> 'failed_step=<failed>' flaky_rerun=<rerun> fence=<fence-name>`, and runs `mark-check.mjs` without `--record`. `line` already takes every field the `check` kind has, so `insights.mjs` is unchanged. The fields match the gate's own record (#331): the same command names as the comment and `failed_step` null on a pass. `fence` is only the fence's name, the word after `Fence:` (`bubblewrap`, `sandbox-exec` or `none`), and is left out when the commands didn't run through `fence.mjs`. Inside the single-quoted values, each `'` is written as `'\''`. (#417, review round 1 on #438)
- **Options considered:** keep `mark-check.mjs --record` as well, which writes a second record into the reviewer's checkout that it never commits, and counts one run twice if the reviewer and the coordinator share a checkout; only `pr`, `sha` and `commands`, as the issue's acceptance check names, which drops the state the gate's record carries; every field the gate's record has, through `line`, with no second record. For the fence (review round 1): the whole `Fence:` line in single quotes, the first pick, which breaks the shell on every real line `fence.mjs` prints, since each holds an apostrophe; keep the whole line and tell the reviewer to write each `'` as `'\''`, which works only if the reviewer escapes a long line without a slip; pass the values through a quoted here-doc, which makes the command several lines and harder to paste; only the fence's name, one plain word that needs no quotes.
- **Why:** The coordinator's harvest already keeps `check` lines from trusted logins, so one pasted line is all the merge step needs. A record file the reviewer never commits can't reach main, so it only adds a way to count one run twice. The fence's name can't break the shell, so the most common value needs no escaping at all; the reason after it stays in the `Checks:` comment. Command names are the reviewer's own and rarely hold an apostrophe, so the `'\''` rule is a small backstop there, not the main path.
