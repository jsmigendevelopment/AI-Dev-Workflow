# Decision 417-1

- **Date:** 2026-11-27
- **Decision:** When the reviewer runs the checks itself (decision 28), `pr-review` ends its `Checks:` comment with the printed output of `insights.mjs line check pr=<pr> sha=<sha> 'commands=<commands>' state=<success|failure> 'failed_step=<failed>' flaky_rerun=<rerun> 'fence=<fence>'`, and runs `mark-check.mjs` without `--record`. `line` already takes every field the `check` kind has, so `insights.mjs` is unchanged. The fields match the gate's own record (#331): the same command names as the comment, `failed_step` null on a pass, and the `Fence:` line's first line. (#417)
- **Options considered:** keep `mark-check.mjs --record` as well, which writes a second record into the reviewer's checkout that it never commits, and counts one run twice if the reviewer and the coordinator share a checkout; only `pr`, `sha` and `commands`, as the issue's acceptance check names, which drops the state and fence the gate's record carries; every field the gate's record has, through `line`, with no second record
- **Why:** The coordinator's harvest already keeps `check` lines from trusted logins, so one pasted line is all the merge step needs. A record file the reviewer never commits can't reach main, so it only adds a way to count one run twice. Matching the gate's fields keeps the weekly report's numbers the same whichever agent ran the checks.
