# Decision 129-1

- **Date:** 2026-11-28
- **Decision:** #129's run record is #329's `job` record, as the issue's comments say. This change adds only what was still missing, on the existing writer and readers: `insights.mjs line job` ends with a run line people read (`Run: <job> · <model> · <effort> · <time> · #<pr> @ <sha>`), the time coming from a new use of the existing `started` field; an optional envelope field `model_from` says where the model and effort were read, or why one is `unknown`; `scripts/insights-runs.mjs` (`npx onrails runs --pr <n> | --issue <n> | --day <yyyy-mm-dd>`, `--brief` for `/back`) prints the chain; and `build` adds `Agent-Model:` and `Agent-Effort:` commit trailers. Records have no account field at all, so the writer refuses `account=` and no record names an account, whatever the profile says. A build's time runs from its start record; a reviewer's from the `started=` it passes. A time no record gives is `unknown`.
- **Options considered:** a separate `docs/runs/` log, as the issue first said (a second format, which the owner's comment of 2026-11-27 ruled out); a new `footer` command beside `line` (two commands with the same fields for every reviewer to paste); the run line printed after the comment that `line job` already prints, as above. For accounts: an optional `account` field behind a profile switch, or none.
- **Why:** Every reviewer already pastes `line job`, so the visible line comes with no new step, and the comment before it stays the one `harvest` reads. `model_from` is optional, so every record already on main still passes #411's `validate`. No account field is the safe reading on a public repo, and the issue says model, effort and time are what matter.
- **Left out:** the "requested vs served" fields and the optional turns and tokens (no acceptance check names them), and AC-3's eval, filed as its own issue: the default eval run is at the 40-run cap.
