# Decision 708-1

- **Date:** 2026-11-28
- **Decision:** `npx onrails config get <section.key> [dir]` (`cli/src/config.mjs`) resolves a setting from three layers, first match wins: `project` (`<dir>/docs/profile.toml`), `personal` (`~/.onrails/profile.toml`, or `~/.ai-dev-workflow/` while only that exists), then `kit default` (the kit's `profile.toml` template). It prints `<value> (<layer>)` on stdout and exits 0. (1) **Name:** exactly `section.key`, letters, digits, `_` and `-`; anything else (no dot, a third part such as `me.signature.name`) exits 2 with a usage line. (2) **Missing file:** a layer whose file is missing is skipped; any other read failure (a folder, no rights) is an error and exits 1 through the CLI's own `Error:` line. (3) **Blank value:** `key = ""` counts as not set and asks the next layer, as `latest.mjs` reads `[updates]`; the template has blank lines (`me.name`) that mean "no value", and `profile copy` copies them into a project, so a blank project line must not hide the personal value. (4) **Shapes read:** `"text"` (basic strings with JSON-style escapes) and `'literal'` strings, `true`/`false`, whole numbers, then a `#` comment. A line in any other form (array, inline table, multi-line string, a value with a control character) is reported on stderr, exit 1, and the lower layers are not used, since the layer that has it would win in TOML. A table inside a table is not a section this reads. (5) **Not found:** exit 1, one plain line on stderr that names the key, nothing on stdout, so `$(npx onrails config get x)` never captures an error. (6) **Secrets:** a name is secret-looking when a whole word of the section or key (split at `_`, `-` and a lower-to-upper change) is `token`, `secret`, `password`, `passwd`, `passphrase`, `key`, `apikey`, `credential`, `credentials` or `bearer`. Then nothing is read: one line on stderr says so, exit 1. `auth` and `monkey` are not on the list (the template's `web.auth = "Clerk"` is a plain choice). (7) **Read only:** it never asks, writes or offers the home-folder move.
- **Options considered:** Export `setting()` from `latest.mjs` (it can't say which layer answered, and it treats a blank value as not set only through its own switch list). Use `signature-toml.mjs` (it refuses any table but `[me.signature]`). A fixed list of secret key names (misses new ones). Print the value and tell the person it is a secret (it would defeat the point). Exit 2 for a missing key (a script can't tell "not set" from "used wrongly").
- **Why:** The issue asks for the first step of layered settings with no new dependency, copying the nearest small reader. The line reader in `config.mjs` is the same shape as `latest.mjs`'s `setting()`, kept separate because the answer must name its layer.
- **Originator:** AI pick, not reviewed (Full automation). The blank-value rule, the secret-word list and its stderr and exit-1 behaviour, exit 2 for a malformed name, and stopping at a project line that isn't read are the builder's picks.
