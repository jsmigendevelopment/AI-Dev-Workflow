# Decision 574-1

- **Date:** 2026-11-28
- **Decision:** In the Go guide's `ReplaceAttr` example, the `msg` case checks `a.Value.Kind() == slog.KindString` and the `level` case checks `a.Value.Kind() == slog.KindAny`, both next to the existing `topLevel` (`len(groups) == 0`) guard. Both checks are kept: the group guard stops an attribute inside a group, the kind check stops a user attribute of another type. The guide says in a comment that a user string attribute named `msg` at the top level still matches, so the rule is never to use a built-in key (`msg`, `level`, `time`) as an attribute name.
- **Options considered:** (1) The group guard alone, as before: a top-level user `level` string is lowercased and a top-level user `msg` is renamed to `event`. (2) The kind check the issue asks for, with the group guard kept: fixes `level` fully (slog's own level is a `slog.Level`, kind `Any`, and a user `level` string is `KindString`) and `msg` for every type but string. (3) Drop the rename of `msg` and add `event` as a separate attribute: changes the logger's shape, which is out of scope.
- **Why:** Checked against Go 1.24.7 in a scratch module (`go vet` clean, `gofmt` no diff): a user `level` of `"LOUD"` stays `"LOUD"`, a user `msg` of `42` stays `42`, and an attribute inside a group is untouched. slog's own `msg` is a plain string (`KindString`), so no check inside `ReplaceAttr` can tell it from a user string `msg`; the example says so instead of claiming more.
