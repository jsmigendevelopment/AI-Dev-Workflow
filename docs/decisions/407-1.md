# Decision 407-1

- **Date:** 2026-11-28
- **Decision:** How #407 closes the gaps the round 3 review of #396 found in `pr-size.mjs` (decision 377-2 has the rule as it now stands).
  1. **Binary files:** a known binary list (images, fonts, archives, audio and video, compiled code, `.pdf`, `.db`, `.lockb`, office files) replaces the source list. Any other file that shows as binary is exit 2, with its name. The source list stays only to word the message ("source code" or "a file of no known binary type").
  2. **One path for every file that isn't a known binary type** in pull request mode: its content at the head decides. A NUL marks it binary (then exit 2). An `added` or `modified` entry with 0/0, no patch and content but no NUL is exit 2. The issue names source entries; the same rule for every unknown type keeps one path, and an unknown type was already a contents call under item 1.
  3. **A mode change is spotted by its blob, not by GitHub's status word.** `modified` with 0/0, no patch and content is exit 2 (AC-407-2), unless the entry's blob `sha` is the base's own blob at that path (`git rev-parse <base>:<path>`; the base is in the checkout already, and the gate uses main's HEAD). Then only the mode changed, and it passes. A `changed` entry (GitHub's documented status for a type change) passes as before. The round 2 test that called a mode change `modified` now says `changed`, with the same assertion that it passes; a new test covers a `modified` entry with the base's blob. A missing or different blob is exit 2, never a pass.
  4. **`.gitkeep`:** no special case. An empty file of no known type now goes through the content check, which sees it's empty, so it isn't listed as binary.
  5. **`sizeAtHead()`** asks `git cat-file --batch-check`, which answers `missing` for a path the head doesn't have and fails only on a real error. Any other answer or failure is exit 2.
  6. **Script and style blocks** are stripped from the description after HTML comments, fenced code and indented code, case-insensitive, and an unclosed one runs to the end. A tag inside inline code (`` `<style>` ``) is text: the same pass matches code spans first and keeps them, so the reason on a visible line is printed as written.
  7. **Monorepo fixtures:** a known limit in decision 377-2, not counted as fixtures. They count, so the check errs toward bigger.
  8. **Tests** go in a new file, `cli/test/pr-size-guards.test.mjs`, so `pr-size.test.mjs` stays under 300 lines.
- **Options considered:** for item 1, reword 377-2 to allow any non-source binary (keeps the gap the review found; AC-407-1 rules it out). For item 3, trust the `changed` status alone (round 0: GitHub's docs don't say what sets it, so a chmod listed as `modified` would stop falsely); the blob compare is one local `git rev-parse`, only for a `modified` 0/0 entry. For item 6, strip inline code spans outright (it would cut code out of a printed reason). For item 5, match git's error text for a missing path (it differs across git versions), or `ls-tree` first (two calls per file). For item 7, count `apps/*/test/fixtures` as fixtures (widens what's skipped; any nested `test` folder was ruled out in round 1).
- **Why:** each pick fails closed with the least code. A file the script can't count never passes, and the honest cases (an image, an empty file, a deleted file, a mode change or rename of a text file) still do.
