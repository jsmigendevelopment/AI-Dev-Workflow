# Decision 698-1

- **Date:** 2026-11-28
- **Decision:** On Full, the update check (#448) opens **one update pull request**, decided by `latest.mjs plan --prs <file> [--issues <file>]` in the same script as `line` (no new file). (1) **Output:** one JSON line `{ action, version, bump, fyi, pr?, issue? }`. `pr`: Full, a minor or patch release, nothing open. `wait`: a pull request on `^chore/\d+-update-onrails$` (read from `head.ref` of GitHub's REST list or `headRefName` of `gh pr list`) or an open issue titled exactly "Update onRails to <x.y.z>" is open, so there is never a second. `suggest`: a major version (`fyi: true`), a level below Full, or `[updates] on_full = "suggest"`. `none`: nothing newer than the repo's kit, or the registry can't be read. (2) **Fail closed:** a list that is missing, empty, not JSON, or not a list (GitHub's error object) exits 2 with one line on stderr and prints nothing, so a broken `gh` can't produce two pull requests. The files come from `gh api ... --paginate --slurp`, and a list of pages is read as one list. (3) **The level** is read from `docs/stack.md` (`- **Level:** full`) the way `agent-files.mjs` and `notify.mjs` read it; no level means below Full. (4) **The switch** is `[updates] on_full = "pr" | "suggest"` beside `check`, default `pr`, in the profile template. (5) **The steps** are skill text: `back` (step 3) and `coordinate` (loop step 1, once a day) run `plan` and file the issue "Update onRails to <version>"; one builder works it on `chore/<n>-update-onrails` with the `update` skill's "On Full, as a pull request" steps (`npx --yes onrails@latest update "<project root>"` from a temp folder, no `--all`, checks, `Closes #<n>`). A release is never cut: no bump, tag or publish. (6) **Tests** use a list file and the fake registry on 127.0.0.1; none reaches GitHub or runs `npx onrails@latest update`. (7) The two nice-to-haves from the #696 review are done: the hang-test bounds in `cli/test/latest.test.mjs` are 2500 ms (still above the 2-second give-up), and the header comment in `.claude/hooks/session-start.mjs` is wrapped.
- **Options considered:** For (1), let the skill text alone check the open issue (as the #448 design did; a model can skip it, and the loop re-runs every sweep, so the helper takes an optional `--issues` file), or call `gh` inside the script (not testable without GitHub). For (2), treat an unreadable list as an empty one (two pull requests when `gh` fails). For (5), update the plugins and global skills too with `--all` (they belong to the machine, not to a pull request).
- **Why:** The helper is a pure function plus a file read, so every acceptance check runs without GitHub, and the only path to `pr` is a list that was read and holds no update. Keeping it in `latest.mjs` reuses the sync copies, and the script stays under 300 lines.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the four acceptance checks, the switch and the skill text. The picks are: the optional `--issues` file, so an open "Update onRails to <version>" issue is checked by code and not only by the skill; reading a `--slurp` list of pages; exiting 2 for a non-list file; and tightening both hang-test bounds to 2500 ms.
