# Decision 320-1

- **Date:** 2026-11-27
- **Decision:** How the Sentry add-on's lint step (step 11 of its Apply list) stays inside the add-on's own files (#320).
  - **Cause:** on a fresh pack copy, `worker-configuration.d.ts` doesn't exist yet: it is git-ignored and only `pnpm lint` (through `pnpm cf-typegen`) or `pnpm typecheck` makes it. Step 11 ran a bare `pnpm exec eslint --fix .` before that. With the Worker's types unresolved, the typed rules' fixes misread the code: `@typescript-eslint/no-unnecessary-type-assertion` dropped `as NodeJS.ProcessEnv` in `scripts/connect/shell.ts` and `scripts/connect/terminal.ts` and a `!` in `src/modules/notes/server/notes.http.test.ts`. `pnpm typecheck` then failed with TS2769 twice and TS2345. With the types made first, the same whole-project fix changes nothing, so no rule is wrong and none is turned off.
  - **Fix:** step 11 is now three commands joined by `&&`, so ESLint never runs without the types: `pnpm cf-typegen`, then `pnpm exec eslint --fix` and `pnpm exec prettier --write` on the files the add-on copies or edits, named one by one. The test takes the files the steps edit from the backticked pack paths in Apply, so a new edited file must join both lines. Step 5's whole-project `pnpm format` is folded into step 11.
  - **Checked by hand on a fresh app** (`init`, `add tanstack-start`, `git init`, `pnpm install`, the add-on's steps 1 to 10 with no account): the new step 11 changed only `src/client.tsx`, `src/server.ts`, `src/lib/monitoring.test.ts` and `vite.config.ts` (import order and formatting, and the `as string | undefined` on `VITE_SENTRY_DSN` that step 4 makes unneeded), `pnpm typecheck` passed, and `pnpm check` passed end to end (458 tests).
- **Options considered:**
  - Name the files in the step (works in every shell, and the reader sees what is touched); take them from `git diff --name-only` (needs a POSIX shell and a clean tree before the add-on); or keep `eslint --fix .` with `pnpm cf-typegen` first (no rewrites today, but still free to change files the add-on never touched).
  - Make the types with `pnpm cf-typegen` (the pack's own lint does this), run `pnpm lint` (also checks, and fails on warnings it can't fix), or turn off the typed fixes (weakens the lint).
  - The other add-ons (analytics, database-supabase, email-resend, jobs, r2-uploads, stripe) have the same `eslint --fix .` step. They are outside this issue's fence, so they went to #425, with the pack's pre-commit hook, which runs `eslint --fix` on staged files without the types too.
- **Why:** the issue asks for the step to change only the add-on's files, and the cause was missing types, not a rule. Making the types first fixes the cause; naming the files keeps the step inside its fence even if a future rule's fix misbehaves.
