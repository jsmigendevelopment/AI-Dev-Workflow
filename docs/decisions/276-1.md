# Decision 276-1

- **Date:** 2026-11-27
- **Decision:** How #276 keeps the bind-mount preflight test (AC-182-2) from failing for a non-root user. `canMount()` in `cli/test/preflight-path.test.mjs` becomes `mountSkip()`, which returns a skip reason or false. Besides unshare and a bind mount, it runs `unshare -rm stat -c %u` on the real git's folder and every folder above it, and skips with "the real git's folder shows as nobody inside an unprivileged user namespace" unless each prints `0` (the caller maps to 0 in that namespace, so this covers root and the caller's own folders). Preflight's ownership rule is unchanged. Verified as root (the test runs and passes) and under an unprivileged uid with `setpriv`, since the session's sandbox refused `useradd` (the full CLI suite passes, the test is skipped with that reason, AC-180-3 passes).
- **Options considered:** Only the real git's folder, as the issue suggested; a uid map (`newuidmap`) so root's files keep their owner, which needs setuid tools and a subordinate id range most machines don't give a test; loosening preflight to trust 65534
- **Why:** Preflight checks the folders above too, so checking only the folder could still let the test run and fail where a parent shows as nobody. A uid map isn't available to an ordinary user without setup. Trusting nobody would weaken the rule the test protects (AGENTS.md rule 7).
