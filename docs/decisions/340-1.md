# Decision 340-1

- **Date:** 2026-11-27
- **Decision:** The Go pack (#279) builds on these picks from the dossier [Go API platform](../../research/go-api-platform.md). (1) The `stack` grill asks one question with seven signs that an app outgrows Workers: more than 5 minutes of CPU for one request or 15 minutes for one job, more than 128 MB in memory, a program outside JavaScript, TypeScript, Python and Rust, uploads over 100 MB, more than 6 calls waiting at once, a server that never stops, or a database over 10 GB. Any "yes" means a Go backend off Workers. (2) The Go service runs on Google Cloud Run, deployed with `gcloud run deploy --source .` and previewed with `--no-traffic --tag`; Fly.io is the runner-up. (3) Its database is Postgres on Neon through pgx, with goose migrations and sqlc queries; never D1 over its HTTP API. (4) It checks Clerk sign-in with Clerk's Go SDK middleware; golang-jwt v5 with keyfunc v3 is the fallback. (#340)
- **Options considered:** hosts: Cloudflare Containers, Fly.io, Railway, Google Cloud Run, a small VPS; databases: D1 over HTTP, Neon, Supabase, SQLite on a volume; migrations: goose, golang-migrate, Atlas; queries: sqlc, pgx alone, sqlx, GORM, Bun; sign-in: Clerk's Go SDK, golang-jwt with keyfunc, jwx
- **Why:** Cloud Run costs nothing at idle and at small load once a billing account exists, builds Go with no Dockerfile, and gives a preview URL per change from the CLI alone, which fits the kit's no-Actions rule; Fly.io is also free for a small app with a card, but its own preview guide uses GitHub Actions. Cloudflare calls D1's HTTP API best for admin use, under an account-wide limit of 1,200 requests per five minutes. Neon is free, scales to zero and branches per preview from its CLI. Clerk's SDK caches keys for an hour and checks `azp` and clock skew for the app. Confidence: high for the Workers limits and against D1 over HTTP, medium for the rest. Re-check by 2027-02-27.
