# Decision 245-2

- **Date:** 2026-11-27
- **Decision:** A builder in the loop, working in a worktree of the coordinator's checkout, doesn't get the local gate's fence (#245, AC-245-3). `coordinate` step 4 says so: the builder runs the loop's own work on a branch the coordinator claimed, needs the coordinator's git and GitHub login to commit and push, and never runs another branch's or a pull request's code; nothing it writes merges before step 6.1 runs it behind the fence.
- **Options considered:** The same fence for every builder command (it would hide the git folder the worktree shares and the login the builder pushes with, so it can't commit); a fence only for the builder's install and tests (a second wrapper path to keep, for code the gate fences anyway before merge); no fence for builders, with the gate as the boundary.
- **Why:** The gate is where code the loop didn't write by hand (a head's install scripts, its checks) first runs before it can reach main, and that run is fenced. A builder's own tool permissions or sandbox still apply to it.
- **Originator:** AI pick, not reviewed
