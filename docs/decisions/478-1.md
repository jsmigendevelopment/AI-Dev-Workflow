# Decision 478-1

- **Date:** 2026-11-28
- **Decision:** How `agent-files.mjs gate` follows the review carry (#478). (1) Only on Full, and only when the head has no writer's verdict of its own: `decide()` marks that one refusal `need`, and only it is lifted. A fail at the head, an unchecked fail, too many files or a moved head refuse as before. Recommended and Hands-on keep the label. (2) The proof is `insights.mjs carry`'s own. `insights-carry.mjs` exports `fetchMain()` (the fetch of main into `refs/remotes/origin/main` that `carry` already ran, now one function `carry` calls) and `mergedFrom()`, which takes a commit's first parent and runs `carry`'s existing `notCleanMerge()` on it: two parents, the second on origin/main, and a merge with main's attributes that gives exactly the head's tree, through `carry`'s isolated git. No second proof. (3) A chain: from the head, each step back must be a clean merge of main into its first parent. At each commit on the way the gate runs `decide()` again with that commit as the head, the access of that commit's voters checked as at the head. The first writer's pass ends the walk and passes, and names that commit; the first writer's fail (or a fail whose access got no answer) ends it and refuses. A read-only login's pass is ignored, so the walk goes on and stops at the first step that isn't a clean merge. (4) A step that isn't a clean merge, a commit that isn't in the checkout or a failed fetch keeps the refusal at the head and adds carry's own reason, so the message still asks for a line at the head. (5) The checkout is the one the gate runs in (`git rev-parse --show-toplevel` from the current folder), which `coordinate` step 7 already says is the checkout of main; step 7 now says to fetch the branch first. (6) The tests are real git, `cli/test/agent-files-carry.test.mjs`, on `insights-carry-fakes.mjs`'s fixtures, with a fake gh.
- **Options considered:** For the proof: call `insights.mjs carry` as a child process (it writes records and needs them first, so the gate would depend on the harvest); copy the merge check into `agent-files.mjs` (a second proof, which the issue rules out). For the chain: one step only (the issue's case, but a records-only move of main after the merge would again need a fresh review); trust a pass at any ancestor (a hand edit in between would carry). For where the checkout comes from: `CLAUDE_PROJECT_DIR` first, as `insights.mjs` finds its own (the gate's step says to run it from your checkout of main, and the current folder is what the caller controls); fetch the pull request's branch inside the gate (more network calls and a new ref in the coordinator's checkout; step 7 already fetches it for `carry`).
- **Why:** Reusing the one proof keeps the gate and `carry` agreeing on what a clean merge of main is. Running `decide()` again per commit keeps every rule about fails, access and levels in one place. A chain of clean merges brings in nothing but main's own changes, so the reviewed diff is the same at every step.
- **Originator:** AI pick, not reviewed (Full automation: the owner, 2026-11-26). The ask is the issue's own words: "When the head is a clean merge of main into a commit with a writer's `Weakening review: pass`, let `gate` accept that line."
