# Decision 418-1

- **Date:** 2026-11-28
- **Decision:** The eval check `AC-378-1-size-checked` matches `/^\s*node\s+\S*pr-size\.mjs\b/`: only a command that starts with `node`. A child of a size split gets no free send-back, and the `Sent back` line goes on the issue as well as the pull request. The rule is in `coordinate` 6.1.1 and in decision 378-1. A child is marked by `Split from #<n>` in its issue, which the split brief tells the builder to write on each child issue. In local mode the line already sits under `## Comments` of the issue file, so `references/local-mode.md` is unchanged.
- **Options considered:** for the match, the issue's regex as written, any `node` word anywhere in the command (the old rule), or a parse of the command's first word through `command-for.mjs`. For the child mark, `Split from #<n>` in the issue body, a label, or a lookup of every issue that links the parent. For the record, a comment on the issue, a field in the insights `job` record, or the pull request comment only.
- **Why:** the issue's regex is one line, and the good plan and every shortcut still behave (the good plan's size step starts with `node`). A line the child's own issue carries can be read by a coordinator with no history; a label or a link search needs more calls, and a new record field is #380's. Putting the send-back line on the issue means a later pull request of the same issue, or a fresh coordinator session, finds it without the first pull request's comments.
