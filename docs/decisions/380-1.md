# Decision 380-1

- **Date:** 2026-11-27
- **Decision:** A run's cost goes on the `job` record as four optional fields: `usage_before`, `usage_after`, `usage_from` and `send_back`. `model` and `effort` were already on every record. `send_back` is one of `size`, `review-must`, `checks`, `infra` and `process`, and is allowed only with outcome `fail`, `failed`, `stopped` or `handed-off`. `usage_from` is required once either usage field is given. The run that sends work back writes the reason: `coordinate` 6.1.1 writes a `job=size-check` record with `send_back=size`; `pr-review` and `pr-security` add `review-must` on request changes; `qa` adds `checks` or `infra` on a fail; `build` adds `infra` or `process` when it stops. The local gate's red run stays its `check` record with `state: failure`, so it gets no second record. The fields are optional so every record from before #380 still validates in the same bytes.
- **Options considered:** a new `run` kind for cost, written next to each `job` record (two records per run, and the weekly report joins them); required fields on `job` (every record already on main would fail `validate` and `land --verify`); optional fields on `job`, checked together when present, as above. For the send-back: a field on the builder's next start record (it knows why it was sent, but the reviewer saw the finding); a field on `fix-round` (only the coordinator writes it, and a size send-back isn't a review round, decision 378-1); the record of the run that sends it back, as above.
- **Why:** #281 folds #129's run record into `job`, so cost belongs there. Optional fields keep the shared format backward compatible. The run that sends work back is the one that knows the reason.
