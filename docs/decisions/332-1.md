# Decision 332-1

- **Date:** 2026-11-27
- **Decision:** A records-only pull request from `insights.mjs land` is reviewed by `insights.mjs land --verify <pr>`, not by `pr-review`, `qa` or the security review. It passes only when gh's own login opened it from a `chore/insights-<yyyy-mm-dd>-<hhmm>` branch of the repo, against main, and every changed file is an added, valid record under `docs/insights/` whose name matches it. It also stands in for `own-branch.mjs`. The pull request still goes through the local gate (step 6.1 from 6.1.2) and merges on `Checks: pass @ <sha>` with `--match-head-commit`. (#332)
- **Options considered:** a full `pr-review` (and `qa`, security) per records pull request, which spends a fresh agent each sweep on JSON files no person reads; one `docs/insights.jsonl` with `merge=union` in `.gitattributes`, which breaks #329's one-file-per-event format and lets a bad line in unchecked; a script that checks the whole diff
- **Why:** The diff of a records pull request is fixed in shape: new JSON files in one folder. A script checks that shape fully and cheaply, and refuses anything else, so a records pull request can never carry a code change past review. The gate still runs on it, so main's checks stay green.
- **Originator:** AI pick, not reviewed
