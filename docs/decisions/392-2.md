# Decision 392-2

- **Date:** 2026-11-27
- **Decision:** How `lesson check --project` reads files (#392), on top of decisions 322-1 and 385-1.
  - **Env files:** `.env`, `.env.<name>`, `.env-<name>`, `.envrc`, `.envrc.<name>` and `.envrc-<name>`, in any folder, are never opened, by name before any read and by real name after a link is resolved. `.env.example` is still the one that is read, for its variable names.
  - **The cap:** a file or a pipe is read in chunks that never go past 1 MB and one byte, so a pipe over 1 MB is refused after reading exactly that much, as a file is. Decision 385-1 said so; before this change a pipe could read up to 64 KB more.
  - **A pipe with no writer:** `lesson check <pipe>` waits in `open()` until something writes, as `cat` does. Ctrl-C ends it. The deny set's own reads never open a pipe: they skip anything that isn't a regular file before opening it.
  - **Guard tests:** the 1 MB cap on the deny set's reads and the skip of a named pipe inside the project each have a test that fails when the guard is removed.
- **Options considered:**
  - Env files: add only `.env-*` and `.envrc` as the issue names them, or also their `.envrc.<name>` and `.envrc-<name>` siblings. The wider one fails closed and costs nothing: no kit or pack file has such a name.
  - The cap: change the docs to say "about 1 MB", or cap each read so the docs are exact. The code change is one line.
  - A pipe with no writer: open it without waiting and refuse it at once, or wait as `cat` does. The person names the file, so waiting is what they expect, and it isn't new.
- **Why:** Rule 9 holds for the env file names projects use, and the docs say exactly what the code does. (Correction by #410: the list missed `.env_local`, `prod.env`, `.ENV`, `.Envrc` and files in `.env.d/` or `.envrc.d/`. Decision 410-1 covers them.)
