# Decision 165-1

- **Date:** 2026-11-27
- **Decision:** How #165 stops decision rows clashing between parallel pull requests. Each new decision is its own file, `docs/decisions/<issue>-<n>.md`, and its id is the file name (`165-1`). Rows 1 to 115 stay in the table in `docs/decisions.md` with their numbers, and the table takes no new rows. A changed decision is a new file that says `Replaces decision <id>`; the old one isn't edited. In an app, the kickoff (one session) still writes table rows; after it, every decision is a file. `cli/test/decision-ids.test.mjs` merges two branches that each add one with plain `git merge`, checks the table is frozen and the ids unique, and checks every `decision <id>` cite in the kit's skills, scripts, tests, docs and changelog resolves.
- **Options considered:** ids `<issue>-<n>` as rows in the same table; rows numbered only at merge by a script; keep numbers and a renumber script; one file per decision
- **Why:** Ids that can't clash still conflict as text when two branches append a row at the same end of the table, and GitHub's merge ignores custom merge drivers. A file per decision touches no shared line, so both merge with no step at merge time and no renumbering. Editing the old row to note a replacement would touch shared lines again, so the new file names what it replaces.
