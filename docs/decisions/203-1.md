# Decision 203-1

- **Date:** 2026-11-27
- **Decision:** How #203 finishes `ci local`'s stop handling. A step that a recorded signal stops before it runs throws a private `Stopped` error, which `pullRequest` catches, so no caller prints a failure line for it; `finally` still removes the worktree. `update` passes on only a stop (exit code above 128) from `ci local`, and `update --all` returns that code at once, before `doctor` and the summary; every other `ci local` result still leaves `update`'s exit code alone, as decision 84 says. `docs/stack.md` committed as a folder is caught by the same pre-write check as a symlink, with `is a folder`. Replaces decision 84 for a stop only.
- **Options considered:** A quiet logger that drops lines once a signal is recorded (would also drop the "local branch is kept" note); make `update` fail on any `ci local` failure (decision 84 rejected it); catch EISDIR around the read (a thrown error after the check, not a plain stop)
- **Why:** The throw marks exactly the steps that never ran, and a step killed while running still says so. A stop means the person wants nothing more to run, which a failed `ci local` doesn't.
