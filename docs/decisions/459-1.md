# Decision 459-1

- **Date:** 2026-11-28
- **Decision:** Two tests in `cli/test/connect-blocks.test.mjs` walk every provider file in every secrets mode and fail when a value is added that trips the "every deploy (test and production)" name (decision 444-1). `AC-459-1` asserts that the only values carrying the name are Sentry's `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT`, in mode `none`. `AC-459-2` takes the "assert no such value exists" route: it asserts that no value asked in that group has a `shape.prefix`. `prefixesFor` in `stacks/tanstack-start/scripts/connect/providers.ts` still counts only the `production` group as production; its doc comment now says so. No behaviour changes.
- **Options considered:** count the "every deploy" group as production in `prefixesFor`; assert that no value in the group has a key-prefix rule; leave it to the decision's note
- **Why:** No value in that group has a prefix shape today. GitHub's `SITE_URL` and `APP_URL` have one (`https://`) and match the rule, but have no place on ci = "local", so their group is empty and never asked. A rule for a case that doesn't exist would be untested code. Counting the group as production would also be a guess: a value in it goes to the test and the production deploy, so neither "live keys only" nor "test keys only" is right for it. The test makes the first such value fail loudly, and its failure points at `prefixesFor`, where the person who adds it picks the rule with a real key shape in hand. The assertion is stricter than a live-or-test rule: any prefix fails it, `https://` included.
