# Decision 362-1

- **Date:** 2026-11-27
- **Decision:** `CHANGELOG.md` merges with git's union driver: one line in the kit's `.gitattributes` and one in the web pack's (`stacks/tanstack-start/.gitattributes`), the only template that writes an app's `.gitattributes`. `coordinate` step 7 names it and says to check the merged `CHANGELOG.md` once, since union keeps a line twice when both sides edited it. The core kit that `init` installs gets no `.gitattributes`: it goes into existing repos that may have their own, and a kit app keeps no `CHANGELOG.md` unless it adds one.
- **Options considered:** Resolve each CHANGELOG conflict by hand as now; one file per entry, merged into the CHANGELOG at release (out of scope in #362); the union driver in the committed `.gitattributes` (chosen)
- **Why:** Two branches that each add a line under the same Unreleased heading conflicted on nearly every merge of main this run, and union kept both sides correctly every time the coordinator used it. It is one line and needs no script. GitHub's own merge ignores it, but the loop merges main into branches locally.
