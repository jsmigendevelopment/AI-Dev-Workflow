# Decision 432-1

- **Date:** 2026-11-28
- **Decision:** When `pr-size.mjs` trusts the checkout it runs from (#432, round 1 fix). (1) Every git call keeps `GIT_CONFIG_GLOBAL=/dev/null` and the rest of the isolation. (2) The script finds the folder above its real path that holds `.git` (a folder, or the file of a linked worktree), without git. (3) It asks git to read the operator's own `safe.directory` list from the files git would read: `GIT_CONFIG_GLOBAL` if set (even empty: then git reads no user config and nothing is listed), else `$XDG_CONFIG_HOME/git/config` (default `$HOME/.config/git/config`) and then `$HOME/.gitconfig`. An unset or empty `HOME` has no user files. Each file is read with `git config --file <file> --includes -z --get-all safe.directory`, through the same isolated `git()` as every other call (`GIT_CONFIG_GLOBAL=/dev/null`, no trusted folder), from a scratch folder, so no repo is opened. Git parses the file, includes and all; the script has no parser of its own. The entries are applied in file order, so a clear in a later file wins. (4) Only when that list holds that folder exactly, or `*`, does every call (the first `rev-parse --show-toplevel` included) add `-c safe.directory=<that folder>`. `*` is read as git reads it, "the operator trusts every folder"; the script still names only the one folder and never passes `*` on. An empty entry clears the entries before it, as in git. (5) Otherwise no call trusts anything, and a checkout owned by another user is refused with git's "dubious ownership" error and exit 2, as on main. (6) Whatever git reads as a list entry counts, and nothing else: git's own reading of quotes, `#` and `;` comments, a bare `directory` key (an empty entry, which clears), backslash continuations and includes. Exit 1 from git is a file with no entry (a missing file, or a folder, which git only warns about). Any other non-zero exit, such as a config line git rejects, lists nothing at all, from any file: it fails closed, and the checkout is refused with the error git prints. A trailing slash or a symlinked spelling of the folder is a different string and is not the folder.
- **The trust rule, and the planted parent `.git` case.** The first version trusted the script's own checkout whether or not the operator had marked it safe. That is wider than main and wider than AC-432-1 ("the global config marks it safe"). The case that matters: a copy of the script sits in a folder with no `.git` of its own, and a `.git` owned by someone else sits in a parent (the `/tmp/.git` pattern). The search above finds that parent. With this rule it is trusted only if the operator listed that exact parent, so an unlisted planted parent is refused, as on main (exit 2). Listing it is the operator's own act, and then the operator has chosen to run git there.
- **Why `SAFE_GIT` covers config execution.** What `safe.directory` guards is git running commands that a repo's own config or hooks name. Every call, trusted or not, starts with `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `core.attributesFile=/dev/null` and `core.ignorecase=false`, and the calls are only `config --file` (the operator's own list, from a scratch folder), `rev-parse`, `ls-tree`, `cat-file`, `merge-base`, `diff --numstat --no-textconv --no-ext-diff`, and an `init` and `check-attr` in a scratch repo. The global and system config and attributes stay dropped and every `GIT_*` variable of the operator's is removed, so the checkout's own config has no way to name a program these calls would start (#225). Trust here only lets git open the repo; it adds no command that runs.
- **Options considered:** (a) trust the script's own checkout always (the first version: simplest, but wider than main and AC-432-1, and a planted parent `.git` is counted); (b) read the list with `git config --global --get-all safe.directory` (a git call that sees the real global config, against the rule that every call runs isolated); (c) read the list from the files with a hand-written parser (round 1: it trusted folders git refuses, such as an entry cleared by `directory = ""` or by an included file, and it fell back to the passwd home when `HOME` is unset); (d) read each file with `git config --file`, as above. (d) wins: it is what AC-432-1 says, it keeps main's refusal for everything the operator did not mark, no call sees the real global config, and git parses its own files, so the script cannot trust what git does not. (b) was first set aside because a test pinned the first call as `rev-parse`; that test was this pull request's own, and now pins only the first call that opens the checkout. `--file` is not a git call that sees the real global config.
