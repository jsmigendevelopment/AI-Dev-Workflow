# Decision 432-1

- **Date:** 2026-11-28
- **Decision:** When `pr-size.mjs` trusts the checkout it runs from (#432, round 1 fix). (1) Every git call keeps `GIT_CONFIG_GLOBAL=/dev/null` and the rest of the isolation. (2) The script finds the folder above its real path that holds `.git` (a folder, or the file of a linked worktree), without git. (3) It reads the operator's own `safe.directory` list straight from the files git would read: `GIT_CONFIG_GLOBAL` if set, else `$XDG_CONFIG_HOME/git/config` (default `~/.config/git/config`) and then `~/.gitconfig`. It does not run git for this, so no call ever sees the real global config. (4) Only when that list holds that folder exactly, or `*`, does every call (the first `rev-parse --show-toplevel` included) add `-c safe.directory=<that folder>`. `*` is read as git reads it, "the operator trusts every folder"; the script still names only the one folder and never passes `*` on. An empty entry clears the entries before it, as in git. (5) Otherwise no call trusts anything, and a checkout owned by another user is refused with git's "dubious ownership" error and exit 2, as on main. (6) The reader accepts only the plain form `git config --add safe.directory <path>` writes: a value with a quote, a backslash, `#` or `;`, an include (`include.path`, `includeIf`) or `[safe] directory = ...` on one line is not read, so the folder is not listed and is refused. That fails closed, and the error git prints names the fix. A trailing slash or a symlinked spelling of the folder is a different string and is not the folder.
- **The trust rule, and the planted parent `.git` case.** The first version trusted the script's own checkout whether or not the operator had marked it safe. That is wider than main and wider than AC-432-1 ("the global config marks it safe"). The case that matters: a copy of the script sits in a folder with no `.git` of its own, and a `.git` owned by someone else sits in a parent (the `/tmp/.git` pattern). The search above finds that parent. With this rule it is trusted only if the operator listed that exact parent, so an unlisted planted parent is refused, as on main (exit 2). Listing it is the operator's own act, and then the operator has chosen to run git there.
- **Why `SAFE_GIT` covers config execution.** What `safe.directory` guards is git running commands that a repo's own config or hooks name. Every call, trusted or not, starts with `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `core.attributesFile=/dev/null` and `core.ignorecase=false`, and the calls are only `rev-parse`, `ls-tree`, `cat-file`, `merge-base`, `diff --numstat --no-textconv --no-ext-diff`, and an `init` and `check-attr` in a scratch repo. The global and system config and attributes stay dropped and every `GIT_*` variable of the operator's is removed, so the checkout's own config has no way to name a program these calls would start (#225). Trust here only lets git open the repo; it adds no command that runs.
- **Options considered:** (a) trust the script's own checkout always (the first version: simplest, but wider than main and AC-432-1, and a planted parent `.git` is counted); (b) read the list with `git config --global --get-all safe.directory` (the same trust, but a git call that sees the real global config, against the rule that every call runs isolated, and the test that pins the first call as `rev-parse`); (c) read the list from the files and trust only a listed folder, as above. (c) wins: it is what AC-432-1 says, it keeps main's refusal for everything the operator did not mark, and no call sees the real global config. The cost: a hand-parsed `safe.directory` reader that only knows the plain form.
