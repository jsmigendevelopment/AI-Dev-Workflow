# Decision 332-2

- **Date:** 2026-11-27
- **Decision:** How `insights.mjs land` and `harvest` handle files and pull requests (#332):
  1. `land` makes its commit in a temp index and pushes it, then stages the landed files in the coordinator's checkout.
  2. `land` keeps one records pull request open. When gh's own login already has an open `chore/insights-` pull request in the repo, `land` adds the missing files to its branch as one more commit (a fast-forward) and prints its number. Any other open one is named for the coordinator to close.
  3. `harvest` names each file by a hash of the record. It skips a record its day folder already holds, and names a different file already on that name, leaving it as it is.
  4. The kit's `.gitattributes` marks `docs/insights/**` `linguist-generated`, so `pr-rules.mjs` leaves records out of the 400-line size rule.
- **Options considered:**
  - For the landed files: leave them untracked, which makes the `git pull --ff-only` after the records pull request merges refuse ("untracked working tree files would be overwritten"); delete them after the push, which loses them if that pull request never merges; or stage them.
  - For an open records pull request: open a new one each sweep, which piles up duplicates; close the old one, delete its branch and open a new one, which spends three more API calls and throws away a gate run; or add to the open one.
  - For the size rule: add the `large-pr` label to every records pull request; mark the records generated; or leave them counted.
- **Why:**
  - Staging keeps both the pull and the records safe.
  - Adding to the open pull request keeps one per repo, needs no force-push, and picks up a pull request a dead session left open. A new commit means a new `--verify` and gate run on the new head.
  - A hash id makes a second `harvest` of the same comments write nothing.
  - Records only grow, and about four merges make a records pull request pass 400 lines, so it would always fail the gate. The trade-off: every pull request's records leave the count, and GitHub folds them in its diff view. `land --verify` caps each record file at 16 KB, so a records pull request can't hide a big change. The marking is in the kit's own `.gitattributes`; an app counts its records until its own `.gitattributes` marks them too.
