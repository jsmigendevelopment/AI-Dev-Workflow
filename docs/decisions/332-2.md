# Decision 332-2

- **Date:** 2026-11-27
- **Decision:** `insights.mjs land` makes its commit in a temp index off `origin/main` and pushes it, then stages the landed files in the coordinator's checkout. `harvest` names each record file by a hash of the record, not a random id, and skips a record its day folder already holds. (#332)
- **Options considered:** leave the landed files untracked, which makes the `git pull --ff-only` after the records pull request merges refuse ("untracked working tree files would be overwritten"); delete them after the push, which loses them if that pull request never merges; stage them, so the pull is clean and an unmerged pull request's files land again next sweep
- **Why:** Staging is the only option that keeps both the pull and the records safe. A hash id makes a second `harvest` of the same comments write nothing, which a random id can't promise.
