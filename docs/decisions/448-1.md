# Decision 448-1

- **Date:** 2026-11-28
- **Decision:** The check for a newer onRails (#448) is **one script, `scripts/latest.mjs`, copied by `sync-skills.mjs` into the `update` skill (`.agents/skills/update/scripts/latest.mjs`) and the CLI (`cli/src/latest.mjs`)**, with no dependency. (1) **Where it runs:** the session-start hook runs the skill's copy as `latest.mjs line --root <project>` only when that file exists, with a 2.5-second kill. `/back` runs `line` and `plan`, `coordinate` runs `plan` on Full, and `doctor` reads the cache only (it never asks npm). (2) **The request:** a plain `fetch` of `<registry>/onrails/latest` with `AbortSignal.timeout(2000)`, no headers or query of ours. A newer version also fetches the CHANGELOG once, under the same 2 seconds, to see whether that release's section has a Breaking heading; the answer is cached with the version, so the CHANGELOG is read once per release. (3) **The cache:** `~/.onrails/latest.json` (`~/.ai-dev-workflow/` while only that one exists), `{ checkedAt, latest, breaking }`. It is fresh for 24 hours (7 days for `weekly`). A failed try is recorded too, keeping the old `latest`, so a hanging registry costs one 2-second wait a day, not one per session. (4) **The line** compares npm's latest with the repo's `kitVersion` and with the Claude Code and Codex plugin versions it finds (the same install records `plugin.mjs` reads). A major version, or a CHANGELOG Breaking section, says so and links the changelog. The global entry skills are not compared: they carry no version record to read. (5) **The switch** is `[updates] check = "daily" | "weekly" | "off"` and `on_full = "pr" | "suggest"` in `docs/profile.toml`, else `~/.onrails/profile.toml`, read the way `notify.mjs` reads `[notify]`; an unknown value means the default. (6) **AC-4:** `latest.mjs plan --prs <file>` takes GitHub's open pull request list and prints `pr`, `wait`, `suggest` or `none`. A branch `chore/<n>-update-onrails` counts as an open update. A major version, a level below Full, or `on_full = "suggest"` is `suggest` (a major also sets `fyi`). An unreadable list exits 2 and never says `pr`. `back` and `coordinate` carry the steps: the loop files the issue "Update onRails to <version>", starts one builder on `chore/<n>-update-onrails`, and treats that open issue like an open pull request. The builder's steps are in the `update` skill. (7) **Tests never reach the network:** `ONRAILS_REGISTRY` and `ONRAILS_CHANGELOG_URL` point the script at a fake registry on 127.0.0.1 (one of them hangs), `ONRAILS_NOW` sets the clock, and HOME is a temp folder. No test runs `npx onrails@latest update`.
- **Options considered:** For (1), put the module only in `cli/src` and have the hook run `npx onrails` (slow, and npx itself reaches the network), or write two files (they drift; this repo already copies shared scripts the way sync-skills does). For (2), one request only, so a Breaking section is never known (cheaper, but the issue asks for it), or read the CHANGELOG on every check. For (3), no record of a failed try (every session start would wait out the timeout while the registry is down). For (4), also compare the global entry skills. For (6), let `/back` and the loop call `gh` inside the script (not testable without GitHub), or look for open update issues in the helper too (a second list to pass in; the skill text covers it).
- **Why:** The hook runs in a project with no CLI, so the one place a project always has is the kit, and the CLI and the plugin get the same bytes from the same copy list. A daily cache with a recorded failure keeps the session start under the 2-second promise whatever the network does. Failing closed on an unreadable pull request list means a broken `gh` can never produce two update pull requests. Doctor stays offline, as `plugin.mjs` already is.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the five acceptance checks and the switch. The picks are: the shared-script placement; fetching the CHANGELOG for the Breaking section and caching it; recording a failed try; the 2.5-second hook kill; naming the plugins in the line; leaving the global entry skills out; the `plan` command's shape and its exit 2 on an unreadable list; the open issue standing in for an open pull request; and doctor showing the cached answer only.
