# Decision 448-1

- **Date:** 2026-11-28
- **Decision:** The check for a newer onRails (#448) is **one script, `scripts/latest.mjs`, copied by `sync-skills.mjs` into the `update` skill (`.agents/skills/update/scripts/latest.mjs`) and the CLI (`cli/src/latest.mjs`)**, with no dependency. (1) **Where it runs:** the session-start hook runs the skill's copy as `latest.mjs line --root <project>` only when that file exists, with a 2.5-second kill. `/back` runs `line`, and `doctor` reads the cache only (it never asks npm). (2) **The request:** a plain `fetch` of `<registry>/onrails/latest` with `AbortSignal.timeout(2000)`, no headers or query of ours. A newer version also fetches the CHANGELOG once, under the same 2 seconds, to see whether that release's section has a Breaking heading; the answer is cached with the version, so the CHANGELOG is read once per release. (3) **The cache:** `~/.onrails/latest.json` (`~/.ai-dev-workflow/` while only that one exists), `{ checkedAt, latest, breaking }`. It is fresh for 24 hours (7 days for `weekly`). A failed try is recorded too, keeping the old `latest`, so a hanging registry costs one 2-second wait a day, not one per session. (4) **The line** compares npm's latest with the repo's `kitVersion` and with the Claude Code and Codex plugin versions it finds (the same install records `plugin.mjs` reads). A major version, or a CHANGELOG Breaking section, says so and links the changelog. The global entry skills are not compared: they carry no version record to read. (5) **The switch** is `[updates] check = "daily" | "weekly" | "off"` in `docs/profile.toml`, else `~/.onrails/profile.toml`, read the way `notify.mjs` reads `[notify]`; an unknown value means `daily`. (6) **Tests never reach the network:** `ONRAILS_REGISTRY` and `ONRAILS_CHANGELOG_URL` point the script at a fake registry on 127.0.0.1 (one of them hangs), `ONRAILS_NOW` sets the clock, and HOME is a temp folder. No test runs `npx onrails@latest update`. (7) **AC-4 is split out to #698** ("Update check on Full: open one update PR"), because the whole of #448 counted 1,087 changed lines against a limit of under 1,000, and the pull request must not need the `size-exception` label. #698 keeps the design that was built and tested in commit `afdd85a` of this branch: `latest.mjs plan --prs <file>` printing `pr`, `wait`, `suggest` or `none`, the `chore/<n>-update-onrails` match on `head.ref` or `headRefName`, an unreadable list exiting 2 and never saying `pr`, the `on_full` switch, an open "Update onRails to <version>" issue counting like an open pull request, and the skill text. The follow-up commit on this branch only removes it.
- **Options considered:** For (1), put the module only in `cli/src` and have the hook run `npx onrails` (slow, and npx itself reaches the network), or write two files (they drift; this repo already copies shared scripts the way sync-skills does). For (2), one request only, so a Breaking section is never known (cheaper, but the issue asks for it), or read the CHANGELOG on every check. For (3), no record of a failed try (every session start would wait out the timeout while the registry is down). For (4), also compare the global entry skills. For (7), drop the `cli/src` copy (doctor would lose its row, which the issue names) or ask for the `size-exception` label (refused by the permission check).
- **Why:** The hook runs in a project with no CLI, so the one place a project always has is the kit, and the CLI and the plugin get the same bytes from the same copy list. A daily cache with a recorded failure keeps the session start under the 2-second promise whatever the network does. Doctor stays offline, as `plugin.mjs` already is. Splitting AC-4 keeps this pull request under the limit and leaves #448 open until #698 lands.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the acceptance checks and the switch. The picks are: the shared-script placement; fetching the CHANGELOG for the Breaking section and caching it; recording a failed try; the 2.5-second hook kill; naming the plugins in the line; leaving the global entry skills out; doctor showing the cached answer only; and splitting AC-4 and the `on_full` switch into #698.
