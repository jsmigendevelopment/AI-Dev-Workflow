# Decision 381-2

- **Date:** 2026-11-27
- **Decision:** How the weekly report reads the records, never estimating a number they don't hold. A run is a `job` record that ended (any outcome but `started` and `pr-opened`). A role comes from routing's table: `build` is the builder; `review-code`, `review-security` and `size-check` are the coordinator; any other job's role is `unknown`. A send-back counts against the last build of the same pull request or issue at or before it, and against model `unknown` when there's none; "Per build" is send-backs over that model's builds this week. Size: no record holds a pull request's size, so the three buckets print `unknown`; the report names each pull request sent back for size (1,000 or more at that head) and gives the send-back rate over all pull requests (#427 records the size). An escalation is a build after a failed review or check (`review-must` or `checks`, routing's "verified failure") whose model or effort differs from the issue's build before it; `unknown` when either side's model or effort is. It fixed it: `no` on a later `review-must` or `checks` send-back, `yes` on a later pass or merge record, else `unknown`. Usage per merged pull request: a `merge` record in the week, summed over the build, review and qa runs on that pull request or its issue up to the merge; each run is its `usage_after` minus its `usage_before` when both are percentages and it didn't go down; any run without both makes the sum `unknown`.
- **Options considered:** for size: count each head with `pr-size.mjs` from local git (its root is the script's own folder, so the CLI copy can't use it, and a head may not be in the checkout); read sizes from GitHub (the report only reads records); `unknown` until a record holds it, as above. For usage: read any number in the text (an estimate, against decision 380-2); a partial sum over the runs with readings (understates); percentages only, and `unknown` on any gap, as above.
- **Why:** The owner's rule: never estimate a number the records don't hold. Every rule above is a count or a difference of what a record says. A gap shows as `unknown`, so the report shows which readings to start recording.
