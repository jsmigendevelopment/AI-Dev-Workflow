# Decision 411-1

- **Date:** 2026-11-28
- **Decision:** The insights record format gets four stricter rules, and every record already on main still passes them. (1) `at` must be exactly `new Date(at).toISOString()`, so the writer's own form (`2026-11-27T14:32:00.000Z`) is the only one: a bracketed comment, an offset, a missing `.000` or a space for `T` is refused. (2) An `int` field must be a safe integer (`Number.isSafeInteger`, 0 or more). A `num` field keeps its fractions, since the local gate writes seconds such as `95.5`, but must stay from 0 to `Number.MAX_SAFE_INTEGER`; a check's `commands` item `seconds` follows the same `num` rule. (3) A `commands` item has only `name`, `result` and `seconds`, an own `__proto__` key counts as an extra key, and `name` is at most `TEXT_CAP` (200) characters. (4) `land`'s `mark` reads the body with `exceptionReason` from `pr-size.mjs`, the size rule's own reader, and when that finds no visible line it puts the size line first in the body, ahead of the old text, which it keeps.
- **Options considered:** For number fields: safe integers for every number field, as the issue's wording reads, which would refuse the gate's fractional seconds and break real check records; safe integers for `int` fields only, which leaves `minutes: 1e21` passing; safe integers for `int` fields and the same upper bound for `num` fields, with fractions kept. For where `land` puts the line: at the end, as before, which an unclosed `<!--` or code fence in the old body hides from the size rule; at the end, then check again and fall back to the top, which is two paths for one job; always at the top, which nothing earlier in the body can hide. For real records: migrate any record a rule refuses, or pick rules none of them breaks.
- **Why:** All 138 records on main at `811eb65` (107 job, 16 review, 13 check, 2 fix-round) pass every new rule in their canonical bytes: each `at` is toISOString's form, every number is a small whole number, and every `commands` item has exactly the three keys with short names. So nothing is migrated. The writer, `line` and the gate all build `at` with `toISOString`, so only a hand-typed record can hold another form. Keeping `num` fractional is the only reading that leaves the gate's records valid. The new test reads every record under `docs/insights/` on each run, so a later rule that refuses a real record fails there. One old test's hand-made record held `at` without `.000`; its fixture now uses the writer's form, and every assertion in it is unchanged.
