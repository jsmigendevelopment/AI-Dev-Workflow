# Decision 710-1

- **Date:** 2026-11-28
- **Decision:** How #710 gives every `pnpm new:*` generator in the TanStack Start pack a `--dry` flag (the first step of #87). `scripts/generate/lib.ts` reads `--dry` once (`DRY`) and the shared steps plan instead of acting: `writeAll` still refuses when a file is already there, then lists what it would create; `edit` still refuses when its anchor is missing, then lists the file it would edit; `tidy` and `migrate` list the tool they would run (ESLint and Prettier, drizzle-kit) and run nothing; `refreshRouteTree` (new, in `routes.ts`) lists `src/routeTree.gen.ts` as an edit instead of regenerating it. `report()` prints the plan (`Would create`, `Would edit`, `Would run`) instead of "Created or changed". Because the refusals are the same code the real run uses, the messages are the same. `positional()` now drops the word after a flag only for a flag that takes a value (`--item`), so `--dry` and `--no-route` can come before or after the words. `scripts/generate/dry.test.ts` runs each generator in a scratch copy with a fake `pnpm` on PATH, compares the file tree (directories and file hashes) before and after a dry run, checks that no tool ran, and checks that the plan is the same set of files a real run creates and edits.
- **Options considered:** (1) A global `DRY` flag read in `lib.ts`, so the five entry scripts barely change. (2) Pass a `dry` argument through every helper and entry script. (3) A plan object that each generator builds and a separate `apply` step that writes it, which also suits the later `--list` and recipes work in #87 but rewrites every generator.
- **Why:** Option 1 is the smallest change that makes the dry run use the real code path, so a refusal can't drift between the two. Option 3 is the better shape for the rest of #87, but it changes what each generator is built from, which the issue puts out of scope ("changing what any generator writes"); #87's later steps can move to it. A dry run lists "would run" lines for the tools instead of running them, and the one file whose name it can't know (drizzle-kit's migration) is named by the command that makes it.
- **Round 1 (review send-back):** `--dry-run` is the kit CLI's own spelling (`onrails update --dry-run`), and before #710 a generator that was given it refused by accident (for example `new:section tasks --dry-run overdue` dropped `overdue` as the flag's value and stopped for a missing word). Once `positional()` skipped every `--flag`, the same typing would have run for real. So `lib.ts` now refuses `--dry-run` and any `--dry=<value>` (and `--dry-run=<value>`) before anything else: one line, `Unknown flag --dry-run. Did you mean --dry?`, exit 1 (the generators' usage exit code), nothing written, no tool run. It is a narrow guard only: refusing every unknown `--flag` is left to the #87 follow-up, because `positional()` still lets an unknown flag shift the words (`--foo bar tasks` takes `bar` as the name; `--item --dry` takes `--dry` as the value).
- **Round 2 (review send-back):** The guard was case-sensitive and narrow, so `--DRY-RUN`, `--Dry` and `--DRY` still wrote. It is now `/^--dry([-_]?runs?)?(=|$)/i`, and only the exact lower-case `--dry` is let through: `--DRY` is read as a typo of `--dry` (safer than quietly accepting it, because the kit's other flags are lower-case), so it is refused with the same `Did you mean --dry?` line, as are `--dry-run`, `--dryrun`, `--dry_run`, `--dry-runs` and `--dry=<value>`, in any case. `-n` and unknown flags in general stay with follow-up #732. `pnpm routes:generate --dry` took `--dry` through the shared `lib.ts` and then really rewrote `src/routeTree.gen.ts`. Two options: refuse the flag there, or make `routes.ts` honour it. It now honours it, which is the smaller change (the entry runs `refreshRouteTree()`, which already plans under `DRY`, then `report()`): it prints `Would edit: src/routeTree.gen.ts` and writes nothing, the same plan the other generators print for that file. Tests: AC-710-6 gains the new spellings before and after the words on every generator (tree byte-identical, no tool run), and a `routes:generate --dry` test in a scratch app that has a route the tree does not list yet.
- **Round 3 (review send-back, follow-up #732 done here):** Now that `positional()` no longer drops the word after any flag, an unknown flag placed before the words really wrote, where main refused it by accident (it dropped the next word). The review found 132 such first-position cases, among them `--dry-mode`, `--dry-`, `--no-dry`, `--plan` and `--preview`. The round 1 and 2 guard named the `--dry-run` family, so it could never be complete. Three options: (1) widen the pattern to every `--dry...` spelling and leave the rest to #732; (2) refuse every `--flag` the generator doesn't take; (3) make `positional()` strict, so an unknown flag shifts nothing, and still let the flag run. Option 2 is the pick, and it closes #732: it is the only one where no spelling can turn a planned run into a real one, and it restores what main caught by accident. `lib.ts` has one function, `refuseUnknownFlags(known)`, which each entry script calls as its first statement (`routes.ts` in its own entry block): the first `--flag` not in the list stops the run with one line, exit 1, nothing written, no tool run. The known flags are exactly `--dry` for every generator and `routes:generate`, plus `--item <singular>` and `--no-route` for `new:module`. Any flag starting `--dry` in any case, other than the exact `--dry`, keeps the line `Unknown flag <flag>. Did you mean --dry?`; any other flag gets `Unknown flag <flag>. Known flags: <list>.`. A flag a generator doesn't take is refused too, so `new:component --no-route` and `--item x` on any generator but `new:module` are usage errors wherever they stand. This differs from main, which refused them only by accident and only when the flag came first (`new:component --no-route notes foo` dropped `notes` as the flag's value and stopped for a missing word); after the words (`new:component notes foo --no-route`, `new:section notes overdue --item x`) main ignored the flag and wrote. The change is intended under #732 AC-1. `--item=<value>` is an unknown flag and refused: the value is always the next word (`--item <value>`), as before. A lone `--` is not a flag and is let through, as before. Real runs with only known flags are unchanged apart from the `positional()` fix. The check runs from the entry scripts rather than on import of `lib.ts`, so a test or tool that imports `lib.ts` (vitest, with its own flags) is never stopped. Tests: AC-710-7 (`unknown-flags.test.ts`) refuses `--dry-mode`, `--dry-`, `--dry-runn`, `--dry-run-only`, `--dry:run`, `--dry `, `--no-dry`, `--plan`, `--preview`, `--check`, `--dr`, `--item=x`, `---x` and `--foo bar` before and after the words on all six generators and `routes:generate`, and `--no-route` on every generator but `new:module`: each leaves the tree byte-identical and runs no tool. The shared scratch-app harness moved to `harness.ts` so `dry.test.ts` stays under 300 lines; no assertion changed.
- **Round 4 (review send-back):** Two gaps in the round 3 guard. (1) #732 AC-2 was not met: `new:module <name> --item` with nothing after it wrote the module with the default singular, because `option()` returned `undefined`, and `--item --dry` was refused only by accident, in `kebab()`. `refuseUnknownFlags` now also refuses a value flag (`--item <singular>`) that has no word after it or a word that starts with a dash, anywhere in the arguments: `--item needs a word after it, like --item <singular>.`, exit 1, nothing written, no tool run. (2) Only a `--flag` was refused, so a word that merely starts with another dash still wrote when it came after the words: `—dry` (the autocorrected em dash, the likeliest real typo), `-dry`, `-n`, `-dry-run`. Options: (a) refuse any word that starts with a dash-like character that is not a known flag; (b) refuse more words than the generator takes; (c) leave it, since main wrote too. Option (a) is the pick: it needs no per-generator word count and it catches every spelling of a dash. The test is `^[\s\p{Z}\p{Cf}]*` followed by the end of the word or by a Unicode dash (`\p{Pd}`, U+2212 minus sign, U+02D7, U+2043, U+30FC), so a space or a zero-width character in front does not hide it, and an empty or zero-width-only word is refused too. The line names the word (spaces and zero-width characters shown as `\uXXXX`): `Unknown flag —dry. Did you mean --dry?` when it reads as a mistyped `--dry`, else `Unknown flag -n. Known flags: <list>.`. The first bad argument in the arguments wins, before or after the words. A lone `--` stays allowed as the usual end-of-options mark and is ignored: `new:module -- tasks` now makes `tasks` where main refused it, but only by accident (`positional()` dropped the word after `--`); that change is intended, and a word after `--` that starts with a dash is still refused. A word with no dash in front is a name, and a word beyond the ones a generator takes is still ignored, as on main; that is the limit of the guard, and the README, the skill line and the changelog say exactly that, not that a mistyped dry run never writes. Tests: AC-710-7 in `unknown-flags.test.ts` gains 23 dash-like words (single dashes, Unicode dashes, a space or zero-width character in front, empty and zero-width-only words) before and after the words on all six generators and `routes:generate`, and 14 `--item` rows (last, before and after the words, with `--dry`, `--no-route`, `--foo`, `--`, a dash word and an empty word after it), plus `--item` on the other generators and `new:module -- <name>`; each leaves the tree byte-identical and runs no tool. The stale title in `dry.test.ts` (`refuses before any other check, and only the --dry look-alikes`) now says what the test checks; no assertion changed.
- **Originator:** AI pick, not reviewed (Full automation). The picks are: the global flag; `--dry` as the only spelling that plans, with the look-alikes `--dry-run` and `--dry=<value>` refused by name; the three headings in the output; listing the route tree as an edit; the scratch-copy test with a fake `pnpm`. Round 2 adds: `--DRY` and the other capitals refused as typos (not accepted); the near-misses `--dryrun`, `--dry_run`, `--dry-runs` refused; `routes:generate --dry` honoured (plan only) rather than refused. Round 3 adds: every unknown `--flag` refused (option 2), with the known flags per generator listed in the message; `--item=<value>` is not accepted. Round 4 adds: `--item` with no word, or a dash word, after it is refused; any word that starts with a dash (option a), an empty word and a zero-width-only word are refused; a lone `--` is ignored (so `new:module -- tasks` works); the guard's limit (a plain extra word is ignored) is documented as it is.
