# Decision 170-1

- **Date:** 2026-11-27
- **Decision:** How #170 fixes the deploy-script follow-ups. A `.takeover` file older than one hour (longer than any deploy takes) is named as left by a crashed run, with its age in hours or days and the file to delete. Each release says which site it is for (`site: 'test' | 'production'`); a failed first deploy on test says the test Worker ships launched instead of the Coming soon advice, and a first deploy's "couldn't tell" check no longer asks for the `main <sha>` message. A deployment with no id reads as "couldn't tell", never as the same deployment. The lock tests move from `follow-ups.test.ts` to `one-at-a-time.test.ts`, and the new #170 tests go in `follow-ups-2.test.ts`.
- **Options considered:** For the old takeover file: a fixed one-hour limit (picked), a limit read from config, or the file's mtime instead of the time it holds (needs a new dep). For the site: a `site` field (picked), reading it from the message prefix, or the `LAUNCHED` var.
- **Why:** The takeover file already holds its start time; one hour is far over a deploy's length. An explicit field is clearer than parsing a message.
