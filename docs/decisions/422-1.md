# Decision 422-1

- **Date:** 2026-11-28
- **Decision:** What `insights.mjs land` (and `land --verify`) keep and drop in the environment of every git call it makes (#422, changed by #450). (1) It drops the variables that move the repository: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_NAMESPACE`, `GIT_CEILING_DIRECTORIES` and `GIT_COMMON_DIR`, and `GIT_CONFIG_PARAMETERS`, which is what `git -c` hands down. (2) It keeps `GIT_CONFIG_COUNT` with its `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>`, so a `url.<x>.insteadOf` rewrite an environment sets git up with still reaches the fetch and the push: an SSH-style origin (`git@github.com:...`) would otherwise fail with `cannot run ssh`. It also keeps `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_NOSYSTEM`, `HOME`, tokens and transport variables, because the push's login lives there. (3) It sets `GIT_TERMINAL_PROMPT=0`, so a missing login fails at once. (4) It passes no `-c` flags and sets no `HOME`, so the repository's own config and hooks apply, unlike carry. (5) The fetches pass `--no-tags` and the two pushes pass `--no-follow-tags`, so a `push.followTags=true`, a `remote.<name>.tagOpt` or a tag on the remote (even one named `origin/main`) can't send a local tag or write a `refs/tags/*` ref. (6) Main is read as `refs/remotes/origin/main`, fetched with an explicit refspec, never by the short name `origin/main` (#422, as before). (7) `gitRoot()` in `insights.mjs` finds the checkout with the same env (`checkoutAt()` in `insights-land.mjs`), so `GIT_DIR` and `GIT_WORK_TREE` can't move land, or `write`, `harvest` or `has-records`, to another clone: the checkout is the one that holds `CLAUDE_PROJECT_DIR` or the current folder. Land differs from carry's fetch (decision 333-2): carry's fetch also drops `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_NOSYSTEM`, and passes `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c core.attributesFile=/dev/null -c safe.directory=<checkout>`, because its other calls merge and must use main's attributes and no hook. Land stages and pushes only files and runs no merge.
- **Options considered:** For the config in the environment: drop all of `GIT_CONFIG_*`, as carry's fetch did and #422 first copied, which loses an `insteadOf` rewrite and breaks a push from an SSH-style origin; drop only `GIT_CONFIG_PARAMETERS`, picked; keep all of it, which lets a `-c` a hook handed down change the push. For tags: pass the flags on the command, picked; unset `push.followTags` and `remote.origin.tagOpt` in the checkout's config, which edits a person's config; fetch with an explicit `refs/tags/` exclusion, which is not a git feature. For the checkout: find it with carry's `checkoutOf()`, which drops the global config, so a `safe.directory` kept there is lost and a dev container's mounted folder fails on ownership; find it with land's own env, picked, which keeps the global config; say in a comment that the guarantee starts once the checkout is found, which leaves `GIT_DIR` able to move land.
- **Why:** A hook's exported `GIT_DIR` and `GIT_INDEX_FILE` must never point land's reads, commit and staging at another repository or index (#422). A `url.<x>.insteadOf` set through `GIT_CONFIG_COUNT` is how an environment points git at a proxy or a token URL, and dropping it left land and carry unable to reach the remote there (#450). A `git -c` value handed down in `GIT_CONFIG_PARAMETERS` is not the environment's own setup, so it stays dropped. Land pushes only a commit it built from files that `land --verify` can check, so a tag that rode along would be an unchecked push. Finding the checkout without `GIT_DIR` is the last step that was still honouring it.
