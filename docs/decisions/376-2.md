# Decision 376-2

- **Date:** 2026-11-27
- **Decision:** `pyramid/scripts/check-plan.mjs` reads the Lines cell with `readSize` and `checkSizes` from `issues/scripts/check-issue-size.mjs`, imported from that file by a relative path. It passes the cell to them as a `Size:` line, so a cell passes or fails exactly as the issue's line would. It words its own message for an estimate of 1,000 or more ("cut it again before the issues are written") and for a split ("cut it into steps in this table"), and prefixes the issues check's message for every other gap. (#376)
- **Options considered:** import it from its file; a synced copy through `COPIES` in `scripts/sync-skills.mjs`, as `command-for.mjs` does (#238); a hand-written copy of the reader
- **Why:** One reader means the step and its issue can never disagree on what an estimate says. Both skills ship together in every kit copy (`.agents/skills`, `.claude/skills` and the CLI's core files), so the path always resolves. This is the first skill script that imports another skill's script; the comment in `sync-skills.mjs` that skill scripts can't import each other predates it. If a skill ever ships alone, this import moves to a `COPIES` entry.
