# Decision 390-1

- **Date:** 2026-11-28
- **Decision:** How #390 makes the live thread only talk. (1) A new standing rule, 17 in `AGENTS.md`, states it once for every skill: the live thread answers, records decisions, writes a note or files an issue, and hands the rest to a background sub-agent or sub-thread; quick reads are fine; a long read goes down with a "when it reports back"; the person is answered right away. Writing a decision or a note stays in the live thread, as #280's eval already allows writes under `docs/`. A tool with no background sub-agent does the work in place and says once it can't react, as `coordinate` already says for the loop. (2) Each live-thread skill gets one or two lines where it did work itself: `coordinate`'s "Where this runs" (a job the person names goes to the loop or a one-job background sub-agent; answer first), `back` (the retro goes to a background sub-agent), `afk` (a missing "Check main" goes down, no wait), `automation` (a background sub-agent opens the pull request) and `ask`'s Handoffs (the live thread never waits for a receipt). (3) The eval, `live-thread-only-talks`, is opt-in, since the default run is at the 40-run cap. To send the second message, the runner gets per-scenario follow-ups: `export const followUps` switches that scenario to `--input-format stream-json`, sends each follow-up as soon as a turn's `result` arrives, marks it in the transcript with an `onrails_follow_up` event, and ends the run 10 s after the last reply, so a sub-agent still working doesn't turn a finished run into a timeout. Checks split the live thread's own calls by turn at those markers.
- **Options considered:** For the second message: a single prompt that holds both messages (not two turns, so it can't show the first turn ended); text tests alone for "answers within one turn" (no behaviour). For the rule: a sub-bullet of rule 15 (the cleanup rule, a different subject); a line in each skill only (no single place for skills the issue doesn't name, like a person-started `build`).
- **Why:** A standing rule reaches every skill the live thread runs. Stream-json input is how the Agent SDK drives Claude Code turn by turn, and it keeps every other scenario on plain text input. Not verified against a real `claude` here (never run in the loop): the real run, `npm run evals -- --scenario live-thread-only-talks`, is the person's call.
- **Originator:** AI pick, not reviewed (Full automation: the owner, 2026-11-26). The rule's content is the owner's words in #390 (2026-11-27).
