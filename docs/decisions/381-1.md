# Decision 381-1

- **Date:** 2026-11-27
- **Decision:** The weekly report is its own read-only script, `scripts/insights-week.mjs`, copied by `sync-skills.mjs` to the `coordinate` skill and to `cli/src` (`npx onrails insights --week [<yyyy-Www>] [dir]`). It prints Markdown and writes nothing. The week is an ISO week in UTC, last full week by default. The loop runs it at the end of every sweep with `--skip <week>`, the week on the `Weekly report:` line of `docs/state.md` (or `none`): it prints nothing until a new week is due, then the coordinator sends the report as one ℹ️ FYI and sets that line to the week it printed. The research report the issue names for the format (section 4) isn't in this repo, so the sections follow the issue's four bullets, adapted to what the records hold.
- **Options considered:** post it as one comment on a pinned "Weekly report" issue (writes to GitHub, and the brief for this build says the report never does); write it to `docs/insights/weekly/<yyyy-ww>.md` (`land` takes only record files under `docs/insights/<yyyy-mm-dd>/`, so it would need its own landing path); print it, and let the loop send it as an FYI, as above.
- **Why:** The report is a pure function of the records and the week, so any past week prints again with `--week`, and nothing needs storing. An FYI shows on the board and at `/back` and never interrupts. `--skip` keeps the ISO week sums in the script, not in an agent's head.
