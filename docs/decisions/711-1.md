- **Date:** 2026-11-28
- **Decision:** How #711 maps the skills for the core and apps split (#86). `docs/skills-map.md` gives each of the 31 folders in `.agents/skills/` one row: `core` (6), `app-only` (18) or `mixed` (7), with a one-line reason. A `mixed` reason starts its second part with `Moves to apps:` and names it. `cli/test/skills-map.test.mjs` fails when a skill folder has no row, a row names no folder, a skill has two rows, a label is not exactly one of the three, a reason is empty, or a `mixed` reason names nothing. No file moves, nothing is renamed, and `plugin.json` and the sync scripts are untouched. No file moves until a later issue, after this map is merged and the short slash prefix question is answered. The row for this map is this file, not a row in `docs/decisions.md`: that table is frozen at row 118 (decision 165-1), and a test fails on a new row.
- **Options considered:** (1) Take #86's two lists as given: all of `grill`, `pyramid`, `issues`, `ask` and `routing` core. (2) Label from each skill's own text, so a skill that names app steps is `mixed`. (3) Label only the four skills the issue left open. For the count of `mixed`: `coordinate` could be `mixed` too (its claim, priority and overlap rules are method, its merge and smoke test are app), but #86 lists it for apps and moving the whole loop is the safer first cut.
- **Why:** The issue says to judge "any skill that mixes both from its text", and #86 says mixed skills get their app parts moved. Option 2 does that. `grill` has product topics that lead into wireframes, `pyramid` has slice 0 with the stack pack and test deploy, `issues` has the Recipes line and `pnpm pr:rules`, `routing` has job rows for wireframes and `qa`, and `ask` ships `preflight`, which probes installs, ports and browsers. Calling those `core` would make a core-only install carry app steps. `idea` and `join` chain core steps with name, wireframes and stack steps. `update` is `core` because it updates every onRails part for any pack. `test-by-hand-as-the-user` is `app-only` because it clicks through an app in a browser. On Full, "agreed" means this pull request merged; the owner can change any label in a later pull request, and the test keeps the table honest.

The picks are: `update` core; `test-by-hand-as-the-user` app-only; `idea` and `join` mixed; moving `grill`, `pyramid`, `issues`, `routing` and `ask` from #86's core list to `mixed`; keeping `coordinate` app-only; the `Moves to apps:` wording; and recording the decision as this file.
