# Decision 400-1

- **Date:** 2026-11-27
- **Decision:** `check-issue-size.mjs` closes five gaps from the round 4 review of #391. (1) An exception whose reason names an issue (`#12`), or says it is split, fails as both an exception and a split. "Says it is split" means "split into", "splitting into", "split in two", "broken into", "already split", "was split", "Split.", "child issues" or "children 12 and 13". It passes only when a "no", "not", "never", "can't", "cannot", "won't", "don't", "unable", "without", "hard" or "too" sits in the same clause, right before the split ("can't be split into parts", "too risky to split up"). A negation in an earlier clause doesn't count ("too big, split into child issues" fails). (2) A later part of the value fails as a second estimate when one word or a `+` sits between its number and "lines" or "loc" ("+600 test lines", "600+ lines"), or when "test" or "tests" sits next to a number, also after a bracket or one qualifier ("tests: 600", "tests: about 400", "tests (600)", "600 in tests"). A path ("test/12-x.ts", "x.test.mjs") or an ID ("AC-12-1 tests") isn't one. (3) A reason fails as a placeholder when it is "nope", "nothing", "later", "TBC", "no reason", "no reason yet", "no reason given", "not needed", "not applicable", "no need", "to be decided", "to be confirmed" or "unknown yet", or starts with "none", "tbd", "tbc", "todo" or "n/a" ("none yet", "TBD later"), except "none of ...". (4) The guard for a size the reader skips needs the unit after the number, with a `+` and any one word allowed between ("1500+ lines", "1,500 code lines"), but not a unit like px, em, KB or MB. So "font size: 16px, line-height: 24px" passes. "about 300 lines changed" reads as 300. (5) On stdin, a split parent with no `labels` exits 2, and the exit 2 message names `labels`. (#400, review round 1 on #429)
- **Options considered:** for (1), fail any reason with "split" in it (refuses "no way to split a rename", a real reason the tests keep), only a reason that names an issue (misses "split into child issues"), or the split phrases above unless a negation comes first, looked for in the whole reason before it (round 0, which passed "too big, split into child issues") or only in its clause. For (2), one word before the unit, or any words (refuses file lists). For (3), the exact phrases only, or a starting word too. For (4), a short list of words allowed between the number and the unit (round 0, which hid "1,500 code lines" and "1500+ lines" that main caught), or any one word and a `+`, minus size units. For (5), exit 2 for any issue with no labels (breaks older input that splits nothing), or only for a split parent.
- **Why:** Each choice fails the misuse the reviews found and keeps every real wording the tests and this repo's own issues use. Round 0's claim that nothing got looser was wrong: its guard hid six shapes main caught. After round 1, main's script and this one ran over the same 81 shapes (the review's, round 0's and these rules' own): none that main fails now passes, and 41 that main passed now fail. The only wordings that now pass where main failed are design notes with a size unit, such as "font size: 16px line-height". All 30 real `Size:` issues in this repo read the same or better (#400's own body no longer trips the guard). The plan check imports this reader, so a step cell gets the same stricter rules.
