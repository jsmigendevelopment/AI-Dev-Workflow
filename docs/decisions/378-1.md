# Decision 378-1

- **Date:** 2026-11-27
- **Decision:** `coordinate` checks the size first, in step 6.1.1 right after `own-branch.mjs` exits 0, before the clone, the checks and any review. Exit 1 sends the pull request to a fresh builder on the same branch with the split brief, and it isn't a review round, so it doesn't count toward the review cap. In local mode, `pr-size.mjs` gets a `--head <ref>` option, so the loop counts a branch from its checkout of main with main's own copy of the script, never the head's copy and never by switching its checkout.
- **Options considered:** rely on `pr-rules.mjs` in 6.1.3, after the install and `check` (a full gate run spent on a pull request that goes back anyway); a new step between 6.1 and 6.2 (renumbers steps other issues and tests cite); a bullet under 6.1.1, as above. For local mode: switch the checkout to the branch (then the branch's own copy of the script runs), run it in a worktree of the head (`pr-size.mjs` counts the checkout it sits in, so main's copy still counts main), or a `--head` option, as above.
- **Why:** #378 asks for the size check before review and a split brief instead of a review. Counting first costs one API read and spares the clone, install and checks. A size send-back is the cut being too big, not a finding about the code, so counting it toward the cap would push a split issue to the cap early. `pr-rules.mjs` keeps its size rule in 6.1.3, so a head that grew after the count still fails.
