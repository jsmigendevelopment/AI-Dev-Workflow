# Decision 333-2

- **Date:** 2026-11-27
- **Decision:** When the coordinator merges main into a branch whose base is behind (`coordinate` step 7), the merge commit goes to a fresh `pr-review`, conflict fix or not. Before, a review of the old head stood when the merge brought no conflict fix. (#333)
- **Options considered:** keep the old rule and let `has-records` accept a review of an older head when the only change since is main's merge, which needs git logic in the check and goes against AC-333-2 (a review of an older sha is missing); have the coordinator copy the old review record onto the new sha, which is writing a record by hand, the thing #281 item 6 exists to stop; a fresh review of the merge commit
- **Why:** The merge check needs a review record for the exact head it merges, written by the reviewer's script. A fresh review is the only way to get one without a hand-written record. It costs one review per base update, and it also reviews what main's merge brought in.
- **Originator:** AI pick, not reviewed
