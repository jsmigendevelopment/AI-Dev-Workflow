# Decision 490-1

- **Date:** 2026-11-28
- **Decision:** Where `insights.mjs carry` proves a merge (#490). (1) `carry()` in `insights-carry.mjs` finds its checkout with the existing `checkoutOf(dirname(fileURLToPath(import.meta.url)))`: an isolated `git rev-parse --show-toplevel` in the folder the script sits in, so it is main's checkout, where `coordinate` step 7 runs it. `CLAUDE_PROJECT_DIR`, `GIT_DIR` and the folder the command was started in no longer pick the checkout. The fetch of main, the redone merge and the records all use that checkout. (2) `carry` takes only the arguments now, `carry(args)`, and `insights.mjs` calls `carry(rest)`. The usage check runs before git is asked for the checkout, so a wrong command line still exits 2 with the usage line. (3) Where git can't name a checkout in the script's folder (not in a repo, or git refuses the folder's owner), `carry` exits 2 with git's message, as any other git error. (4) Nothing else changes: `has-records`, `harvest`, `land` and `write` keep taking their checkout from `CLAUDE_PROJECT_DIR` or the current folder, and the records format and `agent-files.mjs` are untouched, as the issue's fence says.
- **Options considered:** Pass the checkout in from `insights.mjs` (`carry(checkoutOf(...), rest)`): keeps the old signature, but spreads the rule over two files and lets another caller pass a different root. Keep `gitRoot(2)` and compare it with the script's checkout, refusing on a mismatch: more code, and a refusal for a harmless start from another folder. Use `import.meta.dirname`: shorter, but the gate spells it `dirname(fileURLToPath(import.meta.url))`, and one spelling is easier to search for.
- **Why:** The proof of a clean merge must read main's merge attributes, never a pull request clone's. One function (`checkoutOf`) now says where that checkout is, for the gate (#478) and for `carry`, so the two can't drift. The script's own location is the one thing the caller can't change through the environment or the working folder.
- **Originator:** AI pick, not reviewed (Full automation: the owner, 2026-11-26). The ask is the issue's own words: "Have `carry` find its checkout from the script's own location, with an isolated `git rev-parse --show-toplevel`, the same way #478 does for the gate."
