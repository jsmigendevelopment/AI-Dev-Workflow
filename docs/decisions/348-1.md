# Decision 348-1

- **Date:** 2026-11-28
- **Decision:** The Go backend's app conventions are one new guide, `guide/app-conventions-go.md`, that mirrors the server-side sections of `guide/app-conventions.md` and keeps their numbers (5, 8, 10 to 16 and 18). (1) Errors use the web pack's envelope, `{"ok": false, "error": {"code", "message", "requestId"}}`, with the web pack's codes and a request ID from the first middleware. The pack overrides huma's RFC 9457 default once, in its `NewError` hook, so the TypeScript client parses one shape (the dossier's c48). (2) Shared Go code is named under `internal/platform/<name>/` (`apperror`, `money`, `clock`, `logger`, `events`, `authz`, `config`). The architecture template's Go version (#355) may rename it. (3) JSON field names are camelCase (`amountMinor`, `requestId`), like the web pack's types. Log fields stay snake_case, as in the web pack's logger. (4) Logs: `log/slog`'s JSON handler, with `ReplaceAttr` giving `ts`, `event` and a lowercase `level`; a `Secret` type that logs as `[redacted]`. (5) Events: each event is a struct type in one registry file, and an interface with an unexported method lets only those types reach `events.Track`. (6) Time: `time.Time` in UTC, `timestamptz`, a small `Date` type for calendar dates, and an injected `Clock`. (7) Money: `Money{AmountMinor int64, Currency string}`, half-even rounding, remainders allocated, amounts kept under 2^53 for JavaScript. (8) Database: forward-only goose files with no `Down` section, `created_at` and `updated_at` set in Go from the injected clock, ids made in Go. (9) Env: `config.Load(get func(string) string)`, so only `main` calls `os.Getenv`, and every variable set on every deploy because a Cloud Run revision keeps the one before it. (10) Access: `authz.Checker` with `Check(ctx, user, action, object) (bool, error)`, and an error means deny. (11) The guide names the tools decisions 340-1 and 342-1 picked and no version.
- **Options considered:** errors: RFC 9457 problem details (huma's default), the web pack's envelope; layout: one file with every convention, a section per rule that keeps the original numbers, new numbers; JSON names: camelCase, snake_case; database timestamps set by SQL `now()`, or in Go from the injected clock; migrations with `Down` sections, without; shared code: one `internal/platform/` tree, a package per module, `pkg/`; the Go guide copied into `build/references`, linked only from the guide index and the original
- **Why:** The TypeScript client then has one error parser for both packs, which is what the dossier found a single override buys. Keeping the numbers makes "rule 13" mean the same in both guides, and a review can compare them side by side. camelCase follows the web pack's contract types, so the generated client reads naturally. Setting timestamps from the injected clock keeps the database tests deterministic, as rule 11 asks. Goose's `Down` section would let a rollback run on test or production, which the forward-only rule forbids. A fresh Cloud Run revision keeps the previous values, so a variable left unset on one deploy silently stays (the platform dossier). The guide is not copied into `build/references`: the issue lists four files and a skill row is a separate change. Confidence: medium. The layout and the JSON names are the most likely to change when the Go pack's architecture file lands (#355).
