# Decision 386-1

- **Date:** 2026-11-28
- **Decision:** `mark-check.mjs` strips `/[\p{Cc}\p{Cf}\p{Zl}\p{Zp}]/u` from the fence's first line and refuses the same set in a command name and the `failed` step. The fence is cut one code point at a time and stops before a character that would take it past 200 UTF-16 units, so it holds at most 200 code points and never half an emoji. This widens decision 331-3's set (C0, DEL, C1). (#386)
- **Options considered:** cut at exactly 200 code points; cut at 200 code points and also stop at 200 UTF-16 units; drop a trailing lone surrogate after the old cut.
- **Why:** `validate` in `insights-record.mjs` counts a text field's length in UTF-16 units and refuses one over 200. A fence cut at exactly 200 code points can hold up to 400 units, and an emoji-heavy fence would then fail validation and exit 2, which loses the record for a note that only helps reading. Stopping at 200 units keeps the issue's rule (whole code points) and the format's rule (at most 200). Text with no character past U+FFFF is cut exactly as before. The wider set also strips zero width joiners and non-joiners, so a joined emoji sequence in a fence reads as its parts, and a command name with one is refused like any other format character.
