# Decision 472-1

- **Date:** 2026-11-28
- **Decision:** The eval half of #129's AC-3 is one opt-in scenario, `unknown-model`, that checks records and commands, not wording. (1) **The setup:** a built issue waiting for review, a profile whose `[routing]` table names a made-up model and effort (`Claude Zephyr 9`, `extra-high`), and a prompt that says the session shows no model or effort. A made-up name means no real session can be running on it, so a match is always a copy from the table. (2) **Four checks:** the writer ran (`insights.mjs line job` or `write job`) and worked; every record of the run that has a model says `unknown`; every record whose model or effort is `unknown` has a `model_from`; no record or writer command has the table's model or effort. (3) **Where a record is found:** the writer's printed line in a tool result, the issue file, or a file in `docs/insights/`, so both `line` and local mode's `write` pass. (4) **The routing model in `model_from` is allowed:** it says where the reviewer looked ("the routing table says X, but this session shows none"), which is the field's job. Only `model` and `effort` are checked against the table. (5) **Opt-in:** the default run stays at the 40-run cap.
- **Options considered:** Run the reviewer through a fake `gh` and a pull request (more moving parts, and the writer's `line` output is the same). Check only the command line's `model=` argument (misses a record typed by hand, and a `write` file). Make the writer refuse an `unknown` model with no `model_from` (changes the record format, which the issue puts out of scope).
- **Why:** The unit tests of #129 prove the writer takes `model_from`. They don't prove an agent writes `unknown` when its session shows nothing, instead of the model the table asked for. That needs an agent, so it is an eval, and the person runs it by hand.
- **Originator:** AI pick, not reviewed (Full automation). The made-up model, the effort check and allowing the routing model inside `model_from` are the builder's picks.
