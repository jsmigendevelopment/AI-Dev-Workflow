# Decision 540-1

- **Date:** 2026-11-28
- **Decision:** Each web-pack add-on says in its `ADDON.md` table, in a row "With a Go backend", whether it fits an app whose backend is Go (#540). `analytics` and `sentry` start with "fits"; `stripe`, `jobs`, `r2-uploads`, `email-resend` and `database-supabase` start with "TypeScript backend only" and name the Go service as the place for the need. `stacks/tanstack-start-addons/README.md` repeats the seven values in one table, word for word, and the `saas`, `marketplace` and `api-service` presets' add-on lines carry "(a TypeScript backend on Workers; with a Go backend the server-side ones move into the Go service ...)". Words only: no refusal in `npx onrails add`, no add-on code change. `cli/test/addon-go-backend.test.mjs` reads the add-on folder, so a new add-on without the row fails it.
- **Options considered:** a refusal or warning in `npx onrails add` (out of scope in the issue); a `Go: yes/no` column in the README table only (the issue wants each `ADDON.md` to carry it, since an agent reads that file); a separate `go.md` per add-on.
- **Why:** The owner's rule (decision 344-1): a backend not on Workers is Go with a TypeScript web app that calls it. Each add-on was checked against its own `ADDON.md` and files on main.
  - `analytics`: fits. It is one component and a CSP origin in the web app, no server code.
  - `sentry`: fits, but not only "the browser half". It also wraps the web pack's Worker entry (`src/server.ts`, `withSentry`), which the web app keeps in a Go setup while it runs on Workers (the pack's host). It does nothing for the Go service, which needs Sentry's Go SDK. The value says both. (The issue guessed "browser half".)
  - `stripe`: TypeScript backend only. It adds the `billing` module with a D1 table, `billing.functions.ts` and a webhook server route in the Worker.
  - `jobs`: TypeScript backend only. A Cloudflare Queue the Worker produces to and consumes, with a D1 ledger and Cron Triggers.
  - `r2-uploads`: TypeScript backend only. The `files` module with a D1 table, `files.functions.ts` and an R2 binding.
  - `email-resend`: TypeScript backend only. The `EmailSender` port and adapter register in the Worker's `composition.ts`; it has no browser half.
  - `database-supabase`: TypeScript backend only. The issue says it "adapts the notes `drizzle` repository"; the code differs: it replaces four pack files (`src/db/client.ts`, `notes.table.ts`, `notes.repository.test.ts`, `drizzle.config.ts`) and leaves `notes.repository.drizzle.ts` unchanged. The verdict is the same. On a Go backend the database is the Go service's own; the kit's Go conventions (`guide/app-conventions-go.md`) use Postgres through pgx.
  - No add-on exists in `stacks/tanstack-start-addons/` that the issue does not list: the folder holds exactly these seven.
  - The presets' note says "the server-side ones move" because a line also names `Sentry` and `Cloudflare Web Analytics`, which stay; `Clerk` and `Turnstile` on those lines are outside this issue's add-on folder and are not judged here.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the verdicts and the note; the exact wording of each value, the README section name and placement, the `sentry` wording, the presets' sentence and the test's checks are the builder's picks.
