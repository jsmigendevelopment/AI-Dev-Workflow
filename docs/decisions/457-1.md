# Decision 457-1

- **Date:** 2026-11-28
- **Decision:** Voice-to-text support is one small script and one reference. `ask/scripts/voice.mjs` prints `input: typing|voice|both|unset` and the glossary, saves `[me] input` (`voice.mjs input <answer>`) and adds a confirmed mishearing (`voice.mjs add "<heard>" "<meant>"`). `ask/references/voice.md` holds the rule, loaded when `input` is voice or both, and `AGENTS.md` has one pointer line under "Who you're working with". `/idea`, `/join` and `npx onrails profile init` each ask "Do you mostly type, or use voice to text?" once. On Full, `/idea` and `/join` take `both`, save it and say so in the FYI. `profile init` takes `both` on Enter and with `--yes`.
  - **Where it is read:** the personal `~/.onrails/profile.toml` first, then the project's `docs/profile.toml` if a person wrote `[me] input` there by hand (a cloud session has no `~/.onrails/`). `profile copy` and `init` never copy `[me] input` into a project: it is replaced by a comment, as `[research] library` is.
  - **The glossary:** `~/.onrails/glossary.toml`, one `"heard" = "meant"` per line. The kit's own names (onRails, TanStack, shadcn, Clerk, Drizzle, Wrangler) are built into the script and apply with no file, so a new kit name reaches everyone without a migration, and reading writes nothing. A line the person adds beats a built-in one. A repeat confirmation updates the line.
  - **When to confirm:** only in a risky spot (money, deleting, deploying or publishing, or a name or number that picks what gets changed) and only when the reading is a guess. Cheap to undo: go on. A glossary line makes a reading likelier, not certain, so a risky guess still gets the one line. Below Full, one line, then wait. On Full, take the likely reading and record it as an AI pick.
  - **AC-2 is an opt-in eval** (`voice-reading`), because the default run is at its cap of 40. Its project profile carries `input = "voice"`, so a local run never depends on the person's own home folder.
- **Options considered:** for the setting and glossary, a `npx onrails voice` command, a script in the `ask` skill, or instructions to edit the files by hand. For the glossary's seeds, a copy written into the file on first use, or names built into the reader. For `input` in a project, copy it like the rest of the profile, or keep it personal.
- **Why:** a script in the skill runs the same in every tool and in an app with no CLI, and makes AC-1 and AC-4 testable (a temp home, a real file). Built-in seeds avoid a copy that goes stale. Keeping `input` personal follows the issue: one person's way of writing shouldn't apply to everyone who shares the project.
- **Left out:** the issue's comment asks the owner for a few real mishearings from their own app's threads to seed the glossary and the eval. On Full nothing waits, so the seeds are the kit's own names only, with the issue's "10 stack" and "on Rails". "signing" for "assigning" and "sub thread" for "subthread" are not seeded: "signing" is a real word in release work, and both depend on the person. The owner adds them, and more, with `voice.mjs add`.
- **Originator:** AI pick, not reviewed
