# Decision 590-1

- **Date:** 2026-11-28
- **Decision:** The Dependabot Go gate refuses a `go.mod` or `go.sum` under a folder whose name starts with `_` or `.`, at any depth, as it already refuses one under `vendor/` or `testdata/` (#590, follow-up to #581). (1) **One pattern:** the folder rule in `dependabot-go.mjs` is `(?:^|/)(?:vendor|testdata|[_.][^/]*)/`, so `isGoFile` is false for such a path and the shared file-list check in `dependabot-bump.mjs` refuses it, naming the file (exit 1). (2) **Only a folder counts:** the pattern needs a `/` after the name, so a file called `go.mod` is never read as a `.` or `_` name, and `svc/`, `my_vendor/`, `api_v2/` and `a.b/` still pass. (3) **Nothing is loosened:** the `vendor` and `testdata` alternatives and their letter-case rule are unchanged, and the pattern only gains alternatives. (4) **Tests:** `AC-590-1` (the refusals, alone and beside the honest files) and `AC-590-2` (the honest bump and the lookalike folders pass, `vendor/` and `testdata/` stay refused) in `cli/test/dependabot-go.test.mjs`. The `dependencies` skill's Go sentence names the new folders.
- **Options considered:** Name `_vendor` and `.hidden` only (misses every other name Go skips). Match only the first path segment (misses `services/.cache/go.mod`, and the issue says any depth). Refuse any file under a dot folder, not just `go.mod` and `go.sum` (not asked, and the existing file check already refuses every file that isn't a manifest or lockfile).
- **Why:** Go's tools skip a folder whose name starts with `_` or `.`, so a `go.mod` there is a copy or a fixture, never the module being bumped, and the gate decides what merges unreviewed. A match on `.github/go.mod` is refused too, which costs a person a look and nothing more.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the rule. The picks are: one regex alternative for both prefixes; the test cases; and the wording of the skill sentence.
