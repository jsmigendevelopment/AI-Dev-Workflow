# Decision 581-1

- **Date:** 2026-11-28
- **Decision:** Four refusals and a test move close what the review of #578 found in the Go side of the Dependabot gate (#581, follow-up to #531). (1) **A bump of a path on the left of a merge-base `replace` or `exclude` is refused**, named with the path, the two versions and the merge base's line: a `replace` or `exclude` that pins one version is switched on by the new version, and the old version's pin stops applying, with no line changing, and one with no version covers every version. It runs after every other `go.mod` check, so each existing reason is still the one a case gets. (2) **A refusal quotes at most 200 characters of a line** (then `...`), and the module paths and versions it names are cut the same way, so a 2 MB line or a 2 MB version can't fill a GitHub comment. (3) **A new `go.sum` line whose `<module> <version>` or `<module> <version>/go.mod` the merge base has, with another hash, is refused**, naming the line and the merge base's line. Go writes one hash per version, so the line is inert, but it is the shape of a rewritten pin. (4) **A `go.mod` or `go.sum` under a `vendor/` or `testdata/` folder is refused as any other file is** (the file-list check, naming the file), at any depth and in any letter case, as the `dependencies` skill already says. (5) **Decision 531-1's sentence about the checksum database is corrected:** Go compares the downloaded bytes with every `go.sum` line for that version, and asks the checksum database only when a line is missing. `dependabot-go.mjs`'s header said the same wrong thing and says it right now. (6) **The Go cases moved to `cli/test/dependabot-go.test.mjs`**, and the helpers both files use to `cli/test/dependabot-helpers.mjs`, in a commit that changes no test body. `dependabot-bump.test.mjs` is 175 lines. The `dependencies` skill's Go sentence names the new refusals.
- **Options considered:** For (1), refuse only a `replace` or `exclude` that names the version the bump moves from or to (it spares a repo whose `replace` covers every version, but needs the gate to read versions out of every `replace` and `exclude` shape, and a missed shape passes), refuse any bump in a repo that has a `replace` or `exclude` at all (it never lets a bump through for a repo with a local `replace` of an unrelated module), or refuse a bump of any path on the left (the issue's rule). For (2), cut the whole reason, or only the quoted line. For (3), refuse any second hash for a version inside the head too (not asked, and it also only fails a build), or compare with the merge base only. For (4), leave `vendor/` to the file check and read its `go.mod` anyway, or refuse it by name in the Go code; the shared file check names the file already. For (6), import the helpers from `dependabot-bump.test.mjs` (that would run its cases twice), or copy them into the Go file (two copies of the fake `gh` to keep in step).
- **Why:** The gate decides what merges unreviewed, so it fails closed: a bump that can change what builds through a line nobody looked at costs a person's look, and a look costs little. The rule asks nothing of a repo with no `replace` or `exclude`. It spares a bump of a module they don't name, and a `replace` or `exclude` of another module still passes unchanged, as it did. The one existing case this touches is the AC-531-1 case "a replace, exclude and retract the merge base already had": its `replace` and `exclude` named `github.com/acme/lib` and `golang.org/x/text`, which that same case bumps, so (1) refuses it by design. The case now names two paths no bump touches, and still asserts that lines the merge base had pass. No other assertion of the moved Go cases changed. The checksum sentence was checked against Go's behaviour in the #578 review, which ran Go 1.24.7: a wrong second hash for a pinned version makes `go build -mod=readonly` fail with a checksum mismatch, so (3) refuses a shape that could only fail a build.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the rules. The picks are: refusing any bump of a path on the left, versioned or not; running that refusal after the others; the 200-character cap and the `...`; capping the module paths and versions the reasons name; keying the `go.sum` rule on the merge base only; refusing `Vendor/` and `TestData/` in any letter case; the helper file's name and which helpers moved into it; and changing the paths in the one existing case.
