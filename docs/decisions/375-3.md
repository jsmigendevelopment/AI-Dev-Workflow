# Decision 375-3

- **Date:** 2026-11-27
- **Decision:** `check-issue-size.mjs` fails closed. It reads each `Size:` value (any case, also `**Size**:`) at the start of a line or right after a `·`, and counts every one, so two values on one line fail too. Fenced blocks, quote blocks and HTML comments don't count. The value before the first `·` must have one shape: an optional qualifier ("about", "~", "≈", "roughly", "under", "up to" and the like), one number or a range, each with an optional `k`, an optional "changed", then "lines" or "loc". Thousands are grouped by a comma or a space; a decimal needs a `k` ("1.5k"). Anything else with a digit in it fails with "can't read this estimate" and an example. `exception: <reason>` and `split into #a, #b` count only as a whole value, or right after a `·`. A later part of the value can't hold a second estimate: a number followed by "lines" or "loc" there fails with "write one total"; a file list like "split from #1024" or "1200-x.ts" passes. An exception whose reason, without punctuation, is empty or a placeholder (none, n/a, no, nil, null, tbd, todo, unknown, reason, or only dashes and question marks) fails as no reason. A line that mentions a size in lines but holds no value the reader takes (a table cell, `_Size_:`, a full-width colon, "Size -") fails, even next to a read Size line. Fences follow CommonMark: up to 3 spaces of indent, closed by a run at least as long. An estimate written as a limit ("under 1,000 lines") gets the hint "write your estimate, not the limit". (#375, review rounds 1 to 3 on #391)
- **Options considered:** take the largest number anywhere in the estimate; cut the estimate at its first unit word and skip references and paths (round 1, which still read "999 lines + 600 in tests" as 999); one fixed shape that fails everything else; take the largest of two Size values or fail on two
- **Why:** Every format the check tries to guess is a way to read low and pass 1,000 or more. One shape that writers can follow, with every other estimate failing and naming the fix, is the only read that never passes a big issue. Two Size values leave the real estimate unclear, so the check names the issue and asks to keep one.
- **Originator:** AI pick, not reviewed
- **Later:** Decision 400-1 tightens three of these rules: more placeholder reasons fail, a later part with one word before its unit or "test" next to a number is a second estimate, and an exception whose reason names an issue or says it is split fails as both. It also narrows the guard for a size the reader skips, so design notes in px or MB pass.
