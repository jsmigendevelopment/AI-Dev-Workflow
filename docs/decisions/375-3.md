# Decision 375-3

- **Date:** 2026-11-27
- **Decision:** `check-issue-size.mjs` reads a Size line so it never passes an estimate of 1,000 or more. It ignores fenced blocks and HTML comments, and fails an issue with more than one `Size:` line. The estimate ends at the first separator (`·`, `|`, `;`) or the first "lines" or "loc". A number inside a reference or a path (`#1024`, `src/1200-x.ts`) doesn't count. Thousands are split by a comma, a dot, an apostrophe or a space with three digits after it ("1,200", "1.000", "1 200"); any other dot or comma is a decimal ("1.5k", "1,25k"). A `k`, also glued to "loc" or "lines", means thousands. (#375, review round 1 on #391)
- **Options considered:** take the largest estimate when an issue has two Size lines; fail on more than one; count only a number followed by "lines", "loc" or "k"
- **Why:** Two Size lines leave the writer's real estimate unclear, so the check names the issue and asks to keep one. Counting only a number with a unit would pass "1,200 changed lines" as no estimate at all; cutting the estimate at its first unit word and skipping references and paths keeps every number the writer meant and drops the ones in the file list. A wrong read now errs high, never low.
