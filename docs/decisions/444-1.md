# Decision 444-1

- **Date:** 2026-11-28
- **Decision:** On `ci = "local"` (secrets mode `none`), `pnpm connect` names a value's group "every deploy (test and production)" when its production place is only on GitHub but it has a place on this machine. The rule lives in `devName` in `stacks/tanstack-start/scripts/connect/places.ts` and reads the places, not a provider name. Today it matches only Sentry's `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT`, whose one place there is `.env.sentry.local`. Every other provider's labels, and every label on `ci = "actions"`, stay as they were. Where the values are written doesn't change (decision 227-2). The words are the issue's own, so the prompt reads "Paste SENTRY_AUTH_TOKEN for every deploy (test and production) (hidden as you type or paste; Enter alone skips)".
- **Options considered:** a place-based rule in `devName` for mode `none`; a new connect-block field (such as `"deploys": true`) set in `sentry.md`; a rule keyed on the file name `.env.sentry.local`
- **Why:** The place-based rule stays inside the issue's module and needs no change to a provider file, which is outside the fence. On `ci = "local"` a value with no production place of its own can only reach a production deploy through the local file, so the name follows from the places. A file-name rule would break on the next deploy file. The cost: a future value whose only `ci = "local"` place is a file the deploys don't read (such as `.env.local`) while its production place is on GitHub would get this name too; none exists today. The value's shape check is unchanged: the group is not `production`, so a test-key prefix rule still treats it as test. Sentry's three have no shape rule.
