# Decision 532-1

- **Date:** 2026-11-28
- **Decision:** The agent-file guard (`agent-files.mjs`) sees a Go app's check code and tests (#532, split from #347, relates to #279). (1) `CHECK_FILES` gains, at any depth and in any case: golangci-lint's config (`.golangci.yml`, `.golangci.yaml`, `.golangci.toml`, `.golangci.json`); the task runners a `check` script can call (`Makefile`, `GNUmakefile`, `Taskfile.yml`, `Taskfile.yaml`, `Taskfile.dist.yml`, `Taskfile.dist.yaml`, `justfile`, `.justfile`); and the generator config that `check` compares output against (`sqlc.yaml`, `sqlc.yml`, `sqlc.json`, `orval.config.*`). (2) Two names the issue didn't list, taken from the dossier's follow-up 1 ([Go API toolchain](../../research/go-api-toolchain.md)): `.go-arch-lint.yml` and `.go-arch-lint.yaml` (the layer rule), and `tools/*.mod` (the per-tool modfiles that pin golangci-lint, go-arch-lint and the rest, so a version swap there swaps the checker). (3) `TEST_FILE` gains `_test.go` files and `testdata/` folders at any depth, so a deleted or renamed-away Go test, or a deleted golden file, is a deleted test. Adding or editing one stays unprotected, as for `.test.ts`. (4) `automation/references/full.md` lists the same names for the reader, and `cli/test/agent-files.test.mjs` gains the cases. The carry-following logic from #478 and #490 and every existing case are untouched.
- **Options considered:** For the extra names: (a) add the dossier's `.go-arch-lint.yml` and `tools/*.mod` now (chosen); (b) leave them out and file a second issue, which leaves a gap where an agent can loosen the layer rule or swap the linter's version with no review; (c) add every name the dossier mentions, including `tools/*.sum`, `go.work` and `scripts/check-file-size.mjs`. For the contract tool: orval (the dossier's pick for the TypeScript client) now; huma, the Go side, is configured in code and has no file. For `testdata/`: a folder name only, not a file pattern.
- **Why:** The guard is stricter and nothing else changes, so each added name only costs a review when it is edited. (a) closes the gaps the dossier measured (c22) in the same change that closes the rest. `tools/*.sum` is left out: it holds hashes, and a change to it without a change to its `.mod` can't swap a checker. `scripts/check-file-size.mjs` is already check code (`check-*` under `scripts/`). `go.mod` and `go.sum` are dependencies, which the guard leaves alone for `package.json` too (decision 220-1). `testdata/` is the Go tool's own name for fixtures; `pr-size.mjs` already counts it as fixtures, which is a different question (out of scope).
- **Originator:** AI pick, not reviewed (Full automation: the owner, 2026-11-26). The ask is the issue's own words: "Make the agent-file guard see a Go app's check code and tests, so a builder can't loosen lint or delete a test unseen." The extra names in (2) are the AI pick.
