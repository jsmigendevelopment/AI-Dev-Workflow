# Decision 342-1

- **Date:** 2026-11-28
- **Decision:** The Go pack (#279) builds its toolchain on these picks from the dossier [Go API toolchain](../../research/go-api-toolchain.md). (1) Lint and the module boundary: golangci-lint 2.15.0 (its depguard bans `net/http`, huma and SDK imports in services; funlen at 60 lines; nolintlint requires a reason and a named linter), go-arch-lint 1.19.2 for the handler, service, repository direction and each module's one public door, and Go's own `internal/` folders (each module's layers under `modules/<m>/internal/`) so that another module's import fails `go build`. File size: revive's `file-length-limit` in golangci-lint is the 500-line stop (one limit per rule), and a short script, `scripts/check-file-size.mjs`, gives the 300-line warning and fails a `//nolint` with no issue number. Each tool is pinned in its own `tools/<name>.mod` and run with `go tool -modfile`. (2) The check contract: the six commands are scripts in a root `package.json` that call `go tool`, `go vet`, `go test -race`, `go build` and the web pack's scripts; `test:e2e` is Playwright API testing against the built binary; Schemathesis is an optional extra. (3) The contract: code-first with huma 2.41.0 on ServeMux, its OpenAPI 3.1 file committed, and the TypeScript client made by orval 8.49.0; `typecheck` starts with a regenerate-and-compare step, which is what makes a drift between the Go server and the TypeScript client fail `check`. (4) The router is `net/http`'s ServeMux through huma's `humago` adapter, on Go 1.26.11; chi 5.5.0 is the runner-up. (#342)
- **Options considered:** boundaries: depguard rules per module, go-arch-lint, arch-go, Go's `internal/` folders, a `go list` script; where the commands live: `package.json` scripts, a Makefile, a Taskfile; `test:e2e`: Playwright API testing, a Go test on the built binary, Schemathesis, Hurl; contract: oapi-codegen strict server, ogen, huma, swaggo; client: openapi-typescript with openapi-fetch, orval, Hey API; router: ServeMux, chi, echo
- **Why:** Drift does not separate spec-first from code-first: on a field rename both passed on stale generated files and both failed once the files were regenerated and compared, so the compare step is what matters. What separates them is that oapi-codegen's strict server answered 201 to a body that breaks the spec's `minLength` while huma answered 422 with no setup, and that huma matches how the web pack builds its contract. depguard has no wildcard for a module name while the Go compiler enforces `internal/` for free; go-arch-lint covered the layer direction for every module with one config. The local gate and the agent-file guard read `package.json`; a Makefile, a Taskfile and `.golangci.yml` are not check code to the guard today. openapi-typescript and Hey API 0.99.0 crash on TypeScript 7.0.2, which npm now calls `latest` (Hey API's pre-release runs), and npm refuses openapi-typescript beside the web pack's TypeScript 6.0.3; orval is the one stable release that ran on both. ServeMux has method and parameter patterns, 405 with Allow and no dependency, and huma, oapi-codegen and ogen all accept it. Confidence: medium for the lint, the contract and the client generator, medium-high for the check contract, high for the router. Follow-ups for the pack's issues: add the Go check config to the agent-file guard, give the gate a Go environment (Go 1.26.10 or newer, because huma needs it), set huma's nullable arrays, `$schema` and error body. A fresh-session fact-check found one wrong claim in the first draft (that no linter caps file length) and six smaller ones; all are fixed in the dossier. Re-check by 2027-02-28.
