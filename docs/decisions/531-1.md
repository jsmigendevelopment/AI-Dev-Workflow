# Decision 531-1

- **Date:** 2026-11-28
- **Decision:** How the Dependabot gate and the `dependencies` skill take Go modules (#531). (1) `dependabot-bump.mjs` lets a modified `go.mod` or `go.sum`, at any depth, through its file check, and hands each to the new `dependabot-go.mjs`; the npm branches and their messages are as they were. (2) **go.mod** is read at the merge base and the head as statements, so a block and a one-line directive are the same and order and blank lines mean nothing (Go reads them as a set). Every statement but a `require` must be at the head exactly as at the merge base, comments included: a new, changed or missing `module`, `go`, `toolchain`, `godebug`, `tool`, `ignore`, `replace`, `exclude`, `retract` or comment line is refused, naming its line. A `replace`, `exclude` or `retract` the merge base already had passes unchanged, as an unchanged npm line does. (3) Each `require` is a module path and a canonical version (`vMAJOR.MINOR.PATCH`, with a prerelease or `+build` as pseudo-versions and `+incompatible` need) and keeps its comment (`// indirect`); a path the merge base didn't have (a new indirect requirement too, or a new major version path), a path gone, a repeated path or a changed comment is refused. A module path's first element must be a lower-case domain with a dot. (4) A go.mod line the gate can't read is refused at either end, naming the line: any word outside letters, digits and `._~+/=>[],-`, so quotes, backticks, parentheses, colons and stars; a control character, including a carriage return; a `//` stuck to a word; a comment on a block's opening or closing line; an unknown directive; an unclosed block. (5) **go.sum**: each line the merge base didn't have must be `<module> <version> h1:<hash>` or `<module> <version>/go.mod h1:<hash>`, split on single spaces, with `h1:` and 43 base64 characters and one `=`. Removed lines pass (`go mod tidy` drops the old version's). A blank line is never accepted. (6) Either file alone passes, as an npm manifest or lockfile alone does. `vendor/`, `go.work`, `go.work.sum` and source files are refused as other files. (7) The `dependencies` skill gets the Go form beside each npm command, as new lines only (no npm line changed): rules 2, 5, 6, 10 and 11, the young-package line, the Dependabot lines and the checklist. `coordinate`'s step 6.1 exit-0 line and `own-branch.mjs`'s header say a Go bump passes too.
- **Options considered:** Put the Go code inside `dependabot-bump.mjs` (it would pass 300 lines, the size warning, and mix two ecosystems in one file); compare go.mod line by line in order (a reordered or regrouped file is a plausible honest change, and a line moved into another block would need block tracking anyway); a refusal for any `replace`, `exclude` or `retract` at the head, even an unchanged one (npm's gate doesn't judge lines the merge base had, and a repo with a local `replace` could then never take a bump); tie each new `go.sum` line to a module in `go.mod` (a real bump adds `/go.mod` hash lines for modules `go.mod` doesn't list, since Go keeps the go.mod hash of everything in the module graph, so it would refuse honest bumps, and Go checks each hash against the checksum database anyway); accept quoted words and Windows line endings (Go reads them, but two readings of one line is the shape this gate must not pass); judge `go.sum` with `go mod verify` (it would run the pull request's code path and needs the network).
- **Why:** The gate decides what merges unreviewed, so it fails closed: anything it can't read is a person's review, which costs a little time and never a merge. The parser was run over ten real `go.mod` files from the module proxy (client-go, terraform, hugo, cobra and others, with `replace` and `exclude` blocks): all read, and a version bump of one of them passed. The go.sum shape and the `go mod tidy` behaviour (old lines removed, both new lines added) were checked by running Go 1.24.7 against the proxy on a scratch module. A bump that pulls in a new module is refused as the issue asks, so it becomes an issue built with `go get` and `go mod tidy`. The commands in the skill were run (`go list -m -versions`, `go list -m -json`, `go mod download -json`, `go mod verify`, `go mod tidy -diff`, `go build -mod=readonly`, `go mod why`) or, for `go-licenses report` and `govulncheck`, read from their READMEs and the proxy's version lists (not run); the Go pack's own licence and vulnerability scripts stay #530.
- **Originator:** AI pick, not reviewed (Full automation). The issue gives the accept and refuse rules; the file split, the order-free statement model, the unchanged-`replace` rule, the go.sum shape being checked without tying it to go.mod, the characters the gate reads, and the choice of `go-licenses` and `govulncheck` as the Go forms of the licence and audit steps are the builder's picks.
