# Decision 227-2

- **Date:** 2026-11-27
- **Decision:** `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT` get the `local` scope and the file `.env.sentry.local` in Sentry's connect block, next to `github`. On `ci = "local"`, `pnpm connect` asks once and writes them only to that file, which both deploys load (the `sentry` add-on's step 8). On `ci = "actions"` it also writes the GitHub values.
- **Options considered:** a new destination kind that means "the deploy's shell" and writes only on `ci = "local"`; `local` scope with the file only, dropping GitHub; `local` scope with the file and GitHub
- **Why:** The file destination already exists, and `.env.cloudflare.local` uses it the same way for the deploys' own values. A new kind needs new connect code and would ask for the same value twice (test and production) into one file. Keeping `github` keeps `ci = "actions"` working. The cost: on `ci = "actions"` the values also land in a git-ignored local file.
