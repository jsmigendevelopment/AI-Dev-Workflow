# Decision 319-1

- **Date:** 2026-11-27
- **Decision:** The TanStack Start pack keeps `lefthook`, and tells knip about its real use with a script: `"hooks": "lefthook install"` in `package.json` (#421, which replaced the first fix, an `ignoreDependencies: ["lefthook"]` entry in `knip.jsonc`). lefthook is really used: `lefthook.yml` holds the pre-commit hook (Prettier and ESLint on staged files), and `pnpm-workspace.yaml` lets its install script run so `pnpm install` installs that hook inside a git repo. Knip's lefthook plugin counts the package as used only when CI is set or it finds the installed hook in `.git/hooks`. That hook is missing when `pnpm install` ran before `git init`, in a git worktree (where `.git` is a file), or with `LEFTHOOK=0`, so a fresh copy failed `pnpm knip` there. A `hooks` script is a use knip sees in `package.json` itself, so it needs no ignore entry, prints no "Remove from ignoreDependencies" hint when the hook is installed (the first fix did, on every `pnpm check` after `git init`, which invited an agent to delete the entry), and exits 0 with or without the hook. `pnpm hooks` is also the command the README gives for installing the hook after `git init`. `knip.jsonc` ignores no dependency; `cli/test/pack-check-fresh.test.mjs` pins that, and that nothing else in the knip script or config hides one.
- **Options considered:** (1) `ignoreDependencies: ["lefthook"]` with the reason (the first pick, replaced by #421: it printed the hint, and an agent that follows a hint deletes the entry). (2) A `prepare` script, `lefthook install`, so knip sees a real use in `package.json`: `pnpm install` then fails outside a git repo, before the person runs `git init`, and installs hooks in CI. (3) A separate `hooks` script, the same use for knip without that failure, and a command the README names (picked in #421). (4) Remove lefthook and `lefthook.yml`: drops the pre-commit format and lint the pack README and the `stack-tanstack-start` skill promise, the hook that formats a file like `save-fails.test.ts` before it is committed in an app.
- **Why:** The smallest change that tells knip the truth, with no check weakened for any package.
- **Formatter note:** the pack's formatter step is the lefthook pre-commit hook, and it runs only in an app made from the pack. The kit repo commits `stacks/tanstack-start/` with its own git hooks, and the kit's tests read the pack's files without running its Prettier, so the unformatted line in `scripts/cloudflare/save-fails.test.ts` (from #161) reached main. The full fresh-app `pnpm check` is the check that catches it, run by hand on pack changes. Since #421 the same test file runs the pack's pinned Prettier over every pack file, with the pack's own config, whenever that exact version is on hand (decision 421-1), so a line like that fails a kit test.
