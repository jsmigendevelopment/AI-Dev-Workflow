# Decision 439-1

- **Date:** 2026-11-28
- **Decision:** `pr-size.mjs`'s main-module guard becomes a small function, `isMainModule()`, that compares the real path of `process.argv[1]` with the real path of `import.meta.url` (`realpathSync` on both sides). It is false when `argv[1]` is missing or names no file. The module stays importable without running `main`. The other scripts that use the old `resolve(process.argv[1]) === fileURLToPath(import.meta.url)` guard are not changed (see the issue's fence); they are listed in the pull request. `cli/test/pr-size-symlink.test.mjs` starts the script directly, through a symlinked file and through a symlinked repo folder, and expects the same exit code and count (2 for a missing ref, 0 under the limit, 1 at 1,000 lines); a second test imports it and expects no output.
- **Options considered:** remove the guard, as #434 did for `sync-skills.mjs` (it then runs on every import, so a test or another script can't import `MAX_CHANGED_LINES` or `measure` without a size check starting; and `pr-size.mjs` exports are used by `pr-rules.mjs`); compare `process.argv[1]` and `import.meta.url` as `pathToFileURL` URLs (still compares a symlink with a real path); compare real paths on both sides, as above.
- **Why:** A symlink only changes the name node was started with, so comparing real paths is the one check that holds for a symlinked file and a symlinked folder. The exports stay usable by other modules. The guard is false, not an error, when `argv[1]` names no file, so an import under a stand-in `argv[1]` still never runs `main`. A guard in a shared helper would add a module for one caller (no second real use yet).
