# Decision 322-1

- **Date:** 2026-11-27
- **Decision:** How `lesson check --project` builds and matches the deny set (#322). Each term, each part of it (split on `-`, `.`, `+`, `_`, a lower-to-upper step as in `GardenParty`, the end of a capital run and a letter-to-digit step), and the parts joined by a hyphen and by a space are terms; `_` reads as `-`. Kit glossary words and the kit's skill names leave the set, and so does a term whose singular or plural is one (`reviews` for a repo `review`); common words stay, and so do other component names such as `board`, `state` or `vision`, since an app can be named that. A field whose value passed its closed list (every field but `lesson` and `suggested_fix`) is not checked against the set: its value is the kit's own, as `claude-code` or the component `board`, so it carries nothing from the project. An extra key or a refused value is still checked. Docs give capitalised words that don't start a sentence (after a lowercase word, a digit or a comma, and not opening a quote, backtick or bracket), plus capitalised words of a level-one title. Domains come from URL hosts and email addresses in tracked files: the full host and its name label (`fernway` in `api.fernway.dev`, `saltmarsh` in `saltmarsh.co.uk`), never reserved names (`.test`, `.local`, any `example` label as in `app.example.workers.dev`), and never from a file whose bytes match the kit manifest's copy at the same path. Git authors whose name ends in `[bot]` are skipped. `.env` and every `.env.*` but `.env.example` are skipped by name before any read, and by their real name after a link is resolved; `.env.example` gives whole variable names only. Every read resolves links first and reads only a regular file whose real path stays inside the project (the person's own profile in the home folder may link anywhere, as to a dotfiles folder), at most 1 MB; a folder, device or pipe is never opened. Matching is whole-word (a letter or digit on either side breaks it), case-blind and in either number (a term with an `s` or `es` after it, and a plural term without its `s` or `es`: `notes` matches `note`, `Grant` matches `grants`), across every free-text or refused string field, one error per field, as `field: contains a project term (<kind>)`. The command takes `--project <dir>` (default: the top of the current git repo, else the current folder) in place of #321's `[dir]`, which had no use yet.
- **Options considered:** Split terms into parts, or keep them whole (a repo `pulse-notes` then leaks `pulse`); split camelCase too, or only on punctuation (`GardenParty` then leaks as `garden party`); match the singular and plural, or the exact word only (`notes` then leaks as `note`); every heading word as a title word (blocks `what`, `the`), or capitalised title words only; bare domains in code too (catches `this.app` as a host), or URL and email hosts only; split `.env.example` names into parts (blocks `key`, `secret`, `url`), or whole names only; drop every component name from the set (an app named `Board` or `vision-flow` then leaks whole), only glossary words and skill names (more refusals when the docs name such a word), or none (a repo `review` blocks every lesson); skip every file under `.agents/`, `.claude/` and `.codex/` for domains (a project's own skill there could hold its host), or only files the kit ships unchanged; check every string field as #322 first said (a project whose docs say Claude Code then refuses `tool: claude-code` in every lesson), or skip values that passed their closed list; follow links anywhere, never follow them (a project that links its docs loses them), or follow them only inside the project.
- **Why:** Privacy first: a wrong term fails closed and names its source kind, so the person can see why. The choices that only widen the set (parts, camelCase, either number, component names other than skills) cost an odd refusal, and the writer can rephrase or use `[detail]`; the ones that narrow it (no bare domains, no sentence-start capitals, no bots, reserved hosts, unchanged kit files) stop common words such as `the`, `example` or `workers` from blocking every lesson. A bare domain in a lesson is refused by #321's one-sentence rule anyway. Links are resolved before any read so rule 9 holds through a link, and a device is never opened.
