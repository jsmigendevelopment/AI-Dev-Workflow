# Decision 163-1

- **Date:** 2026-11-27
- **Decision:** How the agent-file guard reads `package.json` (#163). Every `package.json` at any depth and in any case in the file list (a rename's old name too) counts as check code when its `scripts`, `eslintConfig`, `prettier`, `jest`, `knip`, `jscpd` or `lint-staged` key changes in any way, by parsed JSON; a dependency bump or any other key doesn't. `agent-files.mjs` names these keys in `CHECK_KEYS`, beside `RULE_FILES` and `CHECK_FILES`, and lists each change as `<path> (scripts, prettier)`. The two sides come from the contents API at the merge base and at the head. The merge base is the compare API's `merge_base_commit` against the live base branch (`pull.base.ref`), not the base sha stored on the pull request, which can be older (round 1). A 404 is an empty side only where the file list says the file isn't there (an added or copied file's base, a removed one's head, a rename's new name at the base and old name at the head); anywhere else, and for any other failure, a missing merge base, a reply with no text (a folder, a symlink out of the repo, a file over 1 MB), a reply whose `path` isn't the path asked for (the contents API answers a symlink to a file in the repo with that file's content and path) or text that isn't a JSON object, the side counts as a change and the line says why. `decide` fails closed on a changed `package.json` it got no text for. `--pr` and `verify-run` go through the same `fromApi`, so they see it too; nothing new was added for them. The level rules don't change.
- **Options considered:** Read the patch text; treat any 404 as empty; compare objects with sorted keys; give `--pr` the old path-only reading; for the symlink (round 1): the trees API's mode (`100644`/`100755`) or the reply's `path`
- **Why:** The issue asks for parsed JSON. A 404 trusted everywhere would read a bad merge base as "no scripts before", which could pass a removal. Reordering keys counts as a change: rare, and failing closed costs one review. One shared `fromApi` keeps the old workflow mode from being the weaker door. Round 1: checking the reply's `path` needs no extra call, where a mode check through the trees API would add one per side; the live base branch is the merge GitHub would make now, and the base its file list uses.
