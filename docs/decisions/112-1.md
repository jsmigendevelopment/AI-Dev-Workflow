# Decision 112-1

- **Date:** 2026-11-27
- **Decision:** The orphan sweep is one script, `coordinate/scripts/orphans.mjs`, that the board render, the coordinator's step 10 and `/back` all use. It reads the sweep's one issue read, which now asks for `comments,body,createdAt` too, so there is no extra read.
  - A handoff record is a `Handoff ·` comment, labelled or not, an issue labelled `handoff`, or a `Claimed by` comment. With no `Got it ·` receipt after it, it counts once past its "check by" time, or 2 hours after the record when it names none.
  - A claim is stale after 2 hours with no commit and no open pull request for its issue, matched by branch name or by the `feat/<n>-` number, as the board does.
  - Review round 1 on #395:
    - Step 10, `/back` and the board run `git fetch origin --prune` right before the script. A claim whose branch has no local or `origin/` ref is `unknown`, never stale, and is listed only once the claim is 2 hours old. The loop never retakes an `unknown` claim.
    - A branch name from a comment is used only when it has no leading dash, only letters, digits, `_`, `.`, `/` and `-`, and passes `git check-ref-format --branch`. `git log` gets `--end-of-options` and the full ref. A name that fails is `unknown`, and its note doesn't repeat it.
    - "check by" is read in UTC, `Z`, `GMT` or a numeric offset (`+01:00`, `-0800`). A named zone (`PST`), no zone, or a time that isn't real (25:00, month 13, 30 February) gets the 2-hour default.
    - Only comments whose `authorAssociation` (gh) or `author_association` (REST) is OWNER, MEMBER or COLLABORATOR count, for records, receipts and claims. gh's `comments` field already carries it, so the read is unchanged. A comment with no association doesn't count. An issue body counts only with the `handoff` label, which only the repo's people can add.
    - One rule for every headline: the comment's text after leading spaces.
    - Nice 5 (one receipt answers every earlier record on the issue): kept as is. Matching a receipt to its record's receiver needs the session names parsed from free text, and two handoffs on one issue to two sessions hasn't come up.
- **Options considered:** a second `gh issue list` for claimed and `handoff` issues with their comments; the comments in the one read the sweep already makes (picked: GitHub prices a read by the nodes it asks for, so one read with comments costs less than two); the check left as skill text only, with no script. For a missing ref: fall back to the claim time (flags live work that wasn't fetched); report it `unknown` (picked).
- **Why:** #112 (follow-ups from the review of #110): a builder dispatched moments ago shouldn't be flagged, step 10 had no comments to check, and a handoff written as a comment never gets the label. A claim waiting on review has no new commits by design, so an open pull request keeps it fresh. Round 1 of the review on #395: a branch name from a public comment reached `git log` as an option, and an unfetched branch read as stale, which on Full would start a second builder on live work.
