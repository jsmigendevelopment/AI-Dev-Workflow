# Decision 747-1

- **Date:** 2026-11-28
- **Decision:** `.agents/skills/issues/scripts/check-gate-acs.mjs` fails an issue that adds a refusal and never says what happens to every other input (default deny), and consistency check 13 runs it. (1) **What counts as a refusing AC:** an AC line (below) whose THEN part, or the whole text when it has no WHEN/THEN, holds one of: refuse (refuses, refused, refusal), block, reject, deny (denied), forbid, disallow, hide (hides, hidden), fail (fails, failed), `prints nothing`, `nothing is printed/shown/written`, `is/are not printed/shown/written/allowed`, `never prints/shows/writes`, `exits` or `exit is/code` followed by `non-zero` or a number from 1 up. Whole words only (`blockchain` and `unblocked` are not hits). A negated one ("is not refused") still counts as refusing, so the check can only catch more. (2) **What counts as an AC line:** a line that starts (after a list mark, a checkbox and an `auto` or `agent` tag) with `AC-<id>`, then a colon, a dash or a full stop, a `(auto)` tag, or straight `WHEN`. Lines in an HTML comment, a fenced block, a quote or an "Out of scope" section are not read. A wrapped line joins its AC. (3) **What satisfies the check, exactly:** one AC line that is not tagged `agent`, whose text is `WHEN <w> THEN <t>`, where `<w>` holds one of: `not on|in|among|one of|part of` + `the|a|an|that|this|its|any` + up to 3 words + `list|allowlist|allow-list|template|set|names|keys|values|flags|inputs`; `any|every|all|each` + `other|remaining|unlisted|unknown|unrecognized|unsupported|unexpected`; `anything else` or `everything else`; one of the words `unknown`, `unlisted`, `unrecognized`, `unsupported`, `unexpected`; or `not` + `listed|allowed|known|recognized|approved|permitted|supported`; and `<t>` holds a refusal word from (1) that is not negated in the three words before it. The same AC may also name the refused input ("--dry-run or any other unknown flag"). (4) **What does not satisfy it:** those words in the goal or any prose, in a comment, fence, quote or "Out of scope" section, in the THEN part, in an AC tagged `agent`, in a line with no `AC-<id>` start, in a mention like `see AC-2 where ...`, or beside a THEN with no refusal word or a negated one ("it is not refused", "it never blocks"). One stray word anywhere is never enough: it takes a numbered, testable WHEN/THEN line that says the rest is refused. (5) **Limit, said plainly:** a script can't tell whether the allowed list the AC names is the right one. A well-formed AC with the right words and a wrong meaning passes; the review reads it, and the test the AC needs tries spelling variants of the refused input (`cli/test/spellings.mjs`). (6) **Exit codes:** 0 when no issue is a gap (prints one summary line); 1 with one line per gap issue, naming the issue and its first refusing AC; 2 when stdin isn't a JSON list, a file can't be read, no issue is left after `Status: done` files are skipped, or any issue has no AC line it can read (that issue's line is printed too, and 2 wins over 1). (7) **Test helper:** `cli/test/spellings.mjs` exports `spellings(flag)`: the flag as written, then lower, upper, title and alternating case, `-`, `_` and no-separator joins of a multi-word name, camel case, a plural (`s`, `es`, `ies`), a trailing `=1` or `=`, and the `--`, `-`, `__`, `_` and no-prefix forms, with no duplicates. The existing generators' `--dry` test is not rewritten. (8) **Check count:** `consistency.md`'s report line (`Consistency check · pass <N> · <date> · <k> issues read`) never held a check count, so nothing there changes beyond the new numbered check 13; a test pins that the checks run 1 to 13 and the report line is as before.
- **Fix round 1 (review of PR #754):** (9) **`Status: done` only skips a file.** A GitHub issue body is never skipped, because anyone who writes the body could switch the check off with one line (like `check-issue-size.mjs`); so a pass of only done files still exits 2, and a stdin issue with `Status: done` and a gap exits 1. (10) **Mentions don't cover.** Before the covering AC's THEN is searched, quoted (`"..."`, curly quotes), backtick and triple-backtick spans are swapped for a mark, and a refusal word after `rather than` or `instead of` (three words) does not count; `` `blocked` is not printed `` does not count either, because "is/are not <x>" said of a quoted name names the name, not the input. A span as the subject of a plain verb (`` `pnpm lint` fails ``) still covers. (11) **Wider detecting list, same covering list.** A refusing AC is also one that says `errors` (the verb, not after `no`/`without`/`the`...), `exits with an error`, `returns|responds with 4xx or 4NN`, `is|are not accepted|permitted` (and `isn't`/`aren't`), `aborts`, `cannot|can't continue`, `does not|doesn't print`, `is|are|gets redacted`. They only mark an AC as refusing, so they can only flag more issues; a covering THEN still needs one of the words in (1), so the covering side is never loosened. (12) **Lookalikes.** The refusing AC's text is normalised before matching: NFKC (full-width letters), zero-width and other invisible characters dropped, common Cyrillic and Greek lookalikes mapped to Latin. The covering AC is read as written, so a hidden word never helps it. (13) **Left as is, on purpose:** an indented code block, a lazy quote line (no `>` on a wrapped line) and a `<details>` block are read as ordinary AC text; a script can't tell them from prose without a Markdown parser, and the review reads the AC.
- **Fix round 2 (review of PR #754):** (14) **Raw text and folded text, either one.** A refusing AC is read as written and also folded (12), and a hit in either counts, so folding can only add hits. Folding alone could lose one: `blocked™` becomes `blockedTM`, and a soft hyphen or zero-width space inside or beside the word was the boundary that made it a whole word. (15) **A long THEN stays fast, and reads the same.** The check that a refusal word is not negated, not after `rather than` or `instead of`, was found by looking at all the text before every refusal word, which grew with the square of the length (43 s at 256 KB). It now finds every lead-in (a negation or `rather than`, then up to three words) in one pass and asks whether a refusal word starts where one ends, and a lone opening curly quote is no longer scanned to the end of the text. Same results as before on every input tried; only the time changed. A fixed window of the last 80 characters was tried and dropped, because a negation 100 letters or 200 blanks before the word then stopped counting, which made the covering side looser. (16) **A number before `errors` is a count, not a verb.** `pnpm lint reports 0 errors` is not a refusing AC. Only a number straight before the word is allowed; this is the one change that makes the detecting side flag fewer ACs, and on the real issues it changes only #146. (17) **Left for a follow-up:** a single-quoted refusal word (`'refused'`) is not read as a mention, and `rather than` followed by four or more words before the refusal word still covers.
- **Options considered:** Fail any issue with a refusing AC unless a named phrase appears anywhere in the body (one magic word passes it; refused). Read the refusing words from the title and goal too (flags prose, not ACs). Use a model to judge the AC (not read-only deterministic, and slower). Let the covering AC be `agent` (a default-deny rule needs a test; refused).
- **Why:** Five gates on 2026-11-28 were built to refuse only the spelling the issue named, and each review round found the next spelling. Asking for one AC that says what is allowed, and refusing the rest, moves that finding from the third review round to the issue's own consistency check.
- **Originator:** AI pick, not reviewed (Full automation). The refusal and catch-all word lists, the `agent` exclusion, the exit 2 for an AC-less issue in a list, the one-line-per-issue output and the spelling forms are the builder's picks.
