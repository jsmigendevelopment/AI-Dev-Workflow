# Decision 475-1

- **Date:** 2026-11-28
- **Decision:** How the 0.7.2 release prep (#475) handles two things the bump runs into. (1) `cli/test/changelog-union.test.mjs` AC-362-1 asserted that the real `CHANGELOG.md` has `### Added` under `## [Unreleased]`. Right after `versions.mjs` moves Unreleased under a version, Unreleased is empty, so the test failed on every release branch, and would fail on main after the merge until the next entry lands. The test now asserts the real file has the `## [Unreleased]` heading, writes the scratch copy with an `### Added` heading under it when the real file has none, and keeps every merge assertion as it was. It still goes red when `.gitattributes` drops `CHANGELOG.md merge=union`. (2) The release pull request adds no line under Unreleased. The release is the new `## [0.7.2]` heading, and Unreleased stays empty, as `versions.mjs` leaves it and as the 0.7.1 release did (#275).
- **Options considered:** For (1): add an empty `### Added` heading under Unreleased in `CHANGELOG.md` (changes the doc to suit a test, and `versions.mjs` would need to write it on every release); fix the test in its own issue and pull request first (the release pull request stays red until that merges); change `versions.mjs` to keep the heading (changes the release tool for a test's sake). For (2): a line under Unreleased that says 0.7.2 was cut (it would ship as the first line of 0.7.3).
- **Why:** The union-merge behaviour is what AC-362-1 checks. Where the starting text gets its Added heading doesn't change that, and the test no longer depends on what happens to sit under Unreleased that day. Fixing it here keeps the release pull request green in one change.
- **Originator:** AI pick, not reviewed (Full automation: the owner, 2026-11-26). The release itself is the owner's ask: "prep 0.7.2 for release".
