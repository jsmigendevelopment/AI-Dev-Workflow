# Decision 220-1

- **Date:** 2026-11-27
- **Decision:** How #220 widens the agent-file guard. Package-manager settings files (`.npmrc`, `.yarnrc`, `.yarnrc.yml`, `pnpm-workspace.yaml`, `.pnpmfile.cjs`) and the other manifest names pnpm reads (`package.yaml`, `package.json5`) are whole-file check code in `CHECK_FILES`, as is `.gitattributes`. In `package.json`, `eslintIgnore`, `stylelint`, `workspaces`, and the override keys `pnpm`, `overrides` and `resolutions` join `CHECK_KEYS`. An alias inside `dependencies` or `devDependencies` (`eslint: npm:<other>`) stays a dependency change and isn't protected.
- **Options considered:** Protect only the script-related keys inside the settings files (needs a YAML and ini parser on both sides, more code and more ways to read one wrongly); protect the whole file (chosen: fails closed, rarely edited); for other manifests, parse them like `package.json` (needs JSON5 and YAML parsers) or protect the whole file (chosen); for aliases, protect any dependency whose name is a checker (a list to keep in step with every tool) or leave them to review (chosen)
- **Why:** Whole files fail closed with one line each and no parser. Override keys are rare and are the plain way to swap a checker repo-wide, so they cost little to protect; aliases sit in the dependency lists every bump touches, and protecting them would put every bump through the weakening review, against AC-4.
- **Originator:** AI pick, not reviewed
