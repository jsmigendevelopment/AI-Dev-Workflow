# Decision 397-1

- **Date:** 2026-11-27
- **Decision:** The orphan sweep's follow-ups from round 2 of the review on #395:
  - An unlabelled issue whose body starts with `Handoff ·` is a handoff record when its author is one of the repo's people: its own `authorAssociation` or REST `author_association` is OWNER, MEMBER or COLLABORATOR, or its author's login wrote a trusted comment anywhere in the sweep's issue list. gh's issue list has no association for the issue itself, and GitHub gives one association per person per repo, so a login seen on a trusted comment is trusted. `board.md`'s issue read asks for `author` so the login is there (round 1 of the review on #437). A labelled issue still counts whoever wrote it. This replaces 112-1's "An issue body counts only with the `handoff` label".
  - The sender runs `gh label create handoff --force` before it files the issue, so a repo set up before the label still takes it.
  - Times are read from gh's `createdAt` or REST's `created_at`; authors from gh's `author` or REST's `user`.
  - A branch name may hold any letter or digit (`\p{L}`, `\p{N}`) plus `_./-`, and still passes `git check-ref-format --branch`. A name outside that is `unknown`, with the note "its branch name isn't one this can check", since git may accept it.
  - Only pull requests whose `isCrossRepository` isn't true keep a claim in review. `board.md`'s pull request read asks for it. A list without the field counts every pull request as this repo's, as before.
  - The issue read's 100-comment limit is written in `board.md`, with the REST command that pages: its output goes in that issue's `comments` in the cached list before the run, or the claim and receipts are checked by hand. It isn't fixed in the script.
- **Options considered:** for the unlabelled body: count it from anyone (an outsider's issue adds a line to the board); a second read for each issue's author association (an extra API call per sweep); trust its author when the login is on a trusted comment in the same list (picked: no extra read, and the person's agents comment on claims and receipts under the same login). For the fork: `headRepositoryOwner` compared to the repo's owner (needs the owner passed in); `isCrossRepository` (picked: one boolean gh already has). For 100 comments: page in the script (it makes no API calls by design); say it in `board.md` (picked).
