# Decision 401-1

- **Date:** 2026-11-28
- **Decision:** How `deploy:test` copes with insights records that wait in the checkout (#401). (1) The TanStack pack's clean-checkout check, `noChanges()` in `stacks/tanstack-start/scripts/deploy/shared.ts`, ignores new files under `docs/insights/`. It runs `git status --porcelain -uall` (each untracked file listed, not just its folder) and drops lines that start with `?? docs/insights/`. (2) An edit to a record git already has, and every other change or untracked file, still stops the deploy. The message lists only what counts. (3) `noChanges()` also serves `deploy:preview` and `deploy:production`, so all three treat pending records the same. (4) Neither insights writer changed, so `insights.mjs` record kinds and `mark-check.mjs` stay free for #334.
- **Options considered:** Write pending records outside the work tree (under `.git/`) and copy them in only inside `land`'s temp index: it changes where every writer, `has-records`, `carry` and `land` read and write, and touches the files #334 is changing. Ignore the whole `docs/insights/` folder in the check, including edits to tracked records: simpler, but a hand edit of a landed record could ship unnoticed.
- **Why:** The check only exists so a build never ships files a commit doesn't hold. A record is data under `docs/insights/`, not shipped code, so ignoring new ones loses nothing. It is the smaller change: one function and its test, no change to how records are written or landed.
