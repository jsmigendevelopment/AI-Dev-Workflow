# Decision 267-1

- **Date:** 2026-11-27
- **Decision:** How #267 keeps the Windows process registry from following a link on a peeked index path. `peek()` in `scripts/procs-store.mjs` now also drops a path when `linkOnWay` (new, `scripts/procs-path.mjs`) finds a symlink or junction on the way: it walks the path from the root down with `lstat` only and stops at the first link or missing part. A dropped path, and every folder of it, stays out of the one ACL batch; it is only looked at again after the index passes its checks, through the checks that already refuse links.
- **Options considered:** Ask PowerShell to skip reparse points in the batch script (the `existsSync` before it still follows links); drop only the folders below the link and keep the ones above (more code for folders the batch mostly reads anyway); drop the whole peeked path
- **Why:** Dropping the whole path is the smallest change, follows nothing, and costs at most a later, separate read for a path that is odd to begin with. Plain paths still go in one batch, so AC-248-2 stays green.
