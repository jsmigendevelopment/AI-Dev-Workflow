# Decision 570-1

- **Date:** 2026-11-28
- **Decision:** The agent-file guard (`agent-files.mjs`) also treats `*.mk` files and `go.work` as check code (#570, follow-up to #532). `CHECK_FILES` gains one alternative that matches any file whose name ends in `.mk`, and `go.work`, at any depth and in any case. A Makefile can `include` any `*.mk` file, so a `check` target moved into one is no longer unseen. `go.work` picks the modules a Go workspace builds and checks, so editing it changes what runs. `go.work.sum` stays out, with `go.mod` and `go.sum` (decision 532-1): it holds checksums only, like `go.sum`, so it can't swap a checker or move a `check` target; a wrong hash makes the build fail, which is a check doing its job. `automation/references/full.md` lists the new names and the three that stay out, and `cli/test/agent-files.test.mjs` gains the AC-570-1 cases. What counts as a test file is unchanged.
- **Options considered:** (a) add `*.mk` and `go.work` only (chosen); (b) also add `go.work.sum`, which costs a review on every checksum refresh and guards nothing the build doesn't already refuse; (c) match only `include`d `*.mk` files by reading the Makefile, which needs the guard to parse Make and fails open on a missed include shape.
- **Why:** The guard only gets stricter. A differential run of the old and new `CHECK_FILES`, `RULE_FILES` and `TEST_FILE` over about 20,000 paths built from the guard's own names found no path the old script protected that the new one doesn't, and every path gained ends in `.mk` or is `go.work`. (a) is the issue's fence: no other new names.
- **Originator:** AI pick, not reviewed (Full automation). The ask is the issue's own words: add `*.mk` and `go.work` at any depth and keep `full.md` in step. Leaving `go.work.sum` out is the AI pick.
