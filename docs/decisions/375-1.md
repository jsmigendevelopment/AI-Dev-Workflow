# Decision 375-1

- **Date:** 2026-11-27
- **Decision:** The consistency check's size rule is a script, `issues/scripts/check-issue-size.mjs`, that reads issues as JSON on stdin (`gh issue list --json number,title,body,labels`) or as `docs/issues/*.md` files, prints one line per issue with a gap and exits 1. It exits 2 when the input can't be read, and when a split parent on stdin has no `labels`, since then it can't tell whether that parent is ready (#400). It reads the estimate before the first `·` on the `Size:` line, takes the largest number there (so a range counts at its top), ignores HTML comments, and lets a `Size: exception: <reason>` line keep an estimate. (#375)
- **Options considered:** a new numbered check in `consistency.md` only, which the checker agent applies by eye; a check inside `check-plan.mjs`, which reads the plan, not the issues; a small script in the `issues` skill that the checker runs
- **Why:** AC-375-2 asks for a check that fails and names the issue, and a script does that the same way every run and can be tested. The consistency check stays read-only: the script writes nothing. Its name keeps it apart from the pull request size check planned in #377.
- **Originator:** AI pick, not reviewed
- **Later:** Decisions 375-3 and 375-4 replace how the script reads a Size line (one fixed shape, every other estimate fails) and the command it runs on (`gh issue list --limit 200 --json number,title,body,labels`). The script and the "issues on stdin or as files" choice stay. Decision 400-1 tightens the exception and second-estimate rules.
