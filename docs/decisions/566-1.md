# Decision 566-1

- **Date:** 2026-11-28
- **Decision:** The Go rows say what they found, and doctor's `go` can't fetch a toolchain (#566, follow-up to #538). (1) The module-proxy row reads the first entry of `go env GOPROXY` (a list is split on `,` and `|`): a plain host is named as before; `off` and `direct` read "GOPROXY is off" and "GOPROXY is direct"; anything else (a URL with a user and a token, a file path) reads "GOPROXY isn't a plain host" and is not printed. `proxy.golang.org` is named only when `go env` is empty (Go's own default) or names it. The ladder's host for those three is "the module proxy". (2) The `GO_CACHE` rung says the project-local module cache helps when the default module cache is unwritable, and that it still needs the proxy to answer. (3) Doctor's `go version` runs with `GOTOOLCHAIN=local` in its environment: `sys.probe` takes an `env` option that adds variables to the child's. (4) Decision 538-1 notes that `go list -m -versions` may create `pkg/mod` under the default GOPATH. (5) Two assertions in `AC-538-2`'s test "the proxy host in the row is the one go says it uses" expected `proxy.golang.org` for a `user:token@` URL and a `file://` path, which is the behaviour (1) removes. They now expect "GOPROXY isn't a plain host"; the other assertions and every other test are unchanged.
- **Options considered:** For (1), keep the default's name for any value that isn't a plain host (the issue's acceptance check rules it out); print the offending value (a URL can carry a token); say only "GOPROXY is not default". For (3), a `doctor`-only `spawnSync` for `go` (a second PATH search that could disagree with every other tool's); setting `GOTOOLCHAIN` in the whole process's environment (changes every tool doctor runs).
- **Why:** The row exists to tell the person which proxy to unblock. Naming the default for a proxy that isn't it sends them to the wrong host. A project-local module cache can't make a blocked proxy answer, so the rung claims only what it does. Doctor runs from the home folder, where a stray `go.work` or `toolchain` line could make `go version` download a toolchain to answer.
