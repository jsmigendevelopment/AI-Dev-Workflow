# Decision 377-2

- **Date:** 2026-11-27
- **Decision:** What `pr-size.mjs` leaves out, and where it reads that from.
  - Lockfiles: the list `pr-rules.mjs` already had, plus `Podfile.lock`, `pubspec.lock`, `flake.lock`, `mix.lock`, `packages.lock.json` and `gradle.lockfile`.
  - Generated files: those the base's committed `.gitattributes` mark `linguist-generated` (the kit's synced copies, and each pack's list in its own `.gitattributes`). The base is `<ref>` for `--base <ref>`, and the pull request's base commit for `<n> --repo`, which must be in the checkout (exit 2 otherwise). The branch's own `.gitattributes` never decide.
  - Test fixtures: a file of a known data type (`json`, `jsonc`, `json5`, `jsonl`, `ndjson`, `yaml`, `yml`, `toml`, `txt`, `csv`, `tsv`, `xml`, `snap`, `golden`, `log` and common image types and `pdf`) in a `fixture`, `fixtures`, `__fixtures__` or `testdata` folder under a top-level `test`, `tests`, `__tests__`, `e2e` or `spec` folder, such as `test/fixtures/page.json`. Also a `.snap` file directly in a `__snapshots__` folder anywhere, as Jest and Vitest store them next to their tests. Every other type counts, files with no extension included. Folder names match case.
  - A rename is left out only when both its names are.
  - A local run counts the diff with an empty work tree and index, so no `.gitattributes` on the branch (`binary`, `-diff`) can show text as binary.
  - Binary files of a known binary type (images, fonts, archives, audio and video, compiled code, `.pdf`, `.db`, office files and the like) count 0 and are listed under "Binary files, not counted". Any other file that shows as binary is exit 2, with its name (#407): git and GitHub call a file binary when it holds a NUL byte, TypeScript and Node accept one in a comment, and a UTF-16 text file (as PowerShell writes) holds many. That covers source, `.md`, `.json`, `.yaml`, `.html`, `.css` and files with no extension. Locally that is a `-` in `--numstat` on a file HEAD still has; a git error other than a missing path is exit 2. In a pull request it is an entry with 0 added, 0 removed and no patch that isn't removed; a known binary type is listed as it is, and any other file's content at the head (GitHub's contents API) decides. An empty file isn't binary and passes. A mode change or a pure rename passes when the file holds no NUL, and is exit 2, in both modes, when it holds one. An `added` or `modified` entry with 0/0, no patch and content but no NUL is exit 2 too: GitHub couldn't diff it. The one exception is a `modified` entry whose blob `sha` is the base's own blob at that path (`git rev-parse <base>:<path>`; main's HEAD at the gate): only its mode changed, so it passes, whatever status word GitHub gives a mode change. Content GitHub won't send (over 1 MB) is exit 2.
  - The `Size exception:` line counts only where the description shows it: not in an HTML comment, a fenced code block, an indented code block or a `<script>` or `<style>` block (#407). Code is stripped first, so a tag in a fence or in inline code, such as `` `<style>` ``, hides nothing. A fence closes only on a line of its own character, at least as many, then spaces (CommonMark 4.5). The reason needs a letter, and the template's `<reason>` doesn't count. A local run has no label, so it can't pass on an exception.
  - A line count that isn't a whole number of 0 or more is exit 2, never a pass.
- **Options considered:** for fixtures, any file in a fixtures folder (round 0: code could hide there), anything but a list of source types under any test folder (round 1: unknown types and nested `test` folders counted as data), or a list of data types under a top-level test folder, as above. For the diff, `--attr-source` (git 2.40 or later only), `--text` (it doesn't undo `-diff` for `--numstat`), or an empty work tree and index, as above.
- **Why:** Reviews 1 and 2 of #396 showed ways a branch could make its code count less: its own attributes, a `fixtures` folder, a NUL byte, or an exception reason hidden from the reader. A list of data types fails closed, and so does a list of binary types. A file the script can't count never passes.
- **Known limits:**
  - Line counts follow `\n` only, as GitHub's do. A file whose lines end in a lone CR, or one very long line, counts as 1 line, though the diff still shows all of it.
  - A submodule counts as 1 line (plus `.gitmodules`), though it brings in another repository's code.
  - In pull request mode the base's `.gitattributes` decide. For a stacked pull request whose base is another feature branch, that branch's attributes decide in `pnpm pr:rules` and `pr-size.mjs <n>`. The gate, `pr-rules.mjs`, reads main's own HEAD, so it isn't affected.
  - A pull request that renames many files without changing them makes one contents call per file that isn't a known binary type, to check each for a NUL byte.
  - A text file the base's `.gitattributes` mark `binary` or `-diff` may show in a pull request as 0/0 with no patch, and is then exit 2. A local run with `--base` ignores those marks and counts it.
  - Only a top-level test folder holds fixtures. A monorepo's `apps/*/test/fixtures` or `packages/*/test/fixtures` data counts, so such a pull request may look bigger than it is (#407): split it, or use the size exception.
