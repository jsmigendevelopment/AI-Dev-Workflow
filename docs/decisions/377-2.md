# Decision 377-2

- **Date:** 2026-11-27
- **Decision:** What `pr-size.mjs` leaves out, and where it reads that from.
  - Lockfiles: the list `pr-rules.mjs` already had, plus `Podfile.lock`, `pubspec.lock`, `flake.lock`, `mix.lock`, `packages.lock.json` and `gradle.lockfile`.
  - Generated files: those the base's committed `.gitattributes` mark `linguist-generated` (the kit's synced copies, and each pack's list in its own `.gitattributes`). The base is `<ref>` for `--base <ref>`, and the pull request's base commit for `<n> --repo`, which must be in the checkout (exit 2 otherwise). The branch's own `.gitattributes` never decide.
  - Test fixtures: a data file in a `fixture`, `fixtures`, `__fixtures__`, `testdata` or `__snapshots__` folder that sits under a `test`, `tests`, `__tests__`, `e2e` or `spec` folder, such as `test/fixtures/page.json`. Source code (`.ts`, `.tsx`, `.js`, `.mjs`, `.py`, `.go` and the like) always counts, wherever it sits. Folder names match case.
  - A rename is left out only when both its names are.
  - A local run counts the diff with an empty work tree and index, so no `.gitattributes` on the branch (`binary`, `-diff`) can show text as binary. Only a real binary file, as git's own test finds it, counts 0.
  - The `Size exception:` line counts only where the description shows it: not in an HTML comment, a fenced code block or an indented code block. Its reason needs a letter, and the template's `<reason>` doesn't count. A local run has no label, so it can't pass on an exception.
  - A line count that isn't a whole number of 0 or more is exit 2, never a pass.
- **Options considered:** for fixtures, any file in a fixtures folder (round 0: it let code hide there), only paths main's `.gitattributes` marks, or data files under a test folder, as above. For the diff, `--attr-source` (git 2.40 or later only), `--text` (it doesn't undo `-diff` for `--numstat`), or an empty work tree and index, as above.
- **Why:** Review round 1 of #396 showed a branch could mark its own code as generated, show it as binary, or put it in a `fixtures` folder, and hide an exception reason from the reader. Data files under a test folder need nothing set up in an app and can't be code a reviewer reads. The empty work tree works on every git version.
- **Known limit:** in pull request mode the counts come from GitHub's file list. Whether GitHub follows a branch's own `binary` or `-diff` attributes when it counts lines wasn't tested here. If it does, a branch could still show text as 0 lines there. `pr-rules.mjs` reads the same list, so the gate has the same limit. A check against a scratch repository would settle it.
