# Decision 249-1

- **Date:** 2026-11-27
- **Decision:** How #249 reads macOS ACLs on the process registry's path. One `/bin/ls -lde -- <paths>` start per command reads every folder's extended ACL. A folder is refused when an `allow` entry for any account but this user and root grants `write`, `add_file`, `append`, `add_subdirectory`, `delete_child`, `delete`, `writesecurity` or `chown`; group entries count, whoever is in the group. A failed `ls`, a missing block or a line the reader doesn't know is "can't tell" and refuses too. `deny` entries grant nothing, so a home folder's default `group:everyone deny delete` passes. The fix named is `chmod -a# <n> <folder>`.
- **Options considered:** One `ls` per folder (simple, but many starts per command); parsing `ls -le` only for folders whose mode shows `+` (two passes, and a `+` can't be trusted alone); the one batched `ls -lde`
- **Why:** One start keeps a command fast, the same shape as the Windows reader (#248), and anything unknown fails closed.
