# Decision 331-2

- **Date:** 2026-11-27
- **Decision:** The gate's record file also carries `pr` (required) and `fence` (optional), so `mark-check.mjs` takes one new flag, `--record <file>`, and no `--pr`. `--record` stays optional: without it, `mark-check.mjs` posts as before and writes nothing. The coordinator writes the file to its own `mktemp` path, outside the head's clone and `<home>`, and removes it after the run. A record that can't be written (no git checkout, a full disk) is a warning: the status is still posted. (#331)
- **Options considered:** `--pr` and `--fence` flags; the pr and fence in the file; `--record` required on every run
- **Why:** One flag keeps the call short and the usage line stable. A required `--record` would break every caller written before this change. A file outside both folders can't be changed by the head's commands. A missing status can hold up a merge, a missing record only drops one count, so the post never waits on the record.
