# Decision 376-3

- **Date:** 2026-11-27
- **Decision:** The plan checker fails closed on line estimates. A steps table with no `Lines` column is one plan error that says to add it. With the column, every step needs a cell, slice 0 included: an empty or comment-only cell, an estimate the issues reader can't read, a second estimate, an exception with no reason, a split, or 1,000 or more each fail that step. In `cli/test/check-plan.test.mjs` the shared head gets the column, and each row written without a Lines cell gets `about 200 lines` before its After cell, so every older assertion runs unchanged. The `plan-thin-steps` eval's good plan gets real estimates, and its `steps-are-small` check also counts the Lines errors. (#376)
- **Options considered:** a missing column is only a warning, so old plans keep passing; a missing column fails; only feature steps need an estimate, slice 0 skipped
- **Why:** AC-376-1 asks for an estimate on every step, and 375-3 chose to fail closed for the same reason: any gap the check lets through is a way to pass a big step. An old plan gets one clear error with the fix the next time the checker runs. The skeleton is often the biggest pull request, so it states its exception instead of being skipped.
