# Decision 333-1

- **Date:** 2026-11-27
- **Decision:** The merge step's record check is `insights.mjs has-records --pr <n> --sha <sha>`, not `verify --pr <n> --sha <sha>` as #333 first named it. Its tests are in `cli/test/insights-has-records.test.mjs`, because `cli/test/insights-verify.test.mjs` already holds #332's `land --verify` tests. (#333)
- **Options considered:** `verify --pr --sha`, the issue's name, which sits next to `land --verify <pr>` and differs from it by one word; a flag on `land`, such as `land --require <pr>`, which mixes a read-only check into the command that pushes and opens pull requests; a subcommand named for what it checks, `has-records`
- **Why:** Two commands that both say "verify" and both take a pull request number check different things: one checks a records-only pull request's diff, the other checks that a code pull request's head has its records. An agent that mixes them up merges on the wrong check. `has-records` says what it checks, shares no word with `land --verify`, and reads only files, so it needs no flag on a command that writes.
- **Originator:** AI pick, not reviewed
