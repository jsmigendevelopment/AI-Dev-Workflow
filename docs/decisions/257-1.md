# Decision 257-1

- **Date:** 2026-11-27
- **Decision:** The TanStack Start pack's `sentry` add-on keeps `@sentry/cloudflare` (Worker, `withSentry`) and `@sentry/react` (browser), with dev `@sentry/vite-plugin`, all pinned at 11.19.0. It does not add `@sentry/tanstackstart-react`.
- **Options considered:** `@sentry/cloudflare` + `@sentry/react` (chosen); `@sentry/cloudflare` + `@sentry/tanstackstart-react`, as Sentry's guide does; `@sentry/tanstackstart-react` alone (its server build depends on `@sentry/node`, and the guide still wraps the Worker with `@sentry/cloudflare`)
- **Why:** On Workers the SDK that runs and reports is `@sentry/cloudflare`: Sentry's guide (`getsentry/sentry-docs`, `docs/platforms/javascript/guides/tanstackstart-react/manual-setup/cloudflare.mdx`, read 2026-11-27) wraps the entry in its `Sentry.withSentry` too. The Start package's `wrapFetchWithSentry` only adds server-function tracing, which the add-on keeps off (`tracesSampleRate: 0`), needs a `@ts-expect-error` the pack's lint forbids without an issue, and pulls in `@sentry/node`. Errors already reach Sentry without it. npm on 2026-11-27: all four packages at 11.19.0 (published 2026-11-26), MIT.
