# Decision 544-1

- **Date:** 2026-11-28
- **Decision:** How `checkoutOf()` in `insights-carry.mjs` finds a checkout owned by another user (#544). (1) The isolated `git rev-parse --show-toplevel` names the script's own checkout as `-c safe.directory=<folder>` only when the operator's own global config lists that exact folder, or `*` (the same rule `pr-size.mjs` follows, decision 432-1). Otherwise the call trusts nothing and a foreign-owned checkout is refused with git's "dubious ownership" error, as before. (2) The rule is not copied: `trustedRoot()` in `pr-size.mjs` is exported, and `checkoutOf()` calls it. It finds the folder above the script that holds `.git` without git, reads the operator's list with `git config --file <file> --includes -z --get-all safe.directory` through the isolated git helper from a scratch folder (`GIT_CONFIG_GLOBAL` if set, even empty, else the XDG file then `~/.gitconfig` under the operator's `HOME`), lets a later empty entry clear the list, treats exit 1 as "no entry" and any other non-zero exit as "nothing listed", and trusts nothing when the operator's environment sets `GIT_CONFIG_COUNT` (non-zero) or `GIT_CONFIG_PARAMETERS`. (3) Nothing else changes: every other call in `insights-carry.mjs` keeps its isolation, and `fetchMain()` and the calls after it already name the checkout `checkoutOf()` returned as `safe.directory`, so the one call that needed the operator's entry was the first lookup. `has-records`, `harvest`, `land` and `write` are untouched. `pr-size.mjs` behaves as before; the only edit there is the `export` keyword.
- **Options considered:** (a) Trust the script's own folder on that call unconditionally, as the issue first suggested: simplest, but wider than git's own rule (a planted parent `.git` owned by someone else would be trusted whether or not the operator had marked it safe) and wider than what #611 shipped for `pr-size.mjs`. (b) Copy `pr-size.mjs`'s list-reading code into `insights-carry.mjs`: no new import, but two copies of a rule that took three review rounds to get right, which would drift. (c) Export `trustedRoot()` from `pr-size.mjs` and use it, as above. A new shared file was also set aside: several existing tests copy only a fixed list of scripts into a throwaway checkout, and one that holds `insights-carry.mjs` already holds `pr-size.mjs`, but none would hold a new file.
- **Why:** (c) wins: one reader of the operator's list, so the gate, carry and the size check cannot disagree about which checkout is trusted, and the isolation the issue asks to keep (no global or system config, no `GIT_DIR`, no `CLAUDE_PROJECT_DIR`) is the same one `pr-size.mjs` already tests. `insights-carry.mjs` now imports `pr-size.mjs`, which imports `agent-files.mjs`; `agent-files.mjs` loads `insights-carry.mjs` only inside `carried()`, so no import cycle runs at load time.
- **Originator:** AI pick, not reviewed (Full automation: the coordinator, on the claim comment of #544, which sent the unconditional design back as wider than #611's rule).
