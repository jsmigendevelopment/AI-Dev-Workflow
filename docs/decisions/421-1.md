# Decision 421-1

- **Date:** 2026-11-28
- **Decision:** Four follow-ups to the TanStack Start pack's fresh-copy check (#319), from the review of #419.
  - **lefthook:** `package.json` gets `"hooks": "lefthook install"`, and `knip.jsonc` loses `ignoreDependencies: ["lefthook"]`. Knip sees lefthook's real use in the script, prints no "Remove from ignoreDependencies" hint, and exits 0 with or without the hook in `.git/hooks`. Decision 319-1 is updated in place, as the issue says.
  - **README and hook comment:** the pack README no longer says `pnpm install` installs the hook always. It says it does so inside a git repository, and gives `pnpm hooks` for after `git init` or in a worktree (also a row in the Commands table). The first line of `lefthook.yml` says the same.
  - **Guard against hiding dependencies:** `cli/test/pack-check-fresh.test.mjs` fails when the pack's `knip` script isn't plain `knip`, `check` doesn't run `pnpm knip`, `knip.jsonc` sets `ignoreDependencies`, `ignoreBinaries`, `ignoreUnresolved`, `rules`, `workspaces`, `include` or `exclude`, an `ignoreIssues` entry lists a dependency kind, `package.json` has a `knip` key, or another knip config file exists. A second test feeds the guard bad settings, so it is known to fail. The "runs knip" test, which only read files, is retitled to say so.
  - **Prettier half:** the same file runs the pack's pinned Prettier (`devDependencies.prettier`, 3.10.1) with `--check .` over every pack file, using the pack's own `.prettierrc.json` and `.prettierignore`. A file it would change fails the test and is named. A second test makes a copy with one long line and one clean file and checks that only the long one is named.
- **AI picks, not reviewed:**
  - **Where the Prettier comes from.** Options: (1) install `prettier@<pin>` in every test run (needs the network, slow, flaky offline); (2) always skip unless the person opts in; (3) look for the exact pinned version in the pack's `node_modules` or in the folder `ONRAILS_PRETTIER_DIR` names, install it into a temp folder only when `ONRAILS_PRETTIER_INSTALL=1` is set (about 5 seconds, needs the network), and otherwise skip with a message that says how (picked). The default `npm test` stays fast and offline, the skip names its three ways out, and the whole-pack check takes about 4 seconds when it runs. The cost: a plain `npm test` on a machine with no Prettier 3.10.1 skips the two Prettier tests, so the fresh-app `pnpm check` stays the check that always runs `prettier --check`.
  - **Only the exact pinned version counts.** Another Prettier version may format a file differently, and a test that fails on a file a fresh app accepts is worse than a skip.
  - **No prepare or postinstall script.** A test pins that none exists: `pnpm install` before `git init` must not fail (decision 319-1, option 2).
  - **Knip itself is not run in the kit's tests.** Running it needs a full `pnpm install` of the pack (minutes). The test reads the files, and the fresh-app run by hand proves knip's output, both with the hook installed and without it.
  - **`include` and `exclude` count as hiding.** Knip's `include` and `exclude` choose which issue types it reports, so either can switch dependency checks off. The issue named `rules`, `workspaces` and `ignoreBinaries`; the others hide the same things.
  - **`lefthook.yml` header edited** though it isn't on the issue's Modules line: it said `pnpm install` installs the hook, which this change makes wrong, and a build updates the docs its change makes wrong.
