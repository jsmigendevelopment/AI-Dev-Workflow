# Decision 405-1

- **Date:** 2026-11-27
- **Decision:** `pyramid/scripts/check-plan.mjs` blanks out what a reader can't see before it reads any table, keeping each line so line numbers still match. A fenced code block (backticks or tildes) is blanked, both as tables and for comments. A comment spans lines only when `<!--` starts a line, with up to 3 spaces of indent, as an HTML block does on the rendered page: it runs to the line with `-->`, or to the end of the file. Anywhere else, as in a table cell, in inline code or on a 4-space indented line, only a comment that opens and closes on the same line is blanked, so an unclosed `<!--` in a cell never hides the rows below it (review round 1 on #436). Then it checks every table with the step columns, not only the first: their steps are read in order as one list, so each step gets every step check and the plan numbers count them all. Each steps table fails on its own when it has no `Lines` column, or when a column the checker reads (`#`, Step, Slice, Try it, Size, Lines, After) appears twice. With more than one steps table, the message names the table's line. The "no steps table" error lists `lines` after `size`. (#405, from the review of #404)
- **Options considered:** check every steps table as one list; fail a plan with more than one steps table (the review's first idea), which also refuses a pass split into two tables on purpose; read only the first table outside comments, which keeps the hole the issue names. For the repeated column: fail only two Lines columns (the issue's words), or any column the checker reads.
- **Why:** The issue asks for every steps table to be checked, so a step can't hide in a second one. Any repeated column the checker reads has the same bug as two Lines columns (only the last one is read), and one loop over the asked columns is simpler than a special case for Lines. Blanking out comments in `tables()` means the slices and outline tables also ignore a commented-out copy.
