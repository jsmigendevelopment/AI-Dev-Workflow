# Decision 415-1

- **Date:** 2026-11-28
- **Decision:** Local mode's merge step checks the records with `insights.mjs has-records --issue <n> --sha <sha>` (#415). (1) The records match on their `issue` field and the exact `sha`; the `pr` field is not looked at, so a local-mode record (`pr: null`) and a pull request's record for the same issue and commit both count. Board records still don't. (2) Exactly one of `--pr` and `--issue` is given, with `--sha`; any other command line exits 2 and names both forms. The `--pr` form, its exits and its messages are unchanged, except that the "Then harvest" hint moved out of the two shared hint strings so the `--issue` form can leave it off: local mode has no pull request to harvest from, its records are already files in the checkout. (3) Local mode's "No remote" step 5 runs the check before `git merge --no-ff`, merges only on exit 0 on every level, and never writes a missing record by hand. A missing `check` record sends the sha back to the gate (step 4), which now says to write that record with `insights.mjs write check issue=<n> pr=null sha=<sha> ...`, because `mark-check.mjs` needs the API. A missing `job` or `review` record sends the sha to a fresh `pr-review`. (4) Only the "No remote" case merges locally. The "Push, no API" cases merge through a pull request or the host's own tool and are left as they are.
- **Options considered:** `--issue <n>` beside `--pr` (picked); one generic `--key issue=<n>` filter, which any later field would also fit but is more than one second use asks for; make `--pr` accept `null` and read the issue from the sha's records, which is a lookup the checkout can't prove.
- **Why:** The issue names `--issue` and the records' `issue` field. It is the smallest edit to `has-records`, which keeps the overlap with #441's change to `harvest` to a minimum, and it keeps one rule for both modes. The pull request form is unchanged, so `coordinate` step 7 and its tests stand.
