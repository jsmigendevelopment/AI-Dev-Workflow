# Decision 268-1

- **Date:** 2026-11-27
- **Decision:** How #268 counts inherit-only rules on the Windows process registry's own folders. The batched ACL reader (`procs-winacl.mjs`) no longer drops an inherit-only rule: it writes it with a trailing ` io` mark, and `winAccess` returns those accounts as `heirs`, apart from `writers` and never in `movers`. `aclProblem` (the repo root or home folder that holds `.onrails`, `.onrails`, its `logs` folder and the registry file) counts `writers` and `heirs` together, with the same fix line; `winAboveProblem` (the folders above a repo root) still reads only `movers`, so the `C:\` case of row 114 stays as it was. Any other mark makes the path "can't tell". Still one PowerShell start per batch.
- **Options considered:** Read the inherit-only rules in a second PowerShell start for the registry's own folders only (two starts, against AC-248-1); count them everywhere (refuses every repo under a folder like `C:\`, which row 114 (4) fixed); mark them in the one batch and let each check pick
- **Why:** One start, one reader, and each caller decides which rules matter for what it does. Narrows row 114 (4) only for the paths where the registry makes files.
- **Originator:** AI pick, not reviewed
