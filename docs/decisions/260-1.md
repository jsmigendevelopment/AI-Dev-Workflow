# Decision 260-1

- **Date:** 2026-11-28
- **Decision:** The "On Full branch per step" scan from #254 now reads every `.md` under `.agents/skills/` (a new skill is scanned the day it lands) and, by name, `AGENTS.md`, its kit copy, the `coordinate` board and references, `automation`'s `references/full.md`, the `build` and `ask` references, the four loop skills that have no references, and the two stack packs' skill files. The 66 steps it found (65 in skills, 1 in `AGENTS.md`) are handled three ways. (1) **A real ask gets its own short On Full branch** that takes the recommended or default option, records it as "AI pick, not reviewed" and goes on (`automation`'s `references/full.md`). (2) **A step that only reads like an ask is reworded**: "if the host offers one" is "if the host has one", "Ask the server every 5 seconds" is "Poll the server every 5 seconds", "the installer asks which agent" is "the installer prompts for the agent", "only if the person picks PostHog" is "chooses", "Wait for them first" (the wireframes, not the person) is "Let them finish first", and `automation`'s description says "takes the pick". (3) **An always-stop step goes in `EXCEPTIONS`** in `cli/test/full-branch-scan.mjs`, each with its words and a reason: `AGENTS.md`'s always-stop heading and its kit copy, the always-stop sentence in the `idea` stack template, never stopping a strongest-tier run (`routing`), a bug in production (`diagnose`), production behind a login (`stack`), `eas` commands that cost money or touch production (`stack-monorepo-expo`), and the Access-in-front-of-production and go-live yeses (`stack-tanstack-start`). An exception whose words match no unbranched step of its file fails the test, so it can't outlive its step. No always-stop rule became an On Full branch. The hooks in `.claude/hooks/` print no kit `.md` (they read the app's `docs/state.md` and `docs/stack.md`), so no hook file is scanned. The job fit in one pull request, so nothing is split.
- **Options considered:** For the false positives, narrow the scan's patterns (a smaller scan, and #254's AC-254-2 shapes would need a second look), or add an exception for each (an exception list is for the always-stop list, and a long one hides real asks); rewording keeps the scan as it is and reads better for an agent too. For the file list, scan the folder only (a moved file drops out unnoticed), or name every `.md` (a new skill would need an edit before it is scanned); the folder plus named files does both.
- **Why:** The top-of-skill override lost to the specific step below it (#254), so each step has to say what it does on Full. The always-stop list is the owner's, and on Full it is parked, not decided.
- **Originator:** AI pick, not reviewed (Full automation). The branch for each step, which steps are rewordings, the nine exceptions and the list of named files are the builder's picks inside the issue's fence.
