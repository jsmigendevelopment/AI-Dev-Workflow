# Decision 331-3

- **Date:** 2026-11-27
- **Decision:** `mark-check.mjs` drops every control character (C0, DEL and C1) from the fence's first line, then caps it at 200 characters. A command name, or the `failed` step, over 200 characters or with a control character makes the gate's file a usage error: exit 2, no record, no post. The record goes into `docs/insights/` of the checkout the script sits in, found from the script's own place with no git, and a checkout with no `docs/` folder is a record that can't be written (a warning; the status is still posted). This replaces decision 331-2's example "no git checkout". (#331, review round 1)
- **Options considered:** strip control characters from command names too and cap them; refuse them (exit 2); leave them to `validate`. Find the checkout with `git rev-parse` in the current folder; from the script's place; from a `--root` flag.
- **Why:** The gate writes the command names itself, so a long or garbled one is a bug in the gate, and refusing it says so at once, while the fence line comes from the sandbox and is only kept for reading. The summary and the merge check print these records later, where an escape or a carriage return garbles the output. The coordinator may run the script from any folder, and must never run git in the head's clone; the script's own place always names the checkout of main it came from.
