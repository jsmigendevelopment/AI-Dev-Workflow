# TanStack Start starter

A small, working app to start from: TanStack Start (React, TypeScript strict) on Cloudflare Workers, with D1 through Drizzle, Clerk for sign-in, shadcn/ui and Tailwind CSS, TanStack Query, Zod, Vitest and Playwright.

It runs, tests and builds with no accounts and no keys. Without Clerk keys, sign-in is off and every notes call is refused.

It starts secure, fast, accessible and search-ready: security headers and a nonce CSP on every response, rate and body limits on server functions, budgets and Lighthouse checks, axe on every route in both themes, and the SEO files built for you. See [On by default](#on-by-default).

## What's inside

```
src/
  routes/            thin file routes: load data, render a module's view
    api/v1/          the versioned HTTP API (server routes) for mobile and desktop clients
  modules/
    home/            the landing page
    notes/           the example module: list, create, rename, delete, owned by the signed-in user
      ui/views/      notes-view.tsx (loading, empty, error and signed-out states)
      ui/components/ note-create-form.tsx, note-item.tsx
      hooks/         use-notes.ts: query options and mutations
      server/        notes.functions.ts   server functions: method, auth, one controller call
                     notes.http.ts        /api/v1/notes: Request in, Response out, same controller
                     notes.controller.ts  parse input, call the service, return the envelope
                     notes.service.ts     business rules. No HTTP, no SQL
                     notes.repository.ts  the port the service depends on
                     notes.repository.drizzle.ts / .memory.ts  D1 adapter and test fake
                     notes.table.ts       the Drizzle table
      schemas.ts     Zod schemas shared by the form and the server
      types.ts
  components/ui/     shadcn/ui primitives
  components/        shared app components (header, theme toggle, empty, error and 404 states)
  hooks/ lib/ db/    shared hooks, helpers (error type, paging, SEO, headers, env schema), the D1 client
  server/            request-guards.ts (headers, CSP, limits), auth.ts (Clerk, actor), env.ts,
                     turnstile.ts, composition.ts (the one place that wires adapters)
public/              _headers, icons, share image, web manifest
scripts/             budgets/ (bundle budgets), check-licenses.ts, generate-icons.ts,
                     setup-cloudflare.mjs (+ cloudflare/: its logic and tests)
migrations/          SQL generated by drizzle-kit, applied by wrangler
e2e/                 Playwright tests: smoke, security, seo, a11y (axe), api
.github/workflows/   ci, deploy-test, preview, deploy-production
```

The rules: a module never imports another module, shared code never imports a module, and a service never imports the database, HTTP or an SDK. `pnpm lint` fails if any of that happens (`eslint.config.js`).

## Set up Clerk

1. Create an application at clerk.com (the free tier is enough).
2. Copy `.env.example` to `.env` and fill in `CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`. Never commit `.env`.
3. `pnpm dev`, open `/notes`, sign in.

The server reads the keys per request in `src/server/auth.ts`. The signed-in user comes from the verified Clerk session, never from the request body. The CSP opens Clerk's Frontend API host (read from the publishable key) only when the keys are set.

## Turnstile (optional)

Add it only when counters show the cheaper layers are not enough. Create a widget in the Cloudflare dashboard, set `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY`, and the note form starts sending a token; `withHumanCheck` verifies it. The script loads on the form's first focus, never on page load.

## Environments

| Where      | Worker           | D1 database      | Deployed by                                                  | GitHub environment |
| ---------- | ---------------- | ---------------- | ------------------------------------------------------------ | ------------------ |
| local      | (none)           | `app`, local     | `pnpm dev`, tests                                            |                    |
| test       | `app-test`       | `app-test`       | every push to main (`deploy-test.yml`)                       | `test`             |
| previews   | `app-test` alias | `app-test`       | every pull request (`preview.yml`)                           | `preview`          |
| production | `app-production` | `app-production` | by hand, after the person approves (`deploy-production.yml`) | `production`       |

Each environment has its own block under `env` in `wrangler.jsonc`. Bindings are not inherited: an add-on that adds a binding adds it to the top level and to both environments. The build picks the environment (`CLOUDFLARE_ENV=test pnpm build`); `wrangler deploy` then uses the build's flattened config. D1 commands take `-c wrangler.jsonc` so they read the source config, for example `pnpm exec wrangler d1 migrations apply DB --remote -c wrangler.jsonc --env test`.

Rename `app`, `app-test` and `app-production` (Worker and database names) in `wrangler.jsonc` before the first setup. Locally, `pnpm db:migrate:local` applies the migrations to the local D1. To change the schema: edit the module's `*.table.ts`, run `pnpm db:generate`, read the SQL, commit it. Never edit a migration that has already run.

## Set up Cloudflare

An agent runs this for the person, dry run first:

```sh
node scripts/setup-cloudflare.mjs --dry-run   # reads only: what exists, what it would create or change
node scripts/setup-cloudflare.mjs             # after the person says yes
```

It checks `wrangler whoami` (if not signed in, the person runs `pnpm exec wrangler login`), creates the test and production D1 databases if missing and writes their ids into `wrangler.jsonc`, creates any R2 bucket or queue an add-on declared, prints `CLOUDFLARE_ACCOUNT_ID` and sets it in the GitHub environments `test`, `production` and `preview`, explains how to create the deploy token (its exact permissions), and runs the kit's `push-secrets.mjs --wrangler` for the app's secrets. With a custom domain (a production `routes` entry, or `--zone example.com`) and a separate zone token in `.env.cloudflare.local`, it applies the free zone settings: Always Use HTTPS, minimum TLS 1.2, AI training crawlers disallowed (never blocked: that would also stop Google and Bing), and a WAF rule that blocks scanner paths. Bot Fight Mode is recommended once the custom domain exists and is the person's choice (`--bot-fight-mode`): the CSP allows its same-origin `/cdn-cgi/` script on the production domain, and the production smoke test runs on workers.dev, outside the zone. Cloudflare's managed robots.txt stays off (`--managed-robots`): it duplicates the app's own. Run it again any time; it skips what exists.

It also asks how to protect the test and preview URLs, and records the answer as `SITE_PROTECTION` in `env.test.vars`:

```sh
node scripts/setup-cloudflare.mjs --protect access --access-email you@example.com  # recommended: Cloudflare Access
node scripts/setup-cloudflare.mjs --protect password                               # a password page in the app
node scripts/setup-cloudflare.mjs --protect none
```

Access puts a Cloudflare sign-in (a one-time PIN by email) in front of the whole test Worker and its previews, and creates a service token for CI (`CF_ACCESS_CLIENT_ID`, `CF_ACCESS_CLIENT_SECRET` in the GitHub environments `test` and `preview`). It needs Zero Trust on the account and an account token in `CLOUDFLARE_ACCESS_TOKEN` (`.env.cloudflare.local`); the email is never written to a file. The password option makes a random `SITE_PASSWORD`, sets it on the test Worker and in GitHub, and shows it once; CI sends it as `x-site-password`. Paths that must stay open (a signed webhook) go in `src/lib/open-paths.ts`.

The app's secrets per environment: `pnpm exec wrangler secret put CLERK_SECRET_KEY --env test` (and `--env production`), or the secrets skill.

## Deploys

- **Test:** each push to main applies the migrations to the test D1, deploys, and runs `pnpm test:deployed` against the deployed URL. If that fails, `wrangler rollback` puts the previous version back and an issue is opened.
- **Previews:** each pull request uploads a version of the test Worker with the alias `pr-<number>` and keeps one comment with its URL up to date. It uses the test database and never migrates it. Skipped for forks, Dependabot and the `lane:tiny` label.
- **Production:** Actions → deploy-production → Run workflow. The `production` environment waits for the person's approval. It takes a D1 Time Travel bookmark, migrates, deploys and smoke-tests; on failure it rolls back the code and prints the restore command with the bookmark. Restoring data is the person's call.

**Going live.** Production deploys with `LAUNCHED` "false" in `env.production.vars`, so every visitor sees "Coming soon" and the smoke test checks that page. Only the person decides to go live: then a pull request sets it to "true", and the next production deploy opens the app (the smoke test then checks the app).

A rollback restores code, never data, so a migration must work with the code before it: add columns and tables first, remove them in a later release. Set `SITE_URL` (a variable on the `production` environment) before the first production deploy, and `APP_URL` only when there is no workers.dev URL to smoke-test. For your own domain, uncomment `routes` under `env.production` in `wrangler.jsonc`, and keep `workers_dev` on: the production smoke test runs there.

## HTTP API (`/api/v1`)

For clients that aren't this web app (mobile, desktop, scripts). The web app itself keeps using server functions.

| Method and path            | Body                                     | Success                                                                    |
| -------------------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| `GET /api/v1/notes`        | `?cursor=&limit=` (1 to 100, default 20) | `200 { ok: true, data: { items: NoteDto[], nextCursor: string \| null } }` |
| `POST /api/v1/notes`       | `{ title }`                              | `201 { ok: true, data: NoteDto }`                                          |
| `PATCH /api/v1/notes/:id`  | `{ title }`                              | `200 { ok: true, data: NoteDto }`                                          |
| `DELETE /api/v1/notes/:id` |                                          | `200 { ok: true, data: { id } }`                                           |

`NoteDto` is `{ id, title, createdAt, updatedAt }` (times in epoch milliseconds). Every request needs `Authorization: Bearer <Clerk session token>` (from `getToken()` on the client, fresh per request); the session cookie is never accepted here. A failure is `{ ok: false, error: { code, message, fields? } }` with the code's status: 400 `validation`, 401 `unauthenticated` (with `WWW-Authenticate: Bearer`), 404 `not_found` (also for another user's note), 405, 411, 413 `too_large`, 429 `rate_limited` (`Retry-After`), 500 `internal`. Bodies are JSON, at most 64 KiB, with no unknown fields. The schemas are `src/modules/notes/schemas.ts`. Optional `CLERK_JWT_KEY` (the instance's PEM public key) verifies tokens without a call to Clerk.

## CI

`.github/workflows/ci.yml` runs on every pull request and on main, cancelling a stale run of the same branch: `checks` (the commands above, a check that migrations match the tables, the bundle budgets and the Playwright suite), `supply-chain` (`pnpm audit --audit-level=high` and the licence allow-list), `secrets` (gitleaks) and `agent-files` (changes to agent rules need a `human-approved` label). The deploy workflows are described under [Deploys](#deploys); they use the secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` by name and never overlap (one concurrency group each). Dependabot opens grouped weekly updates for npm and GitHub Actions. `pnpm install` also installs a pre-commit hook (lefthook) that formats and lints the staged files.

Playwright is the browser test runner. A person's own browser (for example Claude in Chrome) is for a look after Playwright passes, never instead of it.
