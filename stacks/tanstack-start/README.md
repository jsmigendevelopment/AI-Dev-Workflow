# TanStack Start starter

A small, working app to start from: TanStack Start (React, TypeScript strict) on Cloudflare Workers, with D1 through Drizzle, Clerk for sign-in, shadcn/ui and Tailwind CSS, TanStack Query, Zod, Vitest and Playwright.

It runs, tests and builds with no accounts and no keys. Without Clerk keys, sign-in is off and every notes call is refused.

## What's inside

```
src/
  routes/            thin file routes: load data, render a module's view
  modules/
    home/            the landing page
    notes/           the example module: list, create, rename, delete, owned by the signed-in user
      ui/views/      notes-view.tsx (loading, empty, error and signed-out states)
      ui/components/ note-create-form.tsx, note-item.tsx
      hooks/         use-notes.ts: query options and mutations
      server/        notes.functions.ts   server functions: method, auth, one controller call
                     notes.controller.ts  parse input, call the service, return the envelope
                     notes.service.ts     business rules. No HTTP, no SQL
                     notes.repository.ts  the port the service depends on
                     notes.repository.drizzle.ts / .memory.ts  D1 adapter and test fake
                     notes.table.ts       the Drizzle table
      schemas.ts     Zod schemas shared by the form and the server
      types.ts
  components/ui/     shadcn/ui primitives
  components/        shared app components (header, empty and error states)
  hooks/ lib/ db/    shared hooks, helpers (error type, paging), the D1 client
  server/            auth.ts (Clerk, actor), composition.ts (the one place that wires adapters)
migrations/          SQL generated by drizzle-kit, applied by wrangler
e2e/                 Playwright tests
```

The rules: a module never imports another module, shared code never imports a module, and a service never imports the database, HTTP or an SDK. `pnpm lint` fails if any of that happens (`eslint.config.js`).

## Commands

| Command                 | Does                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `pnpm install`          | install (pnpm version pinned in `package.json`)                                       |
| `pnpm dev`              | dev server on http://localhost:3000, Worker code runs in workerd                      |
| `pnpm lint`             | ESLint with the boundary check, then Prettier                                         |
| `pnpm typecheck`        | generate Worker types, then `tsc` for the app and for tests                           |
| `pnpm test`             | unit and contract tests, including the repository against a local D1                  |
| `pnpm test:e2e`         | build, serve the build, run Playwright (`pnpm exec playwright install chromium` once) |
| `pnpm build`            | production build into `dist/`                                                         |
| `pnpm check`            | lint, typecheck, test and build, in that order                                        |
| `pnpm db:generate`      | write a migration after you change a `*.table.ts`                                     |
| `pnpm db:migrate:local` | apply migrations to the local D1                                                      |
| `pnpm deploy`           | build and deploy to Cloudflare Workers                                                |

## Set up Clerk

1. Create an application at clerk.com (the free tier is enough).
2. Copy `.env.example` to `.env` and fill in `CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`. Never commit `.env`.
3. `pnpm dev`, open `/notes`, sign in.

The server reads the keys per request in `src/server/auth.ts`. The signed-in user comes from the verified Clerk session, never from the request body.

## Set up D1

1. `pnpm exec wrangler login`
2. `pnpm exec wrangler d1 create app` and paste the `database_id` it prints into `wrangler.jsonc`.
3. `pnpm db:migrate:local` for local dev.
4. Before the first deploy, and before any deploy that needs a new migration: `pnpm exec wrangler d1 migrations apply app --remote`.

To change the schema: edit the module's `*.table.ts`, run `pnpm db:generate`, read the SQL, commit it. Never edit a migration that has already run.

## Deploy to Cloudflare

1. Rename the Worker (`name`) in `wrangler.jsonc`.
2. Set the secrets once: `pnpm exec wrangler secret put CLERK_SECRET_KEY` and `pnpm exec wrangler secret put CLERK_PUBLISHABLE_KEY`.
3. Check first with `pnpm build && pnpm exec wrangler deploy --dry-run`, then `pnpm deploy`.
4. For your own domain, uncomment the `routes` block in `wrangler.jsonc`.

Roll back with `pnpm exec wrangler deployments list` and `pnpm exec wrangler rollback <version-id>`.

Netlify is the one alternative host: swap the Cloudflare plugin for Netlify's and move D1 to another SQLite host.

## CI

`.github/workflows/ci.yml` runs three jobs on every pull request: `checks` (the commands above, plus a check that migrations match the tables), `secrets` (gitleaks) and `agent-files` (changes to agent rules need a `human-approved` label).
