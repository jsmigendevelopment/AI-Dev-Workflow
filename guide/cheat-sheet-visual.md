Personal plugins load in local sessions.">
<img src="cheat-sheet/trigger-phrases.svg" width="352" align="top" alt="Trigger phrases. “Grill me”. Get three questions at a time, each with a recommended answer. “Give me three options”. Compare trade-offs and get a recommendation. “Use the … skill”. Name the step you want to run. “Tracer bullets”. Plan thin, end-to-end changes you can try. “Modular monolith”. Keep each feature in its own module. “Controller → service → repository”. Separate request handling, business logic and data access. “Review the diff in a fresh context”. Ask an independent reviewer to judge the code. “Start the loop”. Begin building ready issues. “What’s out of scope?”. Set the boundary for this issue.">
<img src="cheat-sheet/model-routing.svg" width="352" align="top" alt="Model routing. Everyday · low. Run the live thread, write issues and check the preview. The README example is Claude Opus 5.5. Everyday · medium. Interview, plan and draw rough layouts. Strongest · high. Research, design screens, plan passes and define the schema and API. Ask first unless the profile allows it. The README example is Claude Fable 5.2.">
<img src="cheat-sheet/build-effort.svg" width="352" align="top" alt="Build effort. Build and review. Build at low effort for complexity 1–4 and medium for 5–7 or from pass two. Review at least at the builder’s effort. Security and art. Security review goes one step higher. Add a second vendor for personal data or money when available. Use the creative tier for art. The README example is ChatGPT. Escalate. Start low. Go up one step after a failed check or a rejected review.">
<img src="cheat-sheet/merge-lanes.svg" width="352" align="top" alt="Merge lanes. Tiny. Copy, styling or config. Run CI and code review. Normal. Add QA on the preview. Risky. Add security review for auth, secrets, personal data, money, migrations or new dependencies. Ask the owner unless Full automation allows the merge. Failed check. Return to a fresh builder. Park the issue after two rejected rounds.">
<img src="cheat-sheet/risk-dial.svg" width="352" align="top" alt="Risk dial. Move fast. For a project without real users yet. Agents merge once checks pass. Careful. For real users or money. The owner reads schema and API changes before agents merge. Strict. For regulated work. The owner approves every merge. Always ask. Wait before deleting or migrating real data, touching production settings or secrets, deploying or going public, or spending money.">
<img src="cheat-sheet/automation-level.svg" width="352" align="top" alt="Automation level. Recommended. Agents build, review and merge tiny and normal changes, then deploy to test. You approve risky and schema changes. Full. Include risky work and overnight runs. The always-stop list still applies. Hands-on. Agents plan, write issues and build one when asked. You open and merge pull requests. Custom. Choose each switch. Where the two dials disagree, the more careful setting wins.">
<img src="cheat-sheet/needs-you.svg" width="352" align="top" alt="Needs you. Blocker. Ping now. Other safe work continues. Decision. Batch questions about gates, scope, taste or money. By default, at most one ping every 30 minutes. FYI. Record progress, usage and rate limits on the board. Catch up with /back. Board. Open ~/.onrails/boards/&lt;project&gt;.md or the configured Google Sheet. Quiet hours and the batch window live in the profile. While away. Only production going down or a live security hole interrupts you.">
